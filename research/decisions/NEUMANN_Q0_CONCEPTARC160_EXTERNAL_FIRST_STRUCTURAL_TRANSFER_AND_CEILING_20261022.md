# NEUMANN 1 | Q0·Q3 근본 목표: 외부 ConceptARC160 구조 전이·문법 능력 하한 및 메타 선택 실패

**연구일:** 2026-10-22  
**상태:** 세 독립 GitHub CI 성공, 소스 기초 문제 해결 능력 확장 **제한적 PASS**. 글로벌 프런티어급 문제 해결, 학습 모델 고유 연산자 발견, 전체 계산효율 10배 우위 **OPEN**.

## 1. 연구 질문과 사전 등록

가장 중요한 질문: *기존 원본에서 학습/개발한 구조 생성 방식이, 새로운 원본 문제에서 기존의 강한 비학습 DSL이 표현할 수 없던 정확한 변환을 실제로 합성할 수 있는가?*

- 다른 연구자가 제작한 공식 **ConceptARC** 원본 160개, 개념 16개 그룹 × 10개, 각 문제의 **테스트 3개 전체**. 성공 기준은 한 문제에 속하는 세 테스트 출력 **전부 정확 일치**.
- 원본 GitHub `victorvikram/ConceptARC@0e67da6af879e4bad3d7cd3c196e8d551b445725`, `corpus` Git tree `a9e933c021388297f21fa1cded180105479addc0`.
- 새 코드 **SHA256 `fbe64dc5021f6f1baf3a3a86c9090648ead1aa82614c87ba44eecedb22d67d6a`**은 이 ConceptARC 캠페인에서 원본 본문 접근 전에 고정했고, 이전 ARC-AGI-2 **개발용 800개**로만 설계함. 다만 ARC2 개발용 로컬 점수 **18/800**은 기존 개발 문법 **24/800**보다 낮음. 이미 공개된 ARC2 train 내부 200 홀드아웃에서 새 구조 **3/200**은 기존 문법 **10/200** 해결집합의 진부분집합이어서 **추가 정답 0개**.
- 모든 160개에서 원본 테스트 정답은 추론 작업 공간에 없음. 첫 예측 파일과 SHA-256을 GitHub artifact로 보존한 **후** 별도의 작업에서 공개 정답을 로드해 독립 채점함.

## 2. 첫 외부 결과, 실제 입증

| 행위/지표 | 기존 ARC2 비학습 DSL | 새 구조 DSL | 기존 우선 혼합 제어기 |
|---|---:|---:|---:|
| 세 테스트 전부 해결한 문제 수 / 160 | **1** | **2** | **1** |
| 개별 정확 테스트 / 480 | **8** | **9** | **8** |
| 시범 예제를 만족하는 후보 프로그램이 존재 / 160 | **8** | **5** | 합집합 **9** |

- `Copy/Copy1`: 두 DSL 모두 3/3 정답.
- **`ExtractObjects/ExtractObjects1`**: 새 DSL `biggest_component` 연산의 **정확한 연결 객체 선택**으로 원본 테스트 **3/3 정답**. 기존 DSL은 test 2/3만 맞았으며, 그 DSL에서 시범 예제를 만족하는 **모든 후보 1개를 전수 검사해도** 완전한 테스트 정답이 없었음. 새 DSL의 해당 후보는 1개이며 정답.
- 이 추가 해결은 **구조 표현의 실제 범위 확장**을 보여주는 작은 외부 원본 성공이다. 하지만 학습 가중치/신경망의 고유 성과가 아니다. 비학습 원본 데이터에서 구조가 바로 추출되었다.
- 모형 우선 혼합기는 예시를 설명하는 기존 후보 1개를 택하는 바람에 `ExtractObjects1` 새 정답을 놓침. 따라서 **구조 생성 성공과 구조 선택 실패**를 정확히 구분해야 한다.
- 최초 GitHub 성공 작업 [#39763209170](https://github.com/yoonsj0305/NEUMANN/actions/runs/39763209170). 독립 original 160 / 480 채점. 이 작업의 추론 과정에서 두 DSL을 합쳐 측정한 벽시계는 **2.5899초/160문제**. 이것은 각각의 구간을 구분한 시간도, 프런티어와 공정한 계산량 비교도 아님.

## 3. 전체 후보 문법의 정확한 사후 상한

완전히 **사후 독립 검사**이며 추론이나 모델 학습에는 피드백으로 제공하지 않음. 두 DSL의 *시범 예제를 정확히 설명하는 모든 후보*를 테스트 정답과 일괄 대조.

| 유한 후보 언어 | 가능한 완전 정답의 상한 |
|---|---:|
| 기존 DSL의 최적 후보 선택 (oracle) | **3/160** |
| 새 DSL의 최적 후보 선택 (oracle) | **2/160** |
| 두 문법을 합친 oracle | **4/160** |
| 현재 기존 우선 혼합기 실제 정답 | **1/160** |

기존 DSL은 `CompleteShape/CompleteShape3`, `CompleteShape/CompleteShape7`, `Copy/Copy1`에서 정답 후보가 존재하지만, 고정 순위기는 앞의 2개에서 다른 후보를 선택해 틀림. 새 DSL은 `Copy/Copy1`, `ExtractObjects/ExtractObjects1`에서 정답 후보 존재. 따라서 두 경로를 합친 완전 후보 집합에서도 **156/160 원본은 정답에 해당하는 프로그램이 없음**. **151/160에서는 시범 예제와 완전히 일치하는 후보 자체가 양쪽에 한 개도 없음.**

이는 *현재 동결된 두 유한 후보 생성기와 시범 예제 완전 일치 조건 아래의 정확한 상한*이다. 임의의 더 강한 프로그램 언어, 오류허용 후보 또는 새로운 neural feature generator가 해결할 수 없다는 수학 정리가 아니다.

사후 oracle 독립 CI: [#39764220945](https://github.com/yoonsj0305/NEUMANN/actions/runs/39764220945). 정답이 있는 외부 원본에서 `ExtractObjects1`의 이전 문법 표현 불가능성 범위 및 새 문법의 정답 존재성을 기계적으로 확인.

## 4. 원본 독립성 감사: 이전 데이터셋 중복 문제 재발 방지

외부 ConceptARC 공식 160개와 **ARC-AGI-1 학습 400 + 평가 400 + ARC-AGI-2 학습 1,000 + 평가 120**, 총 추가 원본 1,920개, 전체 2,080개를 Git 원본 SHA로 인증.

학습 예제 입력·출력의 **순서 무관 멀티셋**과 각 프로그램의 원본 모든 테스트 입력·출력을 정규화해 SHA-256으로 비교:

- 학습 시범 예제가 **완전 일치하는 원본: 0/160**.
- 전체 시범 + 테스트가 **완전 일치하는 원본: 0/160**.

결과는 확실한 *정확한 내용 중복 부재*이지, 추상적 개념·과제 패밀리·AI 기학습 데이터까지 독립임을 보장하지 않음. 외부 original 감사를 수행한 CI: [#39764781217](https://github.com/yoonsj0305/NEUMANN/actions/runs/39764781217).

## 5. 핵심 Q0/Q3/Q4 판정

- **SCOPED PASS, 구조가 확장되면 정답 집합도 확대되는가?** 예. 동결된 비학습 구조 합성 DSL은 추가 `ExtractObjects1` 원본을 정확히 해결한다. 이는 기존 문법의 **어떤 선택기로도 성공하지 못하는 사례**다.
- **SCOPED PASS, 구조 생성과 구조 선택은 서로 다른 병목인가?** 예. 기존 문법의 최적 순위 조정은 실제 1→3개로 가능하지만 최대 3이고, 새 DSL 연산을 추가하지 않는 한 네 번째 문제는 불가능. 새 구조를 합쳐도 실제 안전 제어기 1개만 해결했다.
- **SCOPED PASS, 무의미한 추가 계산은 사전 후보 장벽으로 피할 수 있는가?** 두 유한 후보 언어에서 151/160 원본은 시범 예제 정확 일치 후보가 없다. 해당 후보만 대상으로 하는 신경망 재순위화는 유용한 정답을 만들 수 없다. 단, 실제 가속비, 전력 및 최소 연산 증명은 아직 없다.
- **OPEN, 프런티어급 추론/Q6 전이 성능?** 전체 정확도 최대 실측 2/160, 최고 후보 언어 oracle도 4/160. 프런티어 비교 우위나 충분한 성공률을 확보하지 못함.
- **OPEN, learned-exclusive Q3?** 이번 새 구조 합성기는 학습된 신경망이 아니라 정확한 기존 알고리즘이다. 모델 고유의 primitive invention은 실험하지 못함.
- **OPEN, Q4 10배?** 확인된 2.5899초는 두 DSL 포함 단일 실행의 벽시계일 뿐이며 동일 성능·동일 비용의 강한 frontier baseline과 공정한 가속비는 없다.

## 6. 다음에 반드시 해야 할 일과 종료할 일

**종료:** 고정 두 문법의 후보를 더 오래 반복 랭킹해 프런티어급 성능에 도달한다고 주장하기, ConceptARC 공개 답안에 맞춰 수정하고 결과를 새 블라인드라고 재명명하기, 단 하나의 외부 성과를 통계적으로 우월한 결과로 과장하기.

**다음 결정적 게이트:** 실제 원본 예시에서 *변수 조합뿐 아니라 객체 간 관계, 조건부 연산 순서, 중간 목표* 자체를 모델이 제안하는 프로그램 생성기를 만들고, **기존 모든 강한 소스 파서/정확 대수/완전 후보 oracle**과 동등한 정보·계산권한으로 비교. 모델이 제안한 새로운 AST가 원본 예제를 통과하고 전에 불가능했던 **미관측** 문제를 추가로 해결한 경우에만 learned novelty를 인정. 훈련·구조 제안·검증·실패 원가까지 총합 측정. 공개 벤치마크의 중복 내용을 재검증할 것.

**한 줄 결론:** NEUMANN Q3에서 *유용한 새로운 표현이 실제 문제를 하나 추가 해결한 현상*은 검증했지만, 프런티어급 최소 계산이라는 근본 목표는 아직 크게 못 미쳤다. 이 실패를 기반으로 다음 아키텍처에서 **구조 표현 공간을 동적으로 구성하는 기능**을 최우선으로 해야 한다.
