# 1단계 후보 설계서 — C1 Pointer Fold (PF), C2 Discrete Register Fold with Tape (DRF)

**상태:** **동결 (2026-11-17, 설계 채팅).** 기준선 표(RESULTS.md, 커밋 `29559d3`)를 기준으로 판정 숫자를 고정했다. 이후 변경은 DECISIONS.md에 사유와 함께 기록한다.
**작성:** 2026-11-17, 설계 채팅 (같은 날 개정 2회: ① C1을 DRF에서 PF로 교체, DRF는 C2로 이동 ② 제1원칙 검토로 내용 점프와 백업 학습기 추가)

## 1. 후보가 답하려는 질문
같은 학습 FLOPs에서, 위치와 무관한 공유 갱신과 이산 상태를 가진 학습 모델이, 강한 기준선 4종(abacus, rope, looped_rr, gru)이 실패하는 **분포 밖 길이**에서 일반화하는가?

## 2. 근거 (지금까지의 관측)
| 관측 | 출처 | 설계에 주는 의미 |
|---|---|---|
| GRU는 패리티 분포 밖 전 구간 1.000, 트랜스포머는 찍기 수준 | Phase A | 위치와 무관한 공유 갱신이 길이 일반화의 핵심 |
| 덧셈 분포 밖은 기준선 모두 거의 실패 (최고 looped_rr 11–20: 0.278) | Phase A, A′ | 자리 맞추기(정렬)와 받아올림 상태가 동시에 필요한 빈자리 |
| GRU 덧셈 분포 안 0.896 | Phase A | 고정 크기 연속 상태에 피연산자 전체를 담기 어렵다 |
| §44 K: 숨은 상태를 이산 레지스터로 구성해 70개 중 60개 | Q3 §44 | 이산 상태는 길이가 늘어도 표류하지 않는다 |

**가설:** 길이 일반화 실패의 원인은 (1) 위치에 묶인 계산, (2) 연속 상태의 누적 표류, (3) 정렬을 위해 입력을 기억 속에 옮겨 담아야 하는 부담이다. PF는 (1)을 공유 갱신으로, (2)를 이산 상태로, (3)을 **입력을 기억에 옮기지 않고 직접 가리키는 헤드**로 없앤다.

## 3. C1 Pointer Fold (PF)
**원리 (제1원칙의 삭제):** 입력은 이미 읽을 수 있는 테이프다. 따로 쓰고 다시 읽는 과정을 없애고, 입력 위를 움직이는 헤드로 필요한 기호를 그때그때 읽는다.

**상태**
- 레지스터 R개, 각각 K개 기호 중 하나 (이산). 초기값 0.
- 읽기 헤드 H개, 각각 입력 위치 하나를 가리킴. 초기 위치 0.
- 입력 테이프는 읽기 전용. 생성된 답 토큰도 테이프 끝에 이어 붙는다(자기회귀).

**기억 접근의 두 근본 방식:** 순서 접근(다음 칸)과 내용 접근(이 기호가 있는 곳). 트랜스포머는 내용 접근만(연속), RNN은 순서 접근만 한다. PF 헤드는 **둘 다, 이산적으로** 한다.

**한 step의 계산** (현재 처리 토큰 x_t, 입력 단계와 출력 단계 모두 같은 셀). 이동을 먼저 하고 읽은 뒤 출력한다.
1. 이동 결정: 이동 제어기 g(embed(x_t), onehot(registers), onehot(이전 읽기 r_1..r_H)) 가 헤드마다 이동을 고른다.
   - 순서 이동: {정지, 오른쪽, 왼쪽, 다음 구분자로, 처음으로}
   - 내용 이동: {x_t와 같은 기호의 다음 위치 바로 뒤로}
2. 읽기: 각 헤드 j가 가리키는 기호 r_j = tape[h_j]
3. 갱신·출력: 제어기 f(embed(x_t), onehot(registers), onehot(r_1..r_H)) 가 새 레지스터 값(레지스터마다 K-범주)과 출력 토큰 로짓을 낸다.

구분자는 `+`, `=`, `|`. 계산량은 step당 일정하다(헤드 수 × 작은 MLP 2개). 내용 이동은 기호별 위치 색인으로 구현하며, 색인 갱신·조회 비용을 FLOPs에 포함한다.

**이산화:** 학습 중 straight-through Gumbel-softmax(정방향 hard, 역전파 soft), 평가 중 argmax. 평가 시 모델은 정확히 다중 헤드 양방향 유한 오토마타로 동작한다(계산 이론상 로그 공간 L에 해당).

**내부 지도 없음:** 레지스터·헤드 위치·이동에 정답을 주지 않는다. 손실은 기준선과 같이 답 토큰에만 건다.

**초기 크기 (사전 선언):** R=4, K=16, H=3, 제어기 은닉 256, 2층. 파라미터 수를 기준선에 맞추지 않고, 비교는 **학습 FLOPs**로 한다.

## 4. 과제별로 기대하는 동작 (가능성 논증, 결과 예측 아님)
- **패리티:** 레지스터 하나. 헤드 불필요. GRU와 동등해야 한다.
- **덧셈** (`a 뒤집음 + b 뒤집음 =`): 출력 단계에서 헤드1은 a의 i번째 자리, 헤드2는 b의 i번째 자리를 가리키고, 레지스터에 받아올림. 매 출력 step마다 (a_i + b_i + carry) 한 자리 출력 후 두 헤드 전진. 피연산자 길이가 달라도 구분자를 만나면 0으로 취급하는 규칙으로 처리 가능. 규칙이 길이와 무관하다.
- **MQAR:** 질의 q를 읽는 step에서 헤드가 내용 이동으로 "q의 위치 바로 뒤"로 뛰면 그 자리의 값이 답이다. 질의당 O(1)로 표현 가능하다. 다만 원래 트랜스포머 우위 대조군으로 넣은 과제이므로 **판정 기준은 두지 않고 숫자만 보고한다.**
- **HRT (§44 과제):** 레지스터만으로 표현 가능한 계열. C1 통과 후 K(§44)와 함께 보고한다.

## 5. 선행 연구와 신규성 범위
- **Pointer Networks, NTM/DNC:** NTM은 연속(soft) 주소와 쓰기 때문에 학습이 불안정했다. PF는 쓰기가 없고 헤드가 이산이다.
- **Neural GPU (Kaiser & Sutskever, 2016):** 이진 덧셈·곱셈에서 이미 큰 길이 일반화를 보였다. **"덧셈 길이 일반화 최초"는 주장하지 않는다.**
- **다중 헤드 양방향 유한 오토마타:** 계산 이론의 고전 모델이다. 새로운 것은 이를 답 토큰만으로 학습시키는 것이다.
- **hard attention, Neural Programmer-Interpreter:** 이산적 내용 접근과 프로그램형 제어는 각각 선례가 있다. PF의 차별점은 순서·내용 이산 접근 두 가지를 한 작은 공유 셀에 넣고 계산 효율로 평가한다는 점이다.
- **주장할 수 있는 범위:** 하나의 작은 구조가 같은 학습 FLOPs에서 현대 기준선 4종보다 분포 밖 일반화가 크게 낫다는 **계산 효율 결과**. C1이 통과하면 Neural GPU를 추가 비교 대상으로 넣어 신규성을 다시 점검한다.

## 6. 실험 계획 C1
- 과제: 덧셈, 패리티, MQAR (+ HRT는 C1 통과 후)
- 학습 규약: 기준선과 같다 (N=100,000, 최대 20,000 step, batch 64, 같은 옵티마이저 설정, 분포 안 최고 시점 판정). 옵티마이저 조정 없음.
- 후보 고유 설정(사전 선언, 조정 없음): Gumbel 온도 1.0 → 0.1 지수 감소(학습 전체 구간).
- 1차: 시드 0. 2차(1차가 유효성 기준을 넘으면): 시드 3개 + 어블레이션.

**어블레이션 (원인 귀속용, 2차에서 함께)**
- PF-cont: 이산화 없음(연속 레지스터, soft 헤드 분포) → 표류 가설 검증
- PF-1head: 헤드 1개 → 정렬 가설 검증
- PF-nocontent: 내용 이동 없음 → MQAR에서 내용 접근 가설 검증

**백업 학습기 PF-search (사전 선언):** 답이 되는 PF 프로그램은 작은 이산 표다. 경사하강법(straight-through)은 이산 프로그램을 찾는 데 근본적으로 어색한 근사이므로, 이것이 가장 약한 고리다. PF가 유효성에서 실패하고 PF-cont도 실패하면(최적화 문제), 같은 PF 기계의 제어기 표를 학습 예제로부터 **이산 탐색(§44 계열의 열거·반례 수정)**으로 찾는 PF-search를 1회 돌린다. 탐색 비용은 FLOPs로 똑같이 센다. 경사하강법은 이후 언어·지각으로 확장하기 위해 주 학습기로 유지한다.

## 7. 판정 기준 (동결)
**기준선 기준값** (네 기준선 중 최고, 분포 안 최고 시점 규칙, `29559d3`)
| 과제 | 1구간 | 2구간 | 3구간 | 그 모델의 판정 시점까지 학습 FLOPs |
|---|---|---|---|---|
| 덧셈 (11–20 / 21–30 / 31–40) | 0.278 (looped_rr) | 0.000 | 0.000 | 5.18e14 |
| 패리티 (17–32 / 33–48 / 49–64) | 1.000 (gru) | 1.000 | 1.000 | 1.19e13 |
| MQAR 질의별 (17–32 / 33–48 / 49–64) | 0.978 (looped_rr) | 0.932 | 0.844 | 2.68e14 |

- **유효성 (C1-1, 시드 0):** 덧셈·패리티 분포 안 ≥0.95.
- **1단계 신호 (시드 3개 모두):**
  - 덧셈 11–20 ≥ **0.778**, 21–30 ≥ **0.500** (기준선 최고 + 0.5)
  - 위 덧셈 기준을 처음 만족한 체크포인트까지의 학습 FLOPs ≤ **5.18e14**
  - 패리티 분포 밖 세 구간 모두 ≥ **0.99** (동등성 확인. FLOPs 조건 없음, 숫자만 보고)
  - MQAR: 기준 없음. 질의별(teacher-forced)과 시퀀스 전체(greedy) 둘 다 보고
- **평가기:** 기준선과 같은 평가 코드·같은 평가 데이터를 쓴다. 덧셈·패리티는 시퀀스 단위 정답(greedy).
- **실패 시:** C1이 표현력 때문에 막히면(중간 결과 저장이 필요한 경우) C2(DRF)로 간다. 학습 자체가 안 되면(PF-cont도 실패) PF-search를 1회 돌린다. 그래도 실패하면 설계 채팅에서 판단한다. C2까지 실패하면 1단계를 닫고 방향을 재판단한다(사전 결정 지점).

## 8. 위험
- straight-through 이산 학습은 수렴이 어려울 수 있다. 유효성 실패 시 PF-cont와 비교해 구조 문제와 최적화 문제를 나눈다.
- 헤드 이동 동작("다음 구분자로", "처음으로")은 사람이 준 기본 연산이다. 결과 해석 때 구조적 사전 지식으로 명시한다.
- 쓰기가 없으므로 중간 결과 저장이 필요한 과제(정렬, 곱셈)는 원리적으로 풀 수 없다. 이는 C2의 역할이다.

## 9. C2 Discrete Register Fold with Tape (DRF) — 대기
PF에 쓰기 가능한 테이프를 더한 구조. 테이프 슬롯마다 S개 기호, 헤드 이동 {왼쪽, 정지, 오른쪽, 처음으로}, 쓰기 기호 출력. C1이 표현력에서 막힐 때만 설계 채팅에서 활성화한다. 학습해야 할 동작 연쇄가 길어 C1보다 학습이 어렵다고 예상한다.

## 10. 개정 C1-2 (2026-11-18, 설계 채팅) — C1-1 결과에 따른 이동 학습 추정기 교체
**C1-1 판정:** 유효성 미달(덧셈 분포 안 0.005). 패리티 분포 밖 전 구간 1.000, MQAR 질의별 분포 밖 0.993·0.997·0.998(기준선 최고 0.978·0.932·0.844). C1-1 결과는 FAIL로 보존한다.

**진단:** 표현력 확인 통과, 이동을 고정하면 갱신 제어기는 1,000 step에 덧셈 1.000. 이동 로짓 기울기 평균 6e-6. 원인은 구조가 아니라 **이동 선택의 기울기 추정기**다. straight-through는 이산 선택을 미세하게 바꾼 효과를 근사하는데, 이동은 미세하게 바꿀 수 없다. 따라서 C2로 가지 않는다.

**변경 (이것 하나만):** 헤드 이동의 학습 신호를 straight-through에서 **즉시 손실의 정확한 기대값**으로 바꾼다.
- 한 step에서 이동 → 읽기 → 출력이 이어지므로, 헤드 j의 이동 후보 m(6개) 각각에 대해 그 step의 읽기와 출력 손실 L_j(m)을 계산할 수 있다(다른 헤드는 이번에 고른 이동으로 고정).
- 이동 로짓의 학습 목표: Σ_m p_j(m)·L_j(m) (정확한 미분, 추정 분산 없음). 정방향 실행은 고른 이동 하나만 쓴다(학습 중 샘플링, 평가 중 argmax).
- 다음 step 이후에 미치는 효과(헤드 위치 지속)는 이 신호에 들어가지 않는다. 덧셈·패리티·MQAR의 정답 알고리즘은 이동 효과가 같은 step에 나타나므로 충분하다는 가설이다.
- 출력 손실은 출력 위치에서만 존재한다. 출력이 없는 step의 이동에는 이 신호가 0이다.
- 비용: 헤드당 후보 6개 × 3헤드 = 갱신·출력 제어기 18회 추가 계산. FLOPs에 모두 포함한다.
- 레지스터는 straight-through를 유지한다. 나머지 구조·크기·온도·학습 규약은 C1-1과 같다.

**판정:** 7절 기준 그대로. 이름 `c1_2_*`. 덧셈·패리티·MQAR 세 과제를 모두 다시 돌린다(같은 모델로 판정하기 위해).

**C1-2 실패 시 분기:** PF-search(아래 명세) 1회 → 실패하면 설계 채팅에서 판단.

## 11. PF-search 명세 (C1-1에서 비어 있던 부분)
- **탐색 대상은 이동 정책만.** 갱신·출력 제어기는 기존처럼 경사하강법으로 학습한다(이동 고정 시 1,000 step에 학습됨이 확인됨).
- **이동 정책 표:** 입력 = (헤드, 현재 토큰의 종류). 토큰 종류는 7개: 숫자, `+`, `=`, `|`, 노드(키), 답 단계의 토큰, 그 밖. 출력 = 이동 6종 중 하나. 표 크기 3×7, 후보 6^21.
- **탐색:** 좌표 하강. 표 칸 하나씩 6개 후보를 바꿔 보고 점수가 가장 좋은 것을 고정, 전체 칸을 최대 3바퀴. 점수 = 그 이동 정책으로 갱신 제어기를 300 step 학습한 뒤 학습 데이터의 분포 안 검증 정확도(분포 밖 데이터는 쓰지 않는다).
- **예산:** 후보 평가 최대 400회. 탐색에 든 FLOPs 전체를 학습 FLOPs에 더해 판정한다.
- **최종 학습:** 찾은 이동 정책으로 갱신 제어기를 7절 규약대로 학습하고 판정한다.

## 12. C1-3: PF-search v2 (2026-11-18, 설계 채팅) — 1단계 덧셈의 마지막 시도
**C1-2 판정:** 유효성 미달(덧셈 C1-2 분포 안 최고 약 0.018, PF-search 최종 학습 약 0.009; 최종값은 실행 종료 후 RESULTS.md 기준). 버그 점검에서 구현 결함 없음. 갱신 제어기가 유능할 때 이동 신호는 96%의 정보 있는 step에서 정답 이동을 최소 손실로 가리켰으나, 학습 중에는 갱신 제어기가 유능해지기 전인 step 4,000에 이동 분포가 포화(최대 확률 >0.999)해 기울기가 사라졌다. 원인: **"어디를 볼지"와 "무엇을 계산할지"의 동시 발견에서 이른 고착.**

**PF-search 실패 원인은 11절 명세 오류:** 점수를 300 step 후 정확도로 정해, 모든 후보가 0.000이 되어 순위 신호가 없었다(166회 평가).

**변경 (이것 하나만):** 11절의 점수를 **300 step 후 분포 안 검증 데이터의 평균 교차 엔트로피(답 토큰, 낮을수록 좋음)**로 바꾼다. 정확도가 0이어도 후보를 구별한다. 동점은 현재 칸 유지. 갱신 제어기 초기화·데이터 순서는 후보마다 같은 시드로 고정한다. 나머지(표 3×7, 좌표 하강 최대 3바퀴, 예산 400회, 탐색 FLOPs를 학습 FLOPs에 합산, 최종 학습 규약)는 11절 그대로.

**판정:** 7절 기준. 덧셈 분포 안 ≥0.95면 1단계 신호 판정으로 간다(탐색 FLOPs 포함 ≤5.18e14 확인). 못 넘으면 C1은 덧셈에서 닫고, 설계 채팅에서 "결과만으로 어디를 볼지 발견하기"를 독립 연구 질문으로 재설계한다. 이것이 C1의 마지막 수정이다(규칙 7).

## 13. C1 종료와 C3: Learn Soft, Compile Hard (2026-11-18, 설계 채팅)
**C1-3 판정:** 덧셈 분포 안 0.121. 찾은 표는 a는 정확히 읽고(1.000) b는 읽지 못했다(최대 0.084). 손실 점수는 "한 피연산자만 읽는 표"와 정답 표를 시드 차이보다 작은 폭(0.008)으로만 구별했고, 좌표 하강은 여러 칸을 함께 바꿔야 하는 해에 닿지 못했다. **C1은 덧셈에서 닫는다.**

**1단계에서 확인된 맞교환:** 부드러운 주의(트랜스포머)는 "어디를 볼지"를 쉽게 배우지만(덧셈 분포 안 0.99 이상) 길이 일반화에 실패한다. 단단한 포인터(PF)는 맞게 잡히면 길이와 무관하게 정확하지만, 결과만으로 "어디를 볼지"를 찾지 못했다(경사 3종, 탐색 2종).

**C3 가설:** 학습은 부드러운 모델에 맡기고, 그 모델의 의존 구조를 이산 PF 프로그램으로 컴파일하면, 분포 밖 길이에서 일반화하는 모델을 기준선 예산 안에서 얻는다.

### 13.1 파이프라인 (세 과제 모두 같음)
1. **교사 학습:** `rope`를 기준선과 같은 규약으로 학습한다(시드 0). 교사는 세 과제 모두 `rope`로 고정한다.
2. **의존도 추출 (주 신호):** 교사의 학습 데이터 2,000개, 각 출력 step t에 대해 입력 위치 i별 의존도 s_t(i) = ‖∂(정답 토큰 로짓)/∂(위치 i 임베딩)‖ 를 계산하고, 입력 위치에 대해 합이 1이 되게 정규화한다. 주의 가중치(층·헤드 평균)는 보조로만 기록한다.
3. **이동 표 컴파일 (헤드별 전수 탐색):** PF 이동 표는 (헤드, 현재 토큰 종류 7개) → 이동 6종이다. 헤드 경로는 그 헤드의 열에만 의존하므로 헤드마다 6^7 = 279,936개 열을 전부 시뮬레이션한다.
   - 열 점수 = 모든 출력 step에서, 그 헤드가 읽는 위치의 의존도 s_t(h_t) 평균.
   - 헤드 1 = 최고 점수 열. 헤드 2·3 = 이미 고른 헤드가 읽는 위치의 의존도를 0으로 둔 뒤 다시 최고 점수 열(탐욕 덮기).
   - 정답·참조 정렬은 사용하지 않는다. 입력과 의존도만 쓴다.
4. **학생 학습:** 컴파일된 표로 이동을 고정하고, PF 갱신·출력 제어기를 7절 규약대로 처음부터 학습한다. 레지스터는 straight-through(C1과 같음).
5. **평가:** 기준선과 같은 평가 코드·데이터.

### 13.2 사전 확인 (컴파일 전, 각 과제)
- 손으로 짠 정답 표와 전부 "정지" 표의 의존도 점수를 비교한다. 정답 표 점수가 "정지" 표의 **2배 이상**이 아니면, 의존도가 정렬 구조를 담지 않는 것이므로 그 과제는 멈추고 보고한다. 이때 보조로 주의 가중치 점수도 같은 비교를 기록한다(판정에는 쓰지 않는다).
- 참고 기록(판정 무관): 컴파일된 표가 읽는 위치와 손으로 짠 표가 읽는 위치의 일치율.

### 13.3 FLOPs 회계
교사 학습(판정 시점까지) + 의존도 추출(정방향·역방향) + 표 탐색(헤드 시뮬레이션 연산 수를 FLOPs와 별도 열로 함께 보고) + 학생 학습(판정 시점까지). 덧셈은 합계가 5.18e14 이하여야 한다(7절).

### 13.4 판정
- **유효성 (시드 0):** 덧셈·패리티 학생 분포 안 ≥0.95.
- **1단계 신호:** 7절 기준 그대로(시드 3개, 덧셈 11–20 ≥0.778·21–30 ≥0.500, 합계 FLOPs ≤5.18e14, 패리티 ≥0.99). MQAR은 기준 없이 보고.
- **실패 시:** 사전 확인 실패(의존도에 정렬 없음)와 컴파일 후 일반화 실패를 구분해 보고하고, 설계 채팅에서 판단한다. 추가 수정은 하지 않는다.

### 13.5 신규성 범위
RNN 오토마타 추출, 이산 프로그램으로 컴파일되는 트랜스포머(Learning Transformer Programs, 2023)가 선행한다. 주장 범위는 "같은 계산 예산에서 현대 기준선 4종 대비 분포 밖 일반화와 계산 효율"로 한정한다. "PF가 스스로 어디를 볼지 발견하는 문제"는 C3가 풀지 않으며, 별도 연구 질문으로 남긴다.

## 14. C3-2 판정과 C3-3 (2026-11-18, 설계 채팅) — C3의 마지막 수정
**C3-2 판정**
- **대조군 통과:** 학습 전 교사로 컴파일한 학생은 덧셈 분포 안 0.003·분포 밖 0.000. 성공한 시드의 구조는 사전 지식이 아니라 교사의 학습에서 왔다.
- **시드 재현 미달:** 덧셈 분포 안 0.999·0.002·1.000. 7절 1단계 신호(시드 3개 모두) 미충족. **C3(13절 명세)은 1단계 신호 FAIL로 기록한다.**
- **시드 1 실패 원인 = 컴파일 점수 결함:** 시드 1 교사는 `+` 위치에 a_k와 같은 수준의 기울기 의존도를 두었고(0.147 대 0.149), 끝까지 `+`를 읽는 열이 a를 따라가는 열을 이겼다. `+`는 모든 예에서 같은 기호라 답에 대한 정보가 없다. 기울기 의존도는 위치가 계산에 쓰였는지를 재고, 내용이 답을 바꾸는지를 재지 않는다.
- **패리티:** 세 시드 0.64–0.73. 같은 기계의 C1 PF는 1.000. 레지스터만으로 풀리는 과제이므로 학생 경로의 결함 가능성이 있다. 원인 미상.
- **MQAR:** 토큰 종류 표로 정답 알고리즘을 표현할 수 없다. C3 범위에서 제외한다(질의별 0.371).

**C3-3 변경 1 — 의존도 정의 (주 신호 교체):** 내용 치환 의존도.
- 출력 step t, 입력 위치 i에 대해: 위치 i의 기호를 **같은 토큰 종류의 다른 기호**로 바꾼 입력들(그 종류의 기호를 모두 시도, 최대 9개)에서, 교사의 정답 토큰 확률 변화량 |Δp|의 평균. 입력 위치에 대해 합이 1이 되게 정규화한다.
- 같은 종류에 다른 기호가 없는 위치(구분자 등)의 의존도는 정의상 0이다. 과제별 규칙은 쓰지 않는다.
- 나머지 컴파일(헤드별 전수 탐색, 탐욕 덮기, 정답 정렬 미사용)은 13절 그대로.

**C3-3 변경 2 — 패리티 진단 (규칙 3a):** 전부 정지 표로 학생을 학습한다(시드 0). ≥0.95가 아니면 학생 경로의 결함으로 보고 고친다(확인할 것: 갱신·출력 제어기가 현재 토큰 x_t의 임베딩을 입력으로 받는지, 읽기가 없을 때의 입력 처리). 고친 뒤 결과는 새 이름으로 남긴다.

**절차**
1. 패리티 진단(변경 2).
2. 개발 확인: 시드 0·1·2의 기존 교사로 변경 1의 표를 컴파일하고 학생을 학습한다. 이 결과는 개발용이며 판정에 쓰지 않는다. 시드 1에서 a_k·b_k를 읽는 표가 나오는지 기록한다.
3. **확인 실행(판정용):** 새 시드 3·4·5로 교사부터 전체 파이프라인(변경 1 적용). 과제는 덧셈·패리티.
4. **판정:** 7절 기준을 **시드 3·4·5**에 적용한다(덧셈 11–20 ≥0.778·21–30 ≥0.500·합계 FLOPs ≤5.18e14, 패리티 세 구간 ≥0.99). 시드 0–2 결과는 함께 보고한다.
5. 이것이 C3의 마지막 수정이다(규칙 7). 실패하면 C3을 닫고 설계 채팅에서 1단계 전체를 재판단한다.

## 15. C3 종료와 C4: Compile + Occam (2026-11-18, 설계 채팅) — 1단계의 마지막 수정
**C3-3 판정**
- 덧셈: 판정 시드 3·4·5 모두 7절 기준 충족(분포 안 0.979–0.999, 분포 밖 0.964–1.000, 합계 FLOPs 1.27–1.47e14 ≤ 5.18e14). 개발 시드 0·1·2 포함 6/6 시드에서 a_k·b_k를 읽는 표가 컴파일됐다.
- 패리티: 판정 시드 5만 충족, 시드 3·4는 분포 밖 0.46–0.54. 전부 정지 표 학생은 1.000(학생 경로 결함 없음).
- **사전 기준(시드 3개 모두, 덧셈·패리티) 미충족. C3은 1단계 신호 FAIL로 기록하고 닫는다.**
- 실패 원인: 패리티처럼 의존도가 넓게 퍼지는 과제에서 컴파일이 불필요하게 움직이는 헤드를 만들고, 그 읽기가 학생 학습을 방해한다. 컴파일이 데이터가 뒷받침하지 않는 구조를 넣는 결함이다.

**C4 변경 (이것 하나만): 분포 안 검증에 의한 오컴 선택**
- 과제·시드마다 두 학생을 7절 규약대로 학습한다: (a) C3-3대로 컴파일된 표, (b) 전부 정지 표.
- 각 학생의 판정 체크포인트(분포 안 최고 시점)를 **선택 전용 검증 데이터**로 평가해 고른다. 선택 전용 검증 데이터는 분포 안(학습과 같은 길이 범위)에서 새로 생성한 1,000개로, 학습·평가 데이터와 다른 생성 시드를 쓴다. 보고하는 분포 안 정확도는 기존 평가 데이터 그대로다. 차이가 0.005 이내면 움직이는 헤드 수가 적은 쪽을 고른다. 분포 밖 데이터는 선택에 쓰지 않는다.
- 알려진 한계: 선택지가 "컴파일된 표 전체"와 "전부 정지" 둘뿐이라, 헤드 일부만 불필요한 경우는 거르지 못한다(1단계 두 과제의 결정에는 영향 없음, FUTURE.md).
- 두 표가 같으면(전부 정지로 컴파일된 경우) 학생은 하나만 학습한다.
- 합계 FLOPs = 교사 + 의존도 추출 + 학생 (a) + 학생 (b). 덧셈은 ≤ 5.18e14.
- 나머지(교사, 내용 치환 의존도, 헤드별 전수 탐색, 학생 규약)는 14절 그대로.

**판정:** 한 번도 쓰지 않은 **시드 6·7·8**에서 7절 기준(덧셈 11–20 ≥0.778·21–30 ≥0.500·합계 FLOPs ≤5.18e14, 패리티 세 구간 ≥0.99). 선택된 학생만 판정한다. 선택되지 않은 학생 결과도 함께 보고한다.

**이것이 1단계의 마지막 수정이다.** 실패하면 1단계를 "덧셈 신호 확인, 범용성 미달"로 닫고 설계 채팅에서 방향을 재판단한다. 통과하면 1단계 신호로 확정하고 2단계(규모 시험) 설계로 간다.

## 16. C4 판정과 1단계 종료 (2026-11-19, 설계 채팅)
**C4 판정: 질문에 대한 답은 아니오다.** (원자료 `stage1/results/c4/`, 요약 `77eda52`)
- 덧셈: 판정 시드 6·7·8 모두 7절 기준 충족. 선택된 학생은 모두 컴파일된 표다. 11–20 0.960·1.000·0.978, 21–30 0.958·1.000·0.972, 합계 FLOPs 1.45–1.79e14(기준선 최고 5.18e14의 28–35%).
- 패리티: 시드 6·7은 세 구간 1.000. 시드 8은 두 학생이 모두 낮아(선택용 검증 0.755·0.627) 선택된 학생이 분포 밖 0.516·0.484·0.476이다.
- 선택은 분포 밖 값을 보기 전에 끝났고 커밋 순서로 확인된다. 절차상 문제는 없다.

**1단계 종료: "덧셈 신호 확인, 범용성 미달"** (15절 사전 규칙 그대로). 추가 수정은 하지 않는다. 2단계 규모 시험은 통과 조건부였으므로 하지 않는다.

**확인된 것**
