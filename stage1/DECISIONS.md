# Stage 1 판정 기록

설계 채팅의 판정을 날짜순으로 추가한다. 서준이 전달한 판정을 그대로 옮기며, Claude Code가 판정을 만들지 않는다.

## 2026-11-17 · Phase A 판정 (설계 채팅)
- 기준선 유효성 통과: 덧셈 Abacus 0.998, looped 0.992, 패리티 GRU 1.000 (분포 안).
- 그래프 도달성은 1단계 과제에서 제외(세 기준선 모두 실패, 결과 보존). 연관 기억으로 교체.
- looped에 무작위 반복 횟수 + progressive loss를 넣은 looped_rr 추가(기존 looped 결과 보존).
- 판정 체크포인트: 분포 안 검증 최고 시점. 분포 밖은 그 시점 값으로 보고.
- 기준선만의 Phase B 그리드는 하지 않음. 기준선은 1단계 후보와 함께 돈다.

## 2026-11-17 · Phase A′ 판정 (설계 채팅)
- 연관 기억: 세 기준선 모두 0.31–0.33, 데이터 형식 위반 0건. 기준선이 약한 것으로 판단
  (숫자 아닌 토큰에 위치 신호 없음). 표준 RoPE 트랜스포머 기준선 `rope` 추가.
- looped 기준선은 looped_rr로 교체(α=1 동결). 기존 looped 결과는 보존.
- 도달성은 다시 돌리지 않음.
- 1단계 비교 기준선: abacus, rope, looped_rr, gru. 기준값은 과제·구간별 최고 분포 밖 정확도.

## 2026-11-17 · Phase A″ 판정 (설계 채팅)
- 하네스는 정상(위치만 쓰는 대조 1.000, loss·마스크·디코딩 확인). 원인은 **질의 하나짜리 형식**: step당 지도 신호가 답 64개뿐이라 내용 매칭이 학습되지 않는다. 표준 형식(MQAR)으로 바꾼다.
- 학습률 등 옵티마이저는 **기준선별로 조정하지 않는다.** 모든 기준선과 1단계 후보가 같은 설정을 쓴다. 조정은 공정한 비교를 깨는 튜닝이다.
- 기준선 작업은 이번이 마지막이다(규칙 7). 아래 중단 규칙을 따른다.

## 2026-11-17 · Phase A‴ 판정 (설계 채팅)
- 기준선 작업 종료. MQAR에서 트랜스포머 3종 질의별 분포 안 ≥0.997, 중단 규칙 미적용.
- Phase A 실행 값을 "분포 안 최고 시점" 규칙으로 로그에서 다시 고른 것을 승인한다. 규칙이 분포 밖 값과 무관하게 모든 실행에 같게 적용됐기 때문이다. 원래 Phase A 항목은 기록으로 보존한다.
- MQAR 기준값은 질의별(teacher-forced)을 주로 쓰되, 후보와 기준선 모두 시퀀스 전체(greedy)도 함께 보고한다. MQAR에는 판정 기준이 없다.
- 후보 설계 C1 Pointer Fold 동결 (`stage1/CANDIDATE_DESIGN.md`, PR #785).

## 2026-11-18 · C1-1 판정 (설계 채팅)
- 유효성 미달: 덧셈 분포 안 0.005 (PF-cont 0.393). C1-1은 FAIL로 기록한다.
- 패리티 분포 밖 전 구간 1.000(기준선 최고와 동등, FLOPs 약 절반), MQAR 질의별 분포 밖 0.993·0.997·0.998, 시퀀스 전체 0.876·0.904·0.910(기준선 최고 0.610·0.098·0.000). 판정 시점 FLOPs 4.41e13(기준선 최고 2.68e14). 단, 학습 불안정(마지막 시점 0.624)과 내용 점프의 기여는 아직 미확인이다.
- 덧셈 실패 원인은 표현력이 아니라 이동 선택의 기울기 추정기(이동 고정 시 1,000 step에 1.000, 이동 로짓 기울기 평균 6e-6). C2로 가지 않는다.
- PF-search가 멈춘 것은 설계서 명세 누락 때문이다. 11절에 명세를 채웠다.
- 시드 확장·어블레이션은 덧셈 유효성이 확보된 뒤에 한다.
