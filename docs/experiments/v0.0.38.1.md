# v0.0.38.1 — Mixed Local + Coupled Harder-Family Gate

Status: pre-registered fresh-data family redesign

## Why this experiment exists

v0.0.38 was methodologically valid but failed its pre-registered H4 gate:

    active examples with accepted one-row eliminations > 0
        = 0.5625
        < 0.75

The failure is kept as-is.

The pure coupled family created a real primitive-completeness gap, but it did
not provide the intended bridge:

    local compression makes real progress
        ↓
    local primitive saturates
        ↓
    multi-row structural headroom remains

v0.0.38.1 changes the generator, not the gate.

No v0.0.38 threshold or hardness criterion is relaxed.

## Frozen old pipeline

Carry forward the validated v0.0.37 one-row pipeline unchanged:

    target-leaf @ 0.10
        ↓
    deterministic checker
        ↓
    Markowitz residual @ 0.05
        ↓
    deterministic checker

No threshold calibration is allowed on v0.0.38.1 data.

## Mixed structural family

Use the same scale grid:

    k in {2, 4}
    n in {4, 8, 16, 32}
    n >= k

Let:

    d = n - k

### Controls

If:

    d = 0

generate the dense core only.

### Smallest active cell

If:

    d = 2

retain the v0.0.38 pure coupled motif:

    y + z = f(core)
    y - z = g(core)

This cell has no room for both motif classes.

### Mixed active cells

If:

    d >= 4

reserve exactly:

    easy_leaf_count = 2

derived variables as independent one-row leaves.

Each easy leaf has one row:

    u = h(core)

where the target coefficient is exactly +1 and all core-side coefficients have
absolute value in {2, 3}.

The remaining:

    d - 2

derived variables are partitioned into exact coupled 2x2 blocks:

    y + z = f(core)
    y - z = g(core)

Therefore:

    block_count = (d - 2) / 2

for d >= 4.

All derived rows depend only on core variables and their own declared derived
targets.

Cross-block and leaf-to-block dependencies remain out of scope.

## Permutation and naming

Every generated system uses:

- random row permutation,
- random column permutation,
- generic variable names v0...v(n-1),
- bounded integer coefficients,
- exact integer ground truth.

No inference method receives generator k, leaf identity, block identity, or
unpermuted positions.

## Candidate-visibility contract

The existing one-row candidate enumerator should see:

    expected_candidate_count
        = easy_leaf_count + 4 * block_count

on active mixed examples.

This is reported as a diagnostic but is not a replacement for H4.

The binding H4 remains accepted one-row progress.

## Exact mixed reference

The exact reference removes:

1. every declared easy leaf using its exact one-row affine rule,
2. every declared coupled pair using the exact 2x2 block rule.

The mixed checker must independently re-derive all algebra from the original
system.

Generator metadata may identify only:

- easy-leaf row/target pairs,
- coupled-block row-pair/target-pair identities.

The checker remains execution authority.

The final retained system must contain exactly the k core variables.

## Mixed-reference safety

The mixed reference is accepted only if:

1. all easy-leaf candidates validate against original rows,
2. all 2x2 block candidates validate against original rows,
3. all removed row identities are disjoint,
4. all eliminated target identities are disjoint,
5. reconstruction dependencies are acyclic,
6. the retained system is square and exactly solvable,
7. reconstruction verifies the ORIGINAL full system,
8. reconstructed values equal ground truth exactly.

All arithmetic remains exact Fraction/integer arithmetic.

## Frozen H1-H5 gates

The v0.0.38 hardness thresholds remain unchanged.

### H1 — Oracle reaches declared core

Over active systems:

    mean exact-mixed-reference retained-dimension error = 0

### H2 — Old local pipeline remains materially incomplete

Over active systems:

    mean one-row elimination recovery <= 0.75

where:

    one-row elimination recovery
        = one-row accepted eliminations
          / (n - k)

### H3 — The remaining gap matters computationally

Over active systems:

    mean one-row solver-savings recovery <= 0.90

where:

    oracle solver savings
        = full baseline solver ops
          - exact mixed-reference solver ops

### H4 — Old pipeline still makes real progress

Over active systems:

    fraction with one-row accepted eliminations > 0
        >= 0.75

This criterion is unchanged from v0.0.38.

### H5 — Multi-row value remains broad

At least 5 of the 7 active cells must satisfy:

    mean retained_dimension_gap
        >= 0.5 * coupled_block_count

where:

    retained_dimension_gap
        = one-row retained dimension - k

For the d=2 pure-coupled cell:

    coupled_block_count = 1

## Central result

The redesign achieved the bridge that v0.0.38 failed to establish.

On every mixed active cell, the frozen local pipeline recovered the declared
easy leaves at:

    100%

Yet aggregate total elimination recovery remained only:

    25.43%

and aggregate solver-savings recovery remained only:

    33.53%

This means the residual gap cannot be explained by a generally broken local
pipeline.

The local primitive succeeds on the structure it is designed to handle, then
saturates while substantial multi-row structure remains.

The measured architecture is therefore:

    raw exact system
        ↓
    frozen local one-row compression
        ↓
    genuine verified local progress
        ↓
    local primitive saturation
        ↓
    large residual multi-row headroom
        ↓
    exact 2x2 block compression reference
        ↓
    declared core

This is the intended harder Structural Compression testbed.
