Each seed must pass independently on:

1. `iid64`;
2. `size_surface_shift128`;
3. all 24 cases combined.

Every cell requires:

- all retained answers independently verified on the original LP;
- positive Oracle and candidate savings;
- utility recovery >= 0.80;
- discovery burden <= 0.20;

No holdout tuning is authorized.

This is a useful failure rather than a cost failure. On IID64, the frozen
support proposer reproduces the development result. On the larger
size+surface-equivalent group, inference remains cheap, but the proposal fails
to capture enough of the available Oracle structural savings.

## Representation diagnosis boundary

The v0.0.98 holdout may motivate a **higher-level representation redesign**,
but its case labels, support misses, or route outcomes may not be used to tune
a replacement.

A code-level invariance audit identifies a principled candidate problem in the
current CG5 point representation:

- positive column scaling is removed exactly by column normalization
  `D=A/||A_j||`, `q=c/||A_j||`;
- several point features are invariant to a signed row permutation when A and b
  transform together;
- the signed feature `D.mean(0)` is not invariant to independent row-sign
  changes;
- `abs(D).mean(0)` also changes scale with row count unless explicitly
  normalized for m.

This is a **mechanistic hypothesis**, not a causal conclusion from the holdout.
The next development step must use opened development data or analytic
metamorphic tests only, define the equivalence group first, and test whether a
quotient representation removes these forbidden surface degrees of freedom.
Do not re-evaluate a redesigned model on these 24 holdout cases.
