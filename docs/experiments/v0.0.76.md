# v0.0.76 — Q4 task-admissibility gate

Status: protocol frozen before the first audit.

## One question

Is the existing v0.0.29–v0.0.31 generated 2x2 linear-system text task
admissible for Q4's matched **model-level** Direct-program versus
Structural-IR comparison, or does a zero-learned-parameter deterministic
path already saturate the task?

This version deliberately does **not** train a new model. Q4 must not be
tested on a benchmark whose semantic work is already solved by a cheap
hand-written compiler.

## Why this gate is necessary

The earlier matched MLP and Tiny Transformer experiments showed a large
verified-quality gap between final-answer learning and a Structural path.
But the Structural path had access, after its learned family decision, to
`ControlledLinearSystemStructureFormer`, which deterministically parses the
entire controlled equation grammar into solver-ready matrix IR.

That is useful capability evidence, but it creates a serious Q4 confound:
a new Direct model could appear inefficient merely because one path receives
a deterministic semantic compiler that the other path does not.

Before spending any further training budget, test whether the existing task
needs learned semantic inference at all.

## Frozen candidate and fresh audit split

Candidate family: the existing controlled 2x2 integer linear-system grammar.

Fresh audit positives:

- 243 deterministic systems
- seed: 7602
- all 81 ordered integer solution pairs in [-4, 4]^2 represented
- text must be disjoint from every v0.0.29, v0.0.30 and v0.0.31 corpus

Each positive receives one paired near-negative using the already frozen
three-mode transformation cycle:

1. inequality,
2. nonlinear variable multiplication,
3. underspecified one-equation system.

No audit text is used for training because this version trains nothing.

## Zero-learned-parameter comparator

For each positive:

    raw text
      -> ControlledLinearSystemStructureFormer
      -> LinearSystemSolver
      -> DeterministicVerifier
      -> hidden-generator solution equivalence check

For each paired near-negative:

    raw text
      -> ControlledLinearSystemStructureFormer
      -> must fail closed to UNKNOWN

The hidden generator solution is evaluation-only authority. It is never
available to the compiler or solver.

The comparator has **zero fitted learned parameters**. Python parser/runtime
code is deterministic tooling and its wall time is reported, not hidden.

## Metrics

Report:

- positive compile rate,
- positive deterministic-verifier rate,
- positive hidden-solution equivalence rate,
- paired-negative fail-closed rate,
- median positive complete-path milliseconds,
- median paired-negative rejection milliseconds,
- mean representation / solver / verification ledger steps,
- learned parameter count, fixed to zero.

Timing is diagnostic only in this gate. The admissibility decision is based
on verified capability, not a latency threshold.

## Pre-registered decision

### `REJECT_EXISTING_LINEAR_TASK_FOR_Q4`

Required simultaneously:

1. positive hidden-solution-equivalent verified rate >= 0.99,
2. paired-negative fail-closed rate >= 0.99,
3. learned parameter count = 0,
4. all 243 positive and 243 negative observations are retained.

Interpretation:

> the controlled 2x2 text task is not an admissible central Q4 benchmark,
> because learned semantic discovery is not required to achieve essentially
> complete verified capability.

This does **not** invalidate v0.0.29–v0.0.31. Those remain controlled
capability/allocation experiments. It only prevents promoting them into a
total-compute Q4 result.

### `LINEAR_TASK_REMAINS_Q4_CANDIDATE`

If either capability condition fails, retain the failures and investigate
why before any model training. Do not lower the 0.99 thresholds after the
audit.

## Consequence for the next experiment

If the existing task is rejected, the next Q4 benchmark must satisfy all of:

- raw input requires nontrivial learned semantic inference,
- strongest cheap deterministic processing does not already saturate it,
- Direct and Structural models receive the same raw input,
- Direct predicts an executable program/IR, not merely an answer class,
- both paths receive identical executor and original-task verifier authority,
- deterministic semantic work available to one path is also available to the
  other, or to neither,
- architecture/parameter/training-cardinality budgets are frozen before
  training,
- model inference, deterministic tooling, retries/fallback, memory, and
  training amortization are reported separately,
- final Q4 judgment uses matched independently verified capability and total
  compute.

## Claim boundary

v0.0.76 is a benchmark-selection gate. It cannot establish a NEUMANN
speedup, model advantage, scaling advantage, energy advantage, or
cross-domain generalization.
