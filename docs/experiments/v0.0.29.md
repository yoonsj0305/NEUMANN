# v0.0.29 - Matched-capacity token direct-vs-structure

## Research question

At the same small learned inference capacity, does a structure-first path preserve verified problem-solving quality better than asking the learned model to produce the numeric answer directly?

This is the first NEUMANN benchmark that compares:

    Direct learned path
    raw token sequence
      -> tiny neural model
      -> (x0, x1)
      -> evaluation verifier

against:

    Structural path
    raw token sequence
      -> same-capacity tiny neural model
      -> LINEAR / ABSTAIN
      -> deterministic compiler
      -> deterministic solver
      -> deterministic verifier

The experiment is intentionally limited to generated, controlled, nonsingular 2x2 linear systems.

## Why one family only

Bipartite matching and linear systems have fundamentally different answer spaces.

A matching answer must point back to identifiers in the input. A linear-system answer is a pair of numeric values. Combining both into one "direct solver" would require a much larger multi-task output protocol and would make the first paired comparison harder to interpret.

v0.0.29 therefore isolates one family and makes the comparison clean before broadening it.

## Corpus

The corpus is generated deterministically.

- training positives: 128
- validation positives: 32
- final positives: 64
- integer hidden solutions in [-4, 4]
- invertible integer 2x2 coefficient matrices
- exact right-hand sides generated from the hidden solution
- multiple variable-name pairs
- optional controlled prefixes such as Solve: and Equation:

Each positive also has one deterministic unsupported near-negative for the structural abstention task.

Near-negative modes rotate across:

1. inequality
2. nonlinear variable multiplication
3. underspecified one-equation system

Training, validation, and final splits use different fixed seeds and must be text-disjoint.

## Matched learned architecture

Both learned paths use:

- the exact same fixed-position token encoder
- the same input dimension
- one tanh hidden layer
- 8 hidden units
- two real-valued outputs
- the same sklearn MLPRegressor family
- the same optimizer configuration
- the same random seed
- the same dense weighted-sum architecture proxy

The output semantics differ.

Direct:

    output[0], output[1] -> normalized numeric solution

Structural:

    output[0], output[1] -> LINEAR score, ABSTAIN score

Therefore model parameter count and forward matrix shape are directly matched.

## Token encoder

This is sequence-sensitive but deliberately simple.

Each token position contains:

- one categorical token feature
- an additional scaled scalar for numeric tokens

Single-letter variable names are canonicalized by order of first appearance.

The encoder has no learned parameters.

This is not an embedding model or an LLM tokenizer. It is a controlled token-position research representation.

## Important supervision asymmetry

Inference capacity is matched.

Training supervision cardinality is not.

The direct model trains on the 128 positive systems because numeric answers are defined only there.

The structural model trains on those same 128 positives plus 128 paired near-negatives so it can learn abstention.

This is reported explicitly. v0.0.29 must not be described as a matched-training-data experiment.

## Structural threshold

The structural model is fitted on the training split.

Its decision margin is:

    LINEAR score - ABSTAIN score

Validation near-negatives determine the threshold:

    max(validation negative margin) + 0.10

The contract additionally requires all validation positives to remain above that threshold. Otherwise model construction fails.

No final example is used to choose this threshold.

## Direct verification boundary

The direct model receives only the encoded raw text and produces two numeric values.

During evaluation only, the deterministic compiler creates a reference representation so the existing independent verifier can check whether those two numbers satisfy the original equations.

That reference compiler output is not available to the direct model and is not part of direct inference.

## Cost accounting

Report separately:

- learned parameter count
- learned layer shapes
- dense weighted-sum term proxy
- active encoded input scalars
- diagnostic model wall-clock
- deterministic solver steps for the structural path
- deterministic verification steps

Do not add the learned arithmetic proxy and CostLedger steps into one synthetic number. They have different units.

The dense weighted-sum proxy is not FLOPs, CPU instructions, memory traffic, latency, or joules.

## KEEP contract

KEEP means the paired measurement is valid, not that NEUMANN won.

Required:

1. direct and structural learned parameter counts match exactly
2. direct and structural layer shapes match exactly
3. direct and structural dense weighted-sum proxies match exactly
4. generated final positives compile to valid 2x2 linear systems
5. all direct outputs are finite
6. compiler-gated final false-route rate on near-negatives is zero
7. all learned-work observations are positive

Not a KEEP condition:

- structural verified coverage exceeding direct
- direct model failing
- any specific RMSE
- any wall-clock winner
- any LLM or energy claim

The outcome must be retained even if the direct path performs better.

## Claim boundary

This benchmark has a hand-written narrow deterministic compiler. It is designed to test a specific decomposition hypothesis under controlled conditions.

It does not show that a small language model beats a frontier language model, and it does not yet show token, GPU-memory, FLOP, or energy savings in an actual language model.

## Interpretation

This is the first NEUMANN result in which the learned inference architecture is held constant while the learned objective changes.

On this controlled corpus:

- asking the 8-unit model to directly approximate the two numeric answers did not produce a single answer that passed the strict deterministic equation verifier;
- asking the matched-capacity model only to identify whether deterministic linear structure was applicable preserved all 64 final tasks, after which the deterministic compiler and Gaussian-elimination solver produced verified answers.

That is evidence for a **matched-learned-capacity quality effect**:

> under this narrow setup, spending learned capacity on selecting valid structure was more effective for verified task completion than spending the same learned capacity on direct numeric answer regression.

It is **not yet evidence of lower total computation**.

The Structural path pays additional deterministic compiler, solver, and verifier work. The current learned arithmetic proxy and `CostLedger` steps have different units and are deliberately not added together.

It is also not evidence that direct learning fundamentally cannot solve 2x2 systems. The direct model is deliberately tiny, uses a hand-designed fixed-position encoder, and was not subjected to a capacity/data sweep. Its 0% verified rate may reflect insufficient capacity, unsuitable inductive bias, insufficient training data, or all three.

## Next falsification step

The next experiment should not simply celebrate the 64/64 versus 0/64 gap.

It should try to erase it.

A v0.0.30 capacity/data sweep should increase the direct model's:

- hidden width
- training-set size
- possibly depth, while recording the exact added state and arithmetic proxy

and ask:

> At what learned capacity, if any, does the direct path reach the same strict verified coverage as the structure-first path?

The scientifically useful quantity is then a **break-even frontier**, not a single win/loss result.
