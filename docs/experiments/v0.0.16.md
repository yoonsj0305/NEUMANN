# v0.0.16 — Digest-Bound Activation and Revocation Ledger

## Question

Can plugin execution authority be checked at use time so revocation stops the next solver action even if plugin code is already imported and registered?

## Authority model

Approval is bound to:
- plugin_id
- exact canonical manifest SHA-256

A changed manifest is not covered by an old approval.

Ledger actions are append-only in process:
- APPROVE
- REVOKE
- APPROVE again if desired

Each event receives a monotonically increasing sequence number.

## Managed runtime path

manifest discovery
→ explicit approval
→ authorized activation
→ managed plugin registration
→ RegistryEngine
→ use-time authorization check
→ solver

ManagedPluginRegistry checks the ledger on every get(kind) used by RegistryEngine.

Therefore revocation can block execution without unloading already imported Python code.

## Required proof

1. unapproved manifest cannot trigger resolver/import
2. exact approved digest activates
3. changed manifest digest is rejected
4. approved plugin executes once
5. revoke authorization
6. next execution fails closed
7. solver call count does not increase after revocation
8. re-approval of the same manifest can restore execution

## Boundary

The ledger is currently in-memory only.

It does not yet provide:
- durable storage
- cryptographic signatures
- tamper-evident external audit storage
- distributed consistency
- OS/process sandboxing
- forced module unload

Revocation means execution authority is withdrawn in the managed NEUMANN runtime path. It does not erase already imported Python code from memory.
