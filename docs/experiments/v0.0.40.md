# v0.0.40 — Coupled-Block Discovery / Routing Gauntlet

Status: pre-registered fresh-data discovery experiment

## Motivation

v0.0.38.1 validated the mixed local + coupled family:

- easy local leaves were recovered at 100%,
- the frozen one-row path made progress on 88.84% of active systems,
- total elimination recovery remained 25.43%,
- solver-savings recovery remained 33.53%,
- all original H1-H5 gates passed.

The family-design question is therefore closed.

The next question is:

> Can NEUMANN discover and route the remaining multi-row structure using cheap
> deterministic structure alone, or is learned block scoring actually needed?

v0.0.40 tests deterministic discovery first.

No learned block model is trained in this version.

## Fresh data

Use the frozen v0.0.38.1 mixed-family generator with new seeds.

Scale grid:

    k in {2, 4}
    n in {4, 8, 16, 32}
    n >= k

Per cell:

    final = 32 systems

Total:

    256 systems

Every v0.0.40 signature must be unique and disjoint from the merged
v0.0.38.1 audit set and all comparable prior merged corpora.

Generator block identities are used only for secondary discovery-label metrics
and for the exact mixed reference.

They are not available to deployable discovery methods.

## Frozen reference architecture

The exact mixed reference remains:

    declared easy leaves
        +
    declared exact 2x2 coupled blocks
        ↓
    exact retained solve
        ↓
    reconstruction
        ↓
    original full-system verification

This reference is a family oracle, not a discovery method.

## Frozen legacy baseline

Carry forward the v0.0.37 local pipeline unchanged:

    target-leaf @ 0.10
        ↓
    deterministic checker
        ↓
    Markowitz residual @ 0.05
        ↓
    deterministic checker

This baseline receives no block discovery.

## Discovery primitives

Let a one-row affine candidate target be "candidate-visible" in a row if the
existing frozen one-row enumerator emits that row-target identity.

Let target incidence be the number of original rows with nonzero coefficient
for that variable.

All methods below operate on the permuted original system and generic variable
names only.

They receive neither k, easy-leaf identity, block identity, nor generator
positions.

### D0 — Frozen local-first, no blocks

The legacy baseline above.

Purpose:

    measure the already-frozen local-only floor.

### D1 — Local-first + exact candidate-overlap blocks

1. run the frozen local pipeline,
2. mark its accepted rows and targets unavailable,
3. for every pair of remaining rows:
   - compute the intersection of candidate-visible targets,
   - if the intersection contains exactly two targets,
     derive the exact 2x2 block algebra from those rows/targets,
   - retain the block candidate only if the exact block checker validates it,
4. greedily accept non-conflicting discovered blocks in deterministic
   row-pair / target-pair order,
5. materialize local + block reductions jointly,
6. verify the original full problem.

This tests whether routing too much structure through the old local stage harms
block discovery.

### D2 — Incidence router + exact candidate-overlap blocks

Before local reduction:

    route target-incidence == 1 candidate targets to the local path

and:

    reserve target-incidence > 1 candidate targets from local elimination.

Local candidates in the first group are processed in the frozen target-leaf
score order under the deterministic checker.

Then discover blocks exactly as in D1 from the remaining rows/targets.

This is the primary cheap routing baseline.

### D3 — Incidence router + sparse shared-unit pair

Use the same incidence router as D2.

For each pair of remaining rows:

1. find variables whose coefficient magnitude is exactly 1 in both rows,
2. require global target incidence == 2,
3. if exactly two such targets are shared, derive and validate the exact 2x2
   block candidate,
4. greedily accept non-conflicting candidates in deterministic order.

This is a cheaper, more motif-specific sparse structural heuristic.

### D4 — Incidence router + row/target component graph

Use the same incidence router as D2.

Build a bipartite graph over:

- remaining row nodes,
- remaining candidate-visible target nodes.

Add an edge for each row-target identity emitted by the frozen one-row
candidate enumerator.

For each connected component containing:

    exactly 2 row nodes
    exactly 2 target nodes

derive and validate the exact 2x2 block candidate.

Greedily accept non-conflicting candidates in deterministic order.

This tests whether topology alone is sufficient.

## Shared authority contract

Discovery and routing are advisory.

Every accepted local or block reduction must be re-derived and validated from
the original exact system.

Final authority remains:

    deterministic algebra checker
        ↓
    exact retained solve
        ↓
    reconstruction
        ↓
    verify ORIGINAL full system

Required:

    verified retention = 1.0
    unsafe accepted reductions = 0

## Generic mixed materialization

v0.0.40 introduces no new algebra.

It generalizes the validated v0.0.38.1 mixed materializer so it can receive:

- an arbitrary validated set of one-row affine candidates,
- an arbitrary validated set of exact 2x2 block candidates.

It must reject:

- row conflicts,
- target conflicts,
- algebra mismatch,
- cyclic reconstruction dependencies,
- non-square retained systems,
- exact-solve failure,
- original-problem verification failure,
- ground-truth mismatch.

## Deterministic sufficiency gate

Let the best deterministic deployable method be selected by:

1. highest mean solver-savings recovery,
2. lower mean final solver ops,
3. fewer mean discovered block candidates,
4. fewer mean row-pair examinations,
5. fixed method order D2, D3, D4, D1.

Selection uses the final audit only to describe which pre-registered method won;
there is no fitted threshold or post-hoc method modification.

### KEEP_DETERMINISTIC_DISCOVERY

Required for the selected deterministic method:

    mean solver-savings recovery >= 0.95
    mean elimination recovery >= 0.95
    block recall >= 0.95
    verified retention = 1.0
    unsafe accepted reductions = 0

If all hold:

    decision = KEEP_DETERMINISTIC_DISCOVERY

and no learned block scorer is justified on this family.

### LEARNED_DISCOVERY_HEADROOM

If safety holds but the best deterministic method has:

    0.70 <= solver-savings recovery < 0.95

or:

    0.70 <= block recall < 0.95

then:

    decision = LEARNED_DISCOVERY_HEADROOM

v0.0.41 may test a smallest-adequate learned block scorer.

### REDESIGN_DISCOVERY_REPRESENTATION

If the best deterministic method remains below 0.70 on either primary recovery
or block recall:

    decision = REDESIGN_DISCOVERY_REPRESENTATION

Do not increase neural capacity immediately.

## Anti-triviality diagnostic

A deterministic method may achieve 100% on this frozen family.

That is a scientifically valid result.

If so, the conclusion is not that Structural Compression is solved.

The conclusion is:

> the current mixed 2x2 motif remains structurally transparent enough that a
> cheap deterministic router/discovery rule captures it.

The next harder family would then need to remove the diagnostic shortcut, for
example by:

- varying 2x2 target coefficients beyond +/-1,
- adding distractor row overlaps,
- adding cross-block dependencies,
- mixing block sizes,
- introducing structurally equivalent alternative decompositions.

No such harder-family redesign occurs inside v0.0.40.

## Cost boundary

Do not combine unlike units into a single synthetic compute score.

Report separately:

- discovery row-pair examinations,
- candidate construction counts,
- exact checker/materialization work,
- retained-system solver arithmetic ops,
- reconstruction ops,
- verification ops.

## Important tie interpretation

D2, D3, and D4 are **performance-equivalent** on this audit set.

The pre-registered method-selection rule chose D4 because, after equal recovery,
equal final solver work, and equal discovered-block counts, it used fewer
reported row-pair examinations.

This does **not** establish that D4 has lower total discovery cost.

D4 reports graph-edge examinations instead of row-pair examinations, and the
experiment explicitly forbids combining unlike cost units into a synthetic
score.

Therefore the valid conclusion is:

> D2, D3, and D4 all recover the full verified compression value on this
> family; D4 is the formal selected method under the frozen tie-break, not a
> demonstrated universal cost winner.

## Central structural result: routing before discovery

The strongest v0.0.40 result is the D1 -> D2 transition.

D1:

    coupled targets consumed locally = 0.7109 / system on average
    block recall                     = 86.46%

D2:

    coupled targets consumed locally = 0
    block recall                     = 100%

The exact same block-overlap discovery primitive changes from incomplete to
perfect when target incidence is used to reserve multi-row structure before
local elimination.

The causal architecture suggested by this family is therefore:

    raw exact system
        ↓
    cheap structural routing
        ├── incidence 1 -> local one-row path
        └── incidence >1 -> reserve for multi-row path
        ↓
    deterministic structure discovery
        ↓
    exact algebra checker
        ↓
    retained solve
        ↓
    reconstruction
        ↓
    original-problem verification

This is stronger than a "better block scorer" story.

The main failure mode was consuming the wrong structural degrees of freedom too
early.

## Why learning is deleted here

A learned block scorer would have no measured residual value on this frozen
family.

Three pre-registered deterministic methods already achieve:

    100% solver-value recovery
    100% elimination recovery
    100% block recall
    100% verified retention
    0 unsafe reductions

Adding learned capacity would increase system complexity without recovering any
remaining primary-value headroom.

Therefore:

    learned block scorer = DELETE for this family

This follows the same deletion discipline used in v0.0.37.

## Anti-shortcut diagnosis

The mixed 2x2 family is now saturated.

Its remaining structure is transparent to cheap deterministic signals:

- target incidence,
- candidate-overlap topology,
- shared unit coefficients,
- 2-row / 2-target connected components.

The next harder family must remove at least one of these shortcuts before any
new learned-capacity experiment is meaningful.

Promising perturbations include:

1. generic invertible 2x2 target matrices instead of only +/-1 motifs,
2. distractor row/target overlaps that create false 2x2 components,
3. cross-block dependencies,
4. mixed block sizes,
5. multiple algebraically valid decompositions with different downstream cost,
6. local structures whose incidence alone does not reveal routing class.

## v0.0.40 closure

The v0.0.40 research question is closed.

Validated runtime idea on this family:

    incidence-aware router
        ↓
    deterministic block discovery
        ↓
    exact independent validation
        ↓
    original-problem verification

Do not train a block-discovery neural model on this family.

## Claim boundary

v0.0.40 supports only:

> on this frozen generated mixed local + coupled 2x2 family, cheap
> deterministic incidence-aware routing plus deterministic block discovery
> recovers all measured verified structural-compression value.

It does not establish:

- domain-general routing,
- domain-general block discovery,
- learned structural reasoning,
- natural-language Structural Compression,
- total-compute superiority,
- global minimality,
- asymptotic improvement.

## Next research direction

The next version should be a harder anti-shortcut structural family.

It should be designed so that:

    cheap local routing still has value

but:

    incidence / exact 2x2 component topology alone is insufficient.

Only if deterministic methods leave pre-registered verified downstream
headroom should learned structural discovery be reconsidered.
