# v0.0.102 — Final fresh Q34 holdout and Q3/Q4 closure

## Purpose

v0.0.101 is the final opened-development gate for the current constructed-LP
point-support line. It admitted one frozen deployable contract:

quotient point ranking -> top2m restricted solve -> if the original verifier
rejects, top4m restricted solve -> if that rejects, charged Direct fallback.

v0.0.102 is the single final fresh holdout authorized by the frozen
Q3/Q4 closure rule. There is no further local rescue after this holdout.

## Frozen model and execution authority

Use exactly the two v0.0.100 quotient checkpoints:

- QUOTIENT_s100001
- QUOTIENT_s100002

Use exactly the v0.0.101 adaptive execution contract:

- frozen quotient features;
- one frozen point-model ranking;
- top2m restricted solve;
- original-problem verification;
- on verifier rejection only, top4m restricted solve;
- original-problem verification;
- on rejection only, charged full Direct fallback.

No fitting, optimizer step, checkpoint selection, feature change, support-width

The sealed v0.0.98 holdout and v0.0.101 development outcomes may not be used as
candidate inputs.

## Two-phase holdout discipline

The holdout sources are registered and byte-frozen before any model is loaded
or any candidate route is evaluated.

### Source registration

Generate 24 new base problems with seeds 100500..100523:

- first 12: m=64, n=1024;
- next 12: m=128, n=2048;
- alternating condition number 1 / 1000;
- width factor 16.

For every base problem create one mathematically equivalent surface view using
a signed row permutation plus positive column scaling. The transformation seed
is base_seed + 400000.

This yields 48 holdout views, four cells of 12:

- m64_base
- m64_surface
- m128_base
- m128_surface

The source registration phase may generate and independently certify the Oracle
basis, but must record:

- model_access = false
- candidate_inference = false
- timing = false
- route_evaluation = false

No candidate checkpoint may be loaded during source registration.

### Evaluation

Only after the source archive is committed may the evaluation runner load:

- DIRECT
- ORACLE
- ADAPTIVE_s100001
- ADAPTIVE_s100002

For every case/route use one warmup and three retained timed repetitions in
fixed serial shuffled order seed 102991 + repeat.

Checkpoint restoration, source decoding, and import/setup are reported
separately and cannot rescue or fail the per-query Q34 gate.

## Frozen Q3/Q4 closure gate

Compute the same Q34 quantities on each of the four cells and on all 48 views
combined.

Every model seed must independently satisfy every cell and combined set:

1. every retained answer verifies against the original LP;
2. Oracle savings are positive;
3. candidate pre-discovery savings are positive;
4. structure utility recovery >= 0.80;
5. discovery burden <= 0.20;
6. amortized complete cost / Direct < 1.00.

No favorable cell may hide a failing cell.

If both seeds satisfy the full conjunction:

- decision = CLOSE_Q3_PASS_Q4_PASS_ADVANCE_Q5
- Q3 = PASS_LP_MECHANISM
- Q4 = PASS_LP_MECHANISM
- advance_q5 = true

Otherwise:

- decision = CLOSE_Q3_Q4_CURRENT_LP_FORMULATION_REJECTED_NO_Q5
- Q3 = REJECTED_CURRENT_LP_FORMULATION
- Q4 = REJECTED_CURRENT_LP_FORMULATION
- advance_q5 = false

No second fresh holdout, threshold rescue, width rescue, refit, or use of the
v0.0.98 holdout is authorized after this decision.

The closure is scoped to this constructed-LP mechanism. It is not a claim that
general Q3/Q4 across all domains are solved.
