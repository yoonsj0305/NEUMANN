# v0.0.35 — Utility-Directed Structural Compression

Status: pre-registered research specification

## Motivation

v0.0.34 produced a central negative result:

> Better reference-rule classification does not imply better verified Structural Compression.

The frozen learned scorer achieved the highest generator-reference F1, but simple deterministic heuristics produced lower final solver work.

Therefore v0.0.35 changes the learning target.

The primary target is no longer:

    "Is this candidate in the generator dependency DAG?"

The new target is:

    "How much verified solver work does this candidate remove?"

This is called **Value-of-Reduction**.

## Core research question

> Can a small utility predictor rank certified reductions by downstream computational value better than a reference-label imitation model and strong deterministic heuristics?

## Controlled family

The same leakage-hardened affine-linear family is retained:

- generic variable names,
- randomized row order,
- randomized column order,
- affine dependency rules,
- chained dependencies,
- exact full-problem verification.

v0.0.35 uses new deterministic splits that are disjoint from:

- all v0.0.33 train / validation / final examples,
- all v0.0.34 calibration / final examples.

Scale grid:

    k in {2,4}
    n in {4,8,16,32}
    n >= k

Per cell:

    utility training    = 64
    utility calibration = 24
    utility final       = 32

## One-step utility label

For each full-system candidate c:

1. measure baseline full-system solver arithmetic operations,
2. attempt the certified one-candidate reduction {c},
3. if the reduction is invalid, label utility = 0,
4. if valid, measure reduced solver arithmetic operations,
5. define normalized one-step solver utility:

    U(c) = max(0, C_full - C_after(c)) / C_full

where C is the declared exact Gaussian solver arithmetic-op count.

This is an oracle training label only.

The inference policy does not compute U(c) by solving every candidate.

## Utility learner

To avoid the cross-run MLP refit problem discovered in v0.0.34, the first utility learner uses a deterministic small tree model:

    DecisionTreeRegressor

Pre-registered hyperparameters:

- max_depth = 6
- min_samples_leaf = 16
- random_state = 35
- criterion = squared_error

Input features:

- exactly the same frozen 16 candidate features used by v0.0.33/v0.0.34

This isolates **target change** from **representation change**.

No variable-name, row-index, column-index, k, or n-k feature is supplied.

## Comparison policies

v0.0.35 compares:

### Utility tree
Learned one-step normalized solver utility.

### Frozen reference-label MLP
The immutable v0.0.34 checkpoint.

### Target-leaf
The strongest final-solver-work heuristic in v0.0.34.

### Markowitz-style
The strongest retained-dimension / strong solver heuristic in v0.0.34.

### Sparsity + incidence
The earlier simple structural baseline.

### Oracle one-step utility diagnostic
Scores each candidate by its true U(c).

This oracle diagnostic is not deployable because it solves candidate reductions during scoring. It is reported only to bound the quality of the one-step utility objective.

## Stopping / threshold calibration

No policy receives oracle k or n-k.

Each deployable policy chooses one threshold on the utility calibration split.

Threshold grid:

    {0.00, 0.05, 0.10, 0.15, 0.20,
     0.25, 0.30, 0.35, 0.40, 0.45,
     0.50, 0.55, 0.60, 0.65, 0.70,
     0.75, 0.80, 0.85, 0.90, 0.95}

Selection objective:

    maximize mean certified final solver savings
    on the calibration split

Tie-breaks:

1. fewer mean proposals,
2. higher threshold,
3. deterministic numeric ordering.

This deliberately optimizes the downstream solver objective rather than reference-rule F1.

The oracle one-step diagnostic uses the same threshold grid but remains clearly labeled oracle.

## Inference path

For each final problem:

    score candidates
        ↓
    threshold
        ↓
    deterministic checker
        ↓
    safe accepted subset
        ↓
    exact retained solve
        ↓
    reconstruction
        ↓
    verify ORIGINAL full problem

All learned and heuristic scores remain advisory.

## Utility metrics

### Final solver utility

Report:

- baseline full-system solver ops,
- compressed final solver ops,
- solver savings,
- percent solver savings,
- accepted elimination count.

### Generator-reference diagnostics

Retain only as secondary diagnostics:

- reference-rule precision / recall / F1,
- accepted reference vs non-reference valid reductions,
- generator-reference retained-dimension error.

These are no longer the primary optimization objective.

### One-step utility prediction quality

For the utility tree:

- candidate-level MAE,
- RMSE,
- rank correlation where defined,
- tree node count,
- tree depth,
- feature importances.

### Oracle one-step ranking gap

Compare utility-tree final solver savings against the oracle one-step utility ranking diagnostic.

This measures how much downstream value is lost from utility prediction error plus greedy interaction effects.

## Checker-cost visibility

The deterministic checker is not free.

For each policy report:

- proposal count,
- conflict-only rejection count where observable,
- materialization trial count,
- fail-closed rejection count,
- successful tentative-check solver ops,
- successful tentative-check reconstruction ops,
- successful tentative-check verification ops.

Important boundary:

Failed tentative materializations may terminate before producing a complete operation vector.

Therefore the measured checker arithmetic is a **lower bound** on checker arithmetic, not exact total checker compute.

Do not claim end-to-end total-compute superiority from v0.0.35.

## Deterministic execution-cost view

Report separately:

1. candidate-scoring cost/proxy,
2. checker lower-bound arithmetic,
3. final retained solver arithmetic,
4. final reconstruction arithmetic,
5. final original-problem verification arithmetic.

Do not combine learned tree operations, MLP weighted-sum proxy, and exact rational arithmetic into one synthetic universal compute number.

A separate descriptive deterministic subtotal may be reported only for arithmetic counters sharing the exact-rational operation contract, with limitations stated.

## Safety contract

Every executed final reduction must satisfy:

- exact row algebra,
- unique row / target use,
- acyclic reconstruction,
- square retained subsystem,
- exact retained solve,
- exact reconstruction,
- verification on original full problem.

Required:

    verified retention = 1.0
    unsafe accepted reductions = 0

for every release comparison policy.

## KEEP contract

KEEP means the experiment is methodologically valid.

Required:

1. train / calibration / final signatures are mutually disjoint,
2. all are disjoint from v0.0.33 and v0.0.34 corpora,
3. utility labels are computed only from exact certified one-candidate reductions,
4. final examples are not used for tree fitting or threshold calibration,
5. no policy receives k or n-k at final inference,
6. tree hyperparameters and 16-feature contract match this pre-registration,
7. threshold objective is downstream solver savings rather than reference F1,
8. original-problem verified retention is 1.0 for all release policies,
9. unsafe accepted reductions are zero,
10. all scale cells are populated,
11. utility-tree fitted structure is deterministic across repeated fit,
12. negative results are retained.

Not required:

- utility tree beats target-leaf,
- utility tree beats Markowitz,
- utility tree beats frozen reference MLP,
- one-step utility is globally optimal,
- end-to-end total deterministic work improves.

## Claim boundary

A positive result can support only:

> On this generated affine-linear family, predicting one-step certified solver utility can improve downstream compression policy quality relative to the tested baselines.

It does not establish:

- globally optimal compression,
- optimal multi-step planning,
- domain-general Structural Compression,
- natural-language compression,
- end-to-end total-compute superiority,
- asymptotic complexity improvement.

## Next decision

If utility-directed ranking improves final solver savings:

    advance toward state-dependent / sequential utility prediction.

If deterministic heuristics remain superior:

    absorb the strongest heuristic as the default policy
    and use learning only where it adds measurable marginal value.

If checker lower-bound arithmetic dominates the saved solver work:

    the next milestone should prioritize cheap compression certificates
    and checker algorithms before improving the learned policy.
