# v0.0.35 — Utility-Directed Structural Compression

Status: pre-registered research specification

## Motivation

v0.0.34 falsified an important implicit assumption.

The frozen learned scorer produced the best generator-reference rule F1:

    learned reference F1 = 92.63%

but deterministic structural heuristics produced better verified downstream solver reduction:

    learned mean solver ops     = 442.23
    Markowitz mean solver ops   = 387.31
    target-leaf mean solver ops = 325.13

Therefore:

> **Better reference-certificate imitation does not imply better Structural Compression.**

v0.0.35 changes the optimization target from:

    Is this candidate part of the generator reference certificate?

to:

    If this candidate is accepted safely,
    how much downstream solver work disappears?

The target is **Compression Utility / Value-of-Reduction**.

## Central research question

> Does direct supervision on certified marginal solver utility produce a better verified compression policy than matched reference-label supervision and deterministic structural heuristics?

## Cost boundary

The primary learned target in v0.0.35 is **solver arithmetic reduction only**.

For one candidate c on full problem P:

    U_solver(c | P)
      = max(
          0,
          C_solver(P)
          - C_solver(P reduced by c)
        )

Normalized training target:

    u(c | P)
      = U_solver(c | P) / C_solver(P)

If the one-candidate reduction cannot be certified and verified:

    u(c | P) = 0

This target is deliberately narrow.

v0.0.35 separately reports:

- checker activity,
- reconstruction operations,
- original-problem verification operations,
- proposal counts.

It does **not** collapse these unlike operation categories into a synthetic total-compute score.

No total-compute superiority claim is allowed.

## Matched learned comparison

Two new learned models are trained on the **same v0.0.35 training examples** and the same candidate feature vectors.

### Model A — Reference classifier

Target:

    y_ref = 1
    iff candidate key is in the generator dependency reference

Architecture:

    16 features
      -> 16 tanh hidden units
      -> 1 binary logistic output

### Model B — Utility regressor

Target:

    y_utility = normalized certified one-step solver savings

Architecture:

    16 features
      -> 16 tanh hidden units
      -> 1 linear output

Inference score is clipped to:

    [0, 1]

Both models use:

- identical 16-feature candidate contract from v0.0.33/v0.0.34,
- hidden width 16,
- one hidden layer,
- L-BFGS training,
- alpha 1e-3,
- max_iter 1200,
- random_state 35,
- fitted weight+bias scalar count 289,
- StandardScaler fitted on the same X.

This gives a matched-capacity objective comparison.

## Training-only checkpoint freeze

v0.0.34 exposed cross-run sklearn refit drift.

v0.0.35 therefore freezes both learned models **before any v0.0.35 calibration/final evaluation**.

Checkpoint selection rule is fixed now:

> The canonical reference and utility checkpoints are the exact states emitted by the **first successful v0.0.35 training-only checkpoint-export job** after this pre-registration and training-contract implementation are committed.

The export job:

- reads v0.0.35 training examples only,
- computes candidate features and training labels only,
- does not import v0.0.35 calibration examples,
- does not import v0.0.35 final examples,
- emits exact float64 model/scaler states and SHA-256 fingerprints.

Checkpoint selection is chronological/mechanical, not based on downstream performance.

After checkpoint commit:

- final benchmark must never refit either model,
- scalar deterministic inference is used,
- checkpoint fingerprints are part of experiment identity.

## One-step utility oracle

For every training candidate:

1. solve the full system and record solver arithmetic operations,
2. attempt the candidate alone through deterministic reduction materialization,
3. if invalid/unverifiable: utility = 0,
4. if valid: utility = normalized solver arithmetic reduction.

This is an oracle training label.

It is not available at final inference.

The oracle uses the same exact rational solver and deterministic checker authority.

## Stopping calibration

No method receives oracle k or n-k at final inference.

All methods select one global threshold on the v0.0.35 calibration split.

Threshold grid:

    tau in {
        0.00, 0.05, 0.10, ... , 0.95
    }

For each threshold:

1. score all candidates,
2. keep candidates with score >= tau,
3. process in descending score order through the deterministic checker,
4. compute mean certified solver savings on calibration examples.

Selection objective:

    maximize mean certified solver savings

Tie-breaks:

1. fewer total proposed candidates,
2. higher threshold,
3. deterministic numeric ordering.

This directly calibrates against downstream solver utility rather than generator-reference F1.

Calibration final-data separation is strict.

## Final policy

For every final example:

    score candidates
      -> threshold by calibrated tau
      -> deterministic checker in score order
      -> accepted certified subset
      -> exact retained solve
      -> reconstruction
      -> verify ORIGINAL full problem

No final learned or deterministic method receives:

- k,
- n-k,
- generator reference labels,
- oracle one-step utility labels.

## Primary metrics

For every deployable method:

### Verified safety
- verified retention
- unsafe accepted reductions
- fail-closed rejected proposals

### Compression outcome
- mean accepted eliminations
- mean retained solver ops
- mean solver savings vs full baseline
- mean generator-reference solver-savings recovery
- per-cell solver ops

### Stopping
- mean inferred retained dimension
- retained-dimension MAE vs generator k
- exact generator-k match rate

### Search / evidence overhead
- mean proposed candidates
- mean rejected proposals
- reconstruction operation count
- original-problem verification operation count

These remain separate from solver arithmetic.

### Reference diagnostics
Still report:
- proposal precision
- recall
- F1 against generator reference

but reference F1 is no longer an optimization objective.

### Utility-model diagnostics
Report:
- candidate utility MAE
- utility mean-squared error
- score / true one-step utility correlation

These are diagnostics, not the final decision objective.

## KEEP contract

KEEP validates methodology and safety.

Required:

1. all v0.0.35 splits disjoint from all v0.0.33/v0.0.34 splits,
2. v0.0.35 train/calibration/final mutually disjoint,
3. training-only checkpoint export does not read calibration/final,
4. matched reference and utility models have equal feature dimension and fitted parameter count,
5. checkpoints are frozen before final benchmark wiring,
6. final benchmark never refits learned models,
7. calibration uses only v0.0.35 calibration data,
8. no final deployable method receives k, n-k, reference labels, or oracle utility labels,
9. deterministic checker remains authoritative,
10. original full problem is verified,
11. verified retention is reported for every method,
12. unsafe accepted reduction count is zero for every method,
13. all final scale cells populated,
14. final aggregate is reproducible across independent CI runners.

Not required:

- utility model beats reference model,
- utility model beats deterministic heuristics,
- reference F1 improves,
- retained dimension equals generator k,
- any total-compute win.

## Claim boundary

A positive result could support only:

> In this generated affine-linear family, matched small-model supervision on certified one-step solver utility can produce a more useful verified compression policy than matched supervision on generator reference labels.

It would not establish:

- globally optimal compression,
- globally optimal utility,
- domain-general Structural Compression,
- natural-language utility discovery,
- end-to-end total-compute superiority,
- asymptotic complexity improvement.

## Decision rule after v0.0.35

If utility supervision beats matched reference supervision but not deterministic heuristics:

    absorb the deterministic utility heuristics
    and keep learning only where residual value remains.

If utility supervision beats both matched reference and deterministic baselines:

    proceed to dynamic / state-dependent marginal utility.

If deterministic heuristics remain strongest:

    promote them into the core architecture
    and shift learning toward residual prediction,
    family routing,
    or harder structural domains.

NEUMANN optimizes verified computation, not the prestige of learned components.
