# v0.0.101 — Frozen quotient size-adaptive support preregistration

## Purpose

v0.0.100 cleanly separates surface invariance from size generalization.

The quotient representation is exactly top2m-support invariant on all 16/16
base/surface development pairs for both seeds, yet each m128 cell still has one
restricted-support miss out of eight and falls below the frozen Q34
utility-recovery floor. Discovery remains cheap.

v0.0.101 therefore does **not** fit another model and does not alter the
representation. It asks one final systems question for this point-support
family:

> Can the already-frozen quotient ranking recover the rare m128 misses
> economically by expanding support only after original-problem verification
> rejects the 2m restricted solve?

If not, stop this quotient point-support family rather than continue local
support-width tuning.

## Routes

For each frozen seed:

- `FIXED2_sSEED`: quotient features -> frozen ranking -> top2m restricted
  native solve -> original-LP verification -> charged full Direct fallback.
- `ADAPT24_sSEED`: quotient features -> same frozen ranking -> top2m
  restricted solve -> original verification -> **only if rejected**, top4m
  restricted solve -> original verification -> **only if rejected**, charged
  full Direct fallback.

References:

- `DIRECT`: full native solve + original verification.
- `ORACLE`: exact certified reference basis supplied free to the restricted
  executor + original verification.

No hidden basis or label may enter candidate proposal or expansion decisions.

## Adaptive promotion gate

The adaptive contract is admitted to a **new future fresh Q34 holdout** only if,
for both seeds, all are true on these 16 new m128 development cases:

1. ADAPT24 passes the Q34 conjunction;
2. ADAPT24 uses full Direct fallback on **zero** cases;
3. ADAPT24 has strictly fewer full-Direct fallback cases than FIXED2;
4. ADAPT24 amortized complete/Direct is strictly lower than FIXED2.

PASS:

`ADMIT_NEW_FRESH_Q34_HOLDOUT_FOR_ADAPTIVE_QUOTIENT`

FAIL:

`STOP_QUOTIENT_POINT_SUPPORT_FAMILY`

No threshold rescue, second screen, new fit, or v0.0.98 reuse is allowed after
the first result.

Passing this development screen still does not advance Q5. It only authorizes a
new separately registered holdout with new seeds. Failing it ends local
quotient point-support work and moves one level up in structural authority /
representation / task design.
