# v0.0.101 — Final training-free adaptive support gate

## Purpose

v0.0.100 fixed the known equivalence defect but each frozen quotient model
missed one top2m restricted support among eight m128 development cases, leaving
utility just below the 0.80 Q34 floor. v0.0.101 asks the final local-family
question without training:

Does the already-frozen quotient ranking contain the missed structure inside
top4m, so that verifier-triggered expansion can recover it economically?

This is the final development gate permitted by the Q3/Q4 closure rule.

## Frozen model authority

Load only the retained v0.0.100 first-result archive:
docs/experiments/results/v100_first_refit.manifest.json

Restore exactly QUOTIENT_s100001 and QUOTIENT_s100002.

No fitting, optimizer step, checkpoint selection, threshold change, feature
change, or model parameter change is permitted. The sealed v0.0.98 holdout
must not be loaded.

## New development set

Generate 16 new base problems after this protocol is frozen:

- seeds 100300..100315;
- first eight: m=64, n=1024;
- next eight: m=128, n=2048;
- alternating condition number 1 / 1000;
- width factor 16.

For each base create one mathematically equivalent surface view using the same
signed-row-permutation + positive-column-scaling transformation class, with
surface seed base_seed + 300000.

Four cells, eight views each:
m64_base, m64_surface, m128_base, m128_surface.

This is opened development, not a fresh holdout.

## Routes

DIRECT, ORACLE,
STATIC_s100001, STATIC_s100002,
ADAPTIVE_s100001, ADAPTIVE_s100002.

All learned routes compute the same frozen quotient features, frozen point MLP,
and one full column ranking.

STATIC:
top2m -> restricted solve -> original verifier -> charged Direct fallback.

ADAPTIVE:
top2m -> if verifier rejects, top4m -> original verifier -> charged Direct fallback.

The verifier outcome alone controls expansion. Hidden labels and Oracle support
cannot enter candidate inference or expansion.

## Runtime and accounting

Use the exact v0.0.100 retained runtime:
Python 3.12, NumPy 2.3.5, SciPy 1.17.0, scikit-learn 1.9.1,
torch 2.14.0+cpu, highspy 1.15.1, OpenBLAS HASWELL, threads=1.

For every case/route:
one warmup, three retained timed repetitions, fixed shuffled order 101991+repeat,
5 second complete-path budget, proposal timer before quotient feature construction,
post timer charging all restricted solves, original verification and Direct fallback.
Learned investment remains the retained v0.0.100
(feature_setup_ms + fit_ms) / 10000 per query.

No new training cost is created in v0.0.101.

## Q34 gate

Use unchanged thresholds:
all retained answers verify; positive Oracle and candidate savings;
utility recovery >=0.80; discovery burden <=0.20; amortized complete/Direct <1.00.

Each model seed must pass every cell and all 32 views combined.

## Frozen promotion rule

1. If STATIC passes every cell for both seeds, select STATIC as the simpler survivor.
2. Otherwise, if ADAPTIVE passes every cell for both seeds and for each seed
   recovers at least one m128 restricted-support miss that STATIC sends to full
   Direct fallback, select ADAPTIVE.
3. Otherwise close the current LP point-support line as rejected.

Possible decisions:
ADMIT_FINAL_FRESH_Q34_HOLDOUT_STATIC
ADMIT_FINAL_FRESH_Q34_HOLDOUT_ADAPTIVE
CLOSE_Q3_Q4_CURRENT_LP_FORMULATION_REJECTED

This version cannot itself declare Q3/Q4 PASS because it is development data.
