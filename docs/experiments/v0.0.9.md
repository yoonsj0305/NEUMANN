# v0.0.9 — First multi-family complete-IR routing

## Question

Can NEUMANN compile raw text into complete solver-ready IRs for two different structural families and route each to the correct deterministic solver without an oracle payload?

## Families

1. controlled bipartite matching
2. controlled square linear systems

## New components

- controlled linear-expression parser using Python AST without eval
- linear equation → matrix A, vector b, variable-order IR compiler
- benchmark-side linear semantic verifier
- CompositeStructureFormer:
  - zero recognized families → UNKNOWN
  - exactly one recognized family → accept
  - multiple recognized families → UNKNOWN rather than guessing

## Safety rules

The linear compiler fails closed on:
- nonlinear multiplication such as x*y
- inequalities
- malformed equalities
- fewer than two equations
- non-square systems in this version

## Why this matters

v0.0.7/v0.0.8 proved one complete IR path. v0.0.9 tests whether the architecture can expand horizontally across solver families while preserving fail-closed behavior.

The research object is no longer only "can one parser work?" but:

> Can representation formation become a family-neutral routing layer?

## Boundary

This is still controlled syntax. It is not arbitrary natural-language algebra understanding or general solver selection.
