# v0.0.82 — Oracle-basis complete-cost headroom protocol

Status: **protocol freeze before formal implementation/timing**.

This is a constructed, non-blind development screen. Before this protocol was
written, exploratory local timings on a related planted-basis LP generator
already suggested large oracle-vs-HiGHS separation. Therefore this version
cannot be cited as independent discovery, representative workload evidence, or
a Q3/Q4 result. Its purpose is narrower: determine whether the certificate
interface from v0.0.81 leaves enough complete-path headroom to justify a later
basis-discovery experiment at all.

## Question

If the optimal LP basis is supplied for free to a non-deployable diagnostic
oracle, can

```
basis solve
+ full primal/dual reconstruction
+ original-LP certificate verification
```

cost at least 20% less than the strongest measured complete Direct route on the
same constructed instances?

If not, do not train a basis/active-set predictor on this family.

A positive result establishes only **mechanism headroom**. It does not show
that a basis can be discovered cheaply, that learning is required, or that
NEUMANN beats a matched Direct learner.

## Original task

Every case is the standard-form LP

```
minimize      c^T x
subject to    A x = b
              x >= 0
```

and is verified only by
`neumann1.lp_certificate_v081.verify_standard_form_certificate`.

No route may replace the original verifier with a reduced-problem check, gold
answer lookup, generator assertion, or solver status.

## Constructed generator

Twelve frozen cells:

| rows m | column ratio n/m |
| ---: | ---: |
| 16 | 4, 16, 64 |
| 32 | 4, 16, 64 |
| 64 | 4, 16, 64 |
| 128 | 4, 16, 64 |

Thus `n = m * ratio`, ranging from 64 to 8192 columns.

One fresh deterministic case per cell. Case seeds are `8201..8212` in the
table order above. None of these seeds was used in the pre-protocol exploratory
timing.

For each case:

1. draw an `m x m` Gaussian matrix and take its QR `Q`;
2. use `Q` as the planted basis columns;
3. draw the remaining columns iid Gaussian scaled by `1/sqrt(m)`;
4. uniformly permute all columns;
5. draw strictly positive basic values in `[0.5, 1.5]` and set `b = A x`;
6. draw dual vector `y ~ N(0, I)`;
7. set reduced-cost slack to exactly zero on planted basis columns and
   `Uniform[0.25, 2.0]` elsewhere;
8. set `c = A^T y + slack`.

This makes the planted basis a valid nondegenerate optimal certificate by
construction. The basis permutation is available only to the diagnostic oracle,
not to any Direct route or future learned route.

The generator is deliberately artificial. Passing it cannot establish natural
LP incidence or general optimization advantage.

## Comparator routes

All routes receive the identical `A, b, c`.

### Direct-auto
SciPy `linprog(..., method="highs")`.

### Direct-dual-simplex
SciPy `linprog(..., method="highs-ds")`.

### Direct-IPM
SciPy `linprog(..., method="highs-ipm")`.

Each Direct route must obtain a candidate primal vector and equality dual
marginals from its own solve, then pay the full v0.0.81 original-LP verifier.

### Oracle-basis
The route receives the planted optimal basis indices for free. The free basis
lookup is intentionally **not deployable** and is not counted as a model result.

It must still perform:

1. `A_B x_B = b`;
2. `A_B^T y = c_B`;
3. full `n`-vector primal reconstruction with zero nonbasic variables;
4. full original-LP v0.0.81 certificate verification.

No cached `x`, `y`, objective, reduced cost, answer, HiGHS output, or
factorization may be reused from generation or another route.

## Cost and timing

Setup/generation is recorded separately and excluded from warm per-query
comparison because the same already-materialized LP is supplied to all routes.
It must not later be called free if a deployment requires regeneration or data
loading.

Per timed call, charge wall-clock for:

- route-specific solve/basis linear algebra;
- primal/dual extraction or reconstruction;
- original-LP certificate verification;
- any failed attempt or exception.

One untimed correctness warmup per route/case is preserved separately.

Then run three timed repetitions per route/case in a deterministic shuffled
serial schedule. Threaded numerical libraries are limited to one thread.

Expected formal archive size:

- 12 cases;
- 4 routes;
- 3 timed repetitions;
- **144 timed observations**;
- 48 correctness warmups.

Any solver error, non-finite output, malformed certificate, verifier rejection,
or timeout is `CAPABILITY_UNREACHED` for that observation. It is never
speedup evidence.

## Frozen decision rule

For every case, compute the median complete time of each route.

Define the conservative Direct comparator as the **post-measurement fastest
Direct route per case** among auto, dual simplex and IPM. This is itself
non-deployable oracle selection and therefore makes the admission test harder,
not easier.

Let

```
ratio_i =
    median_complete_time(Oracle-basis, case_i)
    /
    min_j median_complete_time(Direct_j, case_i)
```

Advance only if:

1. all 144 timed observations and all 48 warmups pass the original-LP
   certificate;
2. geometric mean of the 12 `ratio_i` values is `<= 0.80`;
3. at least 8 of 12 cases individually have `ratio_i <= 0.80`.

Otherwise freeze

`REJECT_BASIS_DISCOVERY_TRAINING_ON_V082_FAMILY`.

If all capability checks pass and both cost gates pass, freeze

`CONSTRUCTED_ORACLE_BASIS_HEADROOM_PRESENT`.

That decision still leaves Q3 and Q4 **OPEN**.

## Required archive

The first formal audit must preserve:

- exact generator parameters and source hashes;
- Python, NumPy, SciPy and HiGHS versions;
- platform identifier;
- every warmup and timed record;
- route identity and solver status;
- certificate metrics from v0.0.81;
- setup time;
- per-case medians and ratios;
- the final decision.

The first archive is immutable. CI may validate it but must not rerun the full
timing audit merely to obtain a better result.

## Prior-art boundary

Learning an LP basis is already established work, including:

- Fan et al., *Smart Initial Basis Selection for Linear Programs*, ICML 2023:
  https://proceedings.mlr.press/v202/fan23d.html
- Lu and Yan, *Learning Initial Basis Selection for Linear Programming via
  Duality-Inspired Tripartite Graph Representation and Comprehensive
  Supervision*, ICML 2025:
  https://proceedings.mlr.press/v267/lu25q.html

Therefore a positive v0.0.82 cannot motivate a novelty claim around basis
prediction itself. If the oracle gate passes, the next experiment must compare
cheap deterministic discovery, strong published-style learned basis selection,
a matched Direct executable learner, NEUMANN/no-compression ablation, and
complete certificate-paid costs before any Q3/Q4 claim.
