# v0.0.37 — Smallest Adequate State-Aware Residual Predictor

Status: pre-registered research specification

## Motivation

v0.0.36 established that a cheap-first residual architecture has substantial
headroom on the generated exact affine-linear family:

    target-leaf @ 0.10
        -> deterministic checker
        -> residual marginal-utility search
        -> exact execution
        -> original-problem verification

The exact residual teacher reduced mean retained-system solver work far below
both target-leaf alone and empty-start greedy utility, while requiring far fewer
teacher trials.

The next question is narrower:

> Can a very small state-aware predictor recover enough residual utility to
> justify replacing expensive exact residual search?

This experiment does not assume that a neural model is necessary.

## Fixed first stage

The first stage is frozen from v0.0.35-v0.0.36:

    method = target_leaf
    threshold = 0.10

No recalibration is allowed.

The deterministic checker remains authoritative.

## Prediction target

The learned target is not generator dependency identity and not teacher
candidate identity.

For feasible candidate c in current certified reduction state R:

    normalized_marginal_gain(c | R)
        = clip(
            [C_solver(R) - C_solver(R union {c})]
            / max(1, C_solver(R)),
            -1,
            +1
          )

Invalid tentative reductions receive target:

    -1.0

Thus the model learns downstream computational utility directly.

## Teacher trajectory

For each training system:

1. run frozen target-leaf @ 0.10,
2. begin from the actually certified accepted set,
3. enumerate all non-conflicting residual candidates,
4. exactly materialize each tentative candidate,
5. record state-aware features and normalized marginal gain,
6. select the largest positive exact gain,
7. update the certified state,
8. repeat until no positive exact gain remains.

Teacher tie-breaking is deterministic by row index then target index.

The teacher is a data generator and diagnostic upper reference only.

## State-aware feature contract

The predictor may use only information available from:

- the original exact system,
- the current certified reduction state,
- the current retained-system solver-work count,
- the candidate itself.

It may not use:

- generator k,
- n-k,
- oracle dependency identities,
- future teacher choices,
- final answer labels.

Feature vector:

1. the frozen 16 v0.0.33 candidate structural features,
2. accepted-reduction fraction,
3. current solver-work / full-system solver-work,
4. current feasible-candidate fraction,
5. fraction of candidate dependencies already eliminated,
6. fraction of accepted rules that depend on candidate target,
7. binary indicator that candidate target is used by any accepted rule.

Total feature dimension:

    22

## Model ladder

Exactly two learned candidates are pre-registered.

### L0 — Ridge residual regressor

    standardized 22 features
        -> linear Ridge regressor
        -> scalar predicted normalized marginal gain

Purpose: test whether state-aware utility is almost linear.

### L1 — Tiny residual MLP

    standardized 22 features
        -> tanh hidden layer, 8 units
        -> scalar predicted normalized marginal gain

Approximate fitted weight+bias scalar count:

    22*8 + 8 + 8*1 + 1 = 193

The exact footprint is reported after fitting.

No larger model is allowed in v0.0.37.

## Inference policy

At each residual state:

1. enumerate candidates not conflicting with already accepted reductions,
2. compute state-aware features,
3. score all currently eligible candidates,
4. choose the highest predicted gain above threshold tau,
5. send only that proposal to the deterministic checker/materializer,
6. if accepted, update state and rescore,
7. if rejected, suppress that candidate for the unchanged state and try the
   next highest score,
8. after a state change, rejected candidates may be reconsidered,
9. stop when no unsuppressed score exceeds tau.

Every final answer is reconstructed and verified against the original system.

## Cheap residual baselines

The learned policy must compete against residual versions of:

- target-leaf,
- Markowitz,
- dependency contrast,
- structural combo.

Each baseline begins after the same frozen target-leaf first stage.

Baseline scores use no learned parameters.

Thresholds are selected only on the validation split.

## Data split

Use the same affine-linear generator family and scale grid:

    k in {2, 4}
    n in {4, 8, 16, 32}
    n >= k

Per cell:

    train      = 12 systems
    validation = 8 systems
    final      = 24 systems

Totals:

    train      = 96
    validation = 64
    final      = 192

All signatures must be disjoint from every v0.0.33-v0.0.36 dataset and mutually
disjoint across v0.0.37 splits.

## Threshold calibration

Threshold grid for learned regressors:

    {-0.05, 0.00, 0.01, 0.02, 0.05, 0.10, 0.20}

Threshold grid for deterministic residual scorers:

    {0.05, 0.10, ..., 0.95}

For each method, choose the threshold that maximizes mean verified residual
additional solver savings on validation.

Tie-breaks:

1. lower final retained-system solver ops,
2. fewer attempted proposals,
3. higher threshold.

Final data may not affect threshold selection.

## Smallest-adequate model selection

On validation, define:

    teacher_residual_value
        = mean(target_leaf_ops - exact_residual_teacher_ops)

    method_recovery
        = mean(target_leaf_ops - method_ops)
          / teacher_residual_value

if teacher_residual_value > 0.

Select the smallest learned model satisfying:

    validation recovery >= 0.70

and within 0.05 absolute recovery of the best learned candidate.

Selection order by size:

    L0 Ridge
    L1 Tiny MLP

If neither reaches 0.70, select the better validation model for diagnostic final
evaluation but mark:

    validation_model_status = INADEQUATE

The selection rule is frozen before final evaluation.

## Final primary comparisons

On untouched final systems compare:

1. no residual policy,
2. best validation-selected deterministic residual baseline,
3. selected learned residual predictor,
4. exact state-aware residual teacher.

Primary metrics:

- verified retention,
- unsafe accepted reductions,
- mean residual additional solver savings,
- mean final retained-system solver ops,
- residual teacher savings recovery,
- mean attempted proposals,
- mean accepted residual reductions,
- candidate scores computed,
- fitted model parameter/footprint counts.

Teacher-search work remains separate from deployable-policy work.

## Learned-value decision rule

Let:

    learned_recovery
        = learned additional savings
          / teacher additional savings

and:

    learned_advantage_fraction
        = (learned additional savings
           - best deterministic additional savings)
          / teacher additional savings

Pre-registered decision:

### KEEP_LEARNED_RESIDUAL

Required:

    learned_recovery >= 0.70
    learned_advantage_fraction >= 0.10
    verified retention = 1.0
    unsafe accepted reductions = 0

### KEEP_DETERMINISTIC_RESIDUAL

If a deterministic residual baseline reaches recovery >= 0.70 and the learned
policy fails the learned-value rule, prefer the deterministic residual policy.

### HOLD_RESIDUAL_MODELING

If neither learned nor deterministic residual policies reach 0.70 recovery,
retain the exact teacher as diagnostic evidence only and redesign features or
the structural family before increasing model size.

No larger neural model may be introduced as a post-result rescue inside
v0.0.37.

## KEEP contract

KEEP means the experiment is methodologically valid, regardless of which policy
wins.

Required:

1. all v0.0.37 splits are disjoint from v0.0.33-v0.0.36 and from one another,
2. target-leaf first-stage threshold remains exactly 0.10,
3. final inference receives neither k nor n-k,
4. learned training targets come only from exact teacher marginal utility,
5. model choice and thresholds are frozen on train/validation before final,
6. no final result changes model size, features, threshold grid, or selection
   logic,
7. deterministic checker remains authoritative,
8. original-problem verified retention is 1.0 for every reported deployable
   method,
9. unsafe accepted reduction count is zero,
10. all final scale cells contain exactly 24 systems,
11. teacher-search costs and deployable scorer costs are reported separately.

## Claim boundary

A positive result would support only:

> on this generated exact affine-linear family, a very small state-aware
> predictor can recover a pre-registered fraction of residual solver-work value
> after cheap certified structural compression.

It would not establish:

- natural-language Structural Compression,
- domain generality,
- total-compute superiority,
- globally minimal structure,
- asymptotic complexity improvement,
- superiority to all sparse elimination algorithms.

## Next milestone

If KEEP_LEARNED_RESIDUAL:

    v0.0.38 = harder-family generalization and out-of-family residual transfer

If KEEP_DETERMINISTIC_RESIDUAL:

    freeze the deterministic residual policy and move to a harder family

If HOLD_RESIDUAL_MODELING:

    analyze residual state representation before adding capacity

## Central interpretation

The tiny MLP learned substantial state-aware residual utility.

It recovered about **95.70%** of the exact greedy teacher's final residual
savings.

That is not enough to justify keeping the learned mechanism because the
validation-selected deterministic Markowitz residual recovered about
**104.47%** of the teacher value and reached lower final retained-system solver
work.

The exact teacher is greedy, not globally optimal.

Therefore deterministic recovery above 100% is another path-dependence result,
not a violation of the benchmark.

The currently justified architecture on this family is:

    target-leaf @ 0.10
        ↓
    deterministic checker
        ↓
    Markowitz residual @ 0.05
        ↓
    deterministic checker
        ↓
    exact retained solve
        ↓
    reconstruction
        ↓
    verify ORIGINAL problem

The learned residual branch is rejected for this family.

## First-principles consequence

v0.0.37 answers a stronger question than whether a tiny network can imitate
residual utility.

It can.

But the relevant engineering question is whether learned complexity creates
value beyond a cheaper mechanism.

On this family, it does not.

Therefore increasing model capacity would violate the project sequence:

    question requirements
        -> delete
        -> simplify
        -> accelerate
        -> automate

The correct action is to delete the learned residual component rather than
scale it.

## Benchmark saturation warning

The repeated success of target-leaf, Markowitz, dependency-contrast, and
structural-combo indicates that the current generated affine-linear family is
becoming saturated by local structural heuristics.

Continuing to tune learned models on the same family would risk benchmark
overfitting and would provide weak evidence for general Structural Compression.

The next research step should therefore harden the structural family itself.

## Next milestone

Preferred v0.0.38 direction:

    Harder Structural Family Gate

The next family should introduce valid compressions that cannot be recovered
reliably from a single local leaf/incidence statistic.

Candidate motifs include:

- coupled multi-row / block dependencies,
- redundant constraints that require relation-level reasoning,
- equivalence or symmetry classes,
- adversarial local-incidence decoys,
- mixtures of easy leaf compression and non-local compression.

The deterministic target-leaf + Markowitz pipeline remains the mandatory cheap
baseline.

A learned component may return only if it produces pre-registered downstream
value beyond deterministic structural algorithms on an untouched harder
family.

## Important negative result

The tiny MLP is not weak.

It recovered approximately **95.70%** of the exact greedy teacher's residual
value with only **193 fitted weight+bias scalars** and an average of about
**2.49 attempted proposals** per final system.

Nevertheless it is unnecessary on this benchmark family because a cheaper
deterministic residual rule performs better.

This is exactly the deletion condition the experiment was designed to detect.

## Greedy teacher is not an upper bound

The selected Markowitz residual recovered more than 100% of the exact greedy
teacher's residual savings.

Descriptively, two other deterministic methods also exceeded the greedy teacher
on the untouched final set:

    dependency contrast recovery = 105.38%
    structural combo recovery    = 105.38%
    target-leaf residual recovery = 103.61%

These methods are **not** substituted for the frozen primary Markowitz choice
after observing final results.

The result instead corrects the interpretation of the teacher.

The exact teacher computes exact immediate marginal gain at every step, but it
is only a **one-step greedy trajectory**.

It is not:

- a global optimum,
- an upper bound on achievable residual compression,
- proof of minimal retained structure.

The fact that several cheap structural orderings reach better final states is
another path-dependence result.

## Research consequence

Do not increase model capacity on this family.

The current family is now too friendly to local sparse-elimination heuristics
to justify further neural optimization.

The next experiment should move to a harder Structural Compression family where
cheap local ordering is not expected to capture almost all value.

Candidate challenge classes include:

- coupled affine blocks with nonlocal elimination interactions,
- equivalent-state / symmetry compression,
- redundant-constraint elimination with long-range dependencies,
- mixed structural families requiring a routing decision.

The next experiment must preserve Markowitz and other cheap structural methods
as first-class baselines.

## Claim boundary

v0.0.37 supports only:

> on this generated exact affine-linear family, a 193-parameter state-aware MLP
> can recover most greedy residual utility, but a pre-registered deterministic
> Markowitz residual policy is cheaper and achieves better verified downstream
> solver work.

It does not show that learned residual prediction is unnecessary in harder
domains.

It does show that **learned capacity should not be added where a cheaper
structural rule already wins**.
