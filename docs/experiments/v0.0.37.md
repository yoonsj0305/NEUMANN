# v0.0.37 — State-Aware Residual Policy Gauntlet

Status: pre-registered research specification

## Motivation

v0.0.36 established that:

- frozen target-leaf @ 0.10 is a strong cheap first-stage compressor,
- state-aware residual utility remains after cheap compression,
- residual value is strongly scale- and state-dependent,
- cheap-first residual search can outperform empty-start greedy utility,
- teacher trial materializations can fall by nearly an order of magnitude after the cheap stage.

The next question is not whether a larger model can imitate the exact teacher sequence.

It is:

> Can a very small state-aware learned residual policy reduce verified downstream solver work beyond cheap deterministic residual policies?

## Frozen first stage

Every method begins with the same frozen cheap component:

    target-leaf @ threshold 0.10
        ↓
    deterministic checker
        ↓
    certified initial reduction set R0

The threshold is transferred unchanged from v0.0.35 and v0.0.36.

No method may recalibrate or bypass this first stage.

## Residual policy authority boundary

Residual policies only rank or stop proposals.

They do not receive execution authority.

Every proposed residual candidate must pass the deterministic reduction checker, followed by exact solve, reconstruction, and verification against the original full problem.

Required throughout:

    learned suggestion ≠ execution authority

## Data contract

Use the same leakage-hardened affine-linear generator family.

Scale grid:

    k in {2, 4}
    n in {4, 8, 16, 32}
    n >= k

New disjoint splits:

    train       = 64 examples per cell = 512
    calibration = 24 examples per cell = 192
    final       = 32 examples per cell = 256

Every v0.0.37 signature must be disjoint from every v0.0.33-v0.0.36 signature and from the other v0.0.37 splits.

Final data are untouched until model architecture, deterministic baselines, feature contract, calibration rules, and continuation criteria are frozen.

## Teacher trajectory

For train examples only:

1. run frozen target-leaf first stage,
2. begin from the certified accepted set R0,
3. enumerate feasible residual row/target candidates,
4. for each candidate c, materialize R union {c},
5. for valid materializations measure:

       relative_VoR(c | R)
           = (solver_ops(R) - solver_ops(R union {c}))
             / max(1, solver_ops(R))

6. record the state/candidate feature vector and relative_VoR,
7. choose the valid candidate with largest positive absolute solver-op gain,
8. tie-break deterministically by row index then target index,
9. repeat until no valid positive-gain candidate remains.

Invalid tentative materializations are not used as utility regression targets.

They remain under deterministic checker authority and are reported as fail-closed proposal cost at inference.

The teacher is greedy, not globally optimal.

Its final solver work is a diagnostic reference, not an upper bound.

## State-aware feature contract

The learned and deterministic residual methods may use only information derivable from:

- the original exact linear system,
- the current certified accepted reduction set,
- the current retained/materialized state,
- the residual candidate.

They may not use:

- generator core dimension k,
- n-k,
- oracle dependency labels,
- ground-truth solution values as features,
- final-set labels.

### Frozen feature vector

Base candidate features:

    the existing 16 v0.0.33 candidate features

State features:

1. retained_dimension / n
2. accepted_reduction_count / n
3. current_solver_ops / baseline_solver_ops
4. log1p(current_solver_ops) / log1p(max(1, baseline_solver_ops))
5. current target-column incidence / retained_dimension
6. current candidate-row retained nnz / retained_dimension
7. mean current dependency incidence / retained_dimension
8. max current dependency incidence / retained_dimension
9. min current dependency incidence / retained_dimension
10. (target incidence - dependency mean incidence) / retained_dimension
11. fraction of candidate dependencies currently retained
12. fraction of candidate dependencies already eliminated
13. target incidence reduction from original state / n
14. mean dependency incidence reduction from original state / n

Total feature dimension:

    30

All denominator guards are deterministic and frozen before final evaluation.

## Learned model family

Use deterministic scikit-learn DecisionTreeRegressor models only.

Candidate maximum depths:

    {2, 3, 4, 6}

Frozen settings:

    criterion = squared_error
    splitter = best
    min_samples_leaf = 16
    random_state = 37

Target:

    relative_VoR

No neural model is introduced in v0.0.37.

This is intentional.

If a shallow tree is adequate, adding a neural model is unnecessary complexity.

## Learned rollout

At final inference:

1. run frozen target-leaf,
2. enumerate non-conflicting residual candidates,
3. compute current state-aware features,
4. predict relative_VoR for every candidate,
5. rank descending,
6. among candidates with predicted value >= tau, try candidates in order through the deterministic checker/materializer,
7. accept the first valid candidate,
8. recompute the state and scores,
9. stop when no above-threshold candidate can be validly accepted.

The model is state-aware because scores are recomputed after every accepted residual reduction.

## Learned threshold grid

For each tree depth, calibrate one global predicted relative-utility threshold on the v0.0.37 calibration split:

    tau in {
        0.000,
        0.001,
        0.0025,
        0.005,
        0.010,
        0.020,
        0.050,
        0.100
    }

Calibration objective:

    maximize mean residual additional solver savings

Tie-breaks:

1. lower mean final solver ops,
2. fewer checker/materialization proposals,
3. higher threshold.

## Smallest-adequate model selection

For each depth, retain its best calibration threshold.

Let S_best be the highest mean calibration residual additional solver savings across depths.

A depth is calibration-adequate if:

    S_depth >= 0.95 * S_best

Select the adequate model with:

1. smallest maximum depth,
2. fewest fitted tree nodes,
3. fewer calibration checker proposals,
4. higher threshold.

This selection uses calibration data only.

The chosen tree and threshold are frozen before final evaluation.

## Deterministic residual baseline gauntlet

Every deterministic baseline is state-aware and recomputed after each accepted residual reduction.

Pre-registered methods:

### 1. Residual target-leaf

Prefer residual targets with lower incidence in the current retained state.

### 2. Residual Markowitz

Use current retained-row nnz and current target incidence:

    M = max(0, row_nnz - 1)
        * max(0, target_incidence - 1)

    score = 1 / (1 + M)

### 3. Residual dependency contrast

Prefer targets whose current incidence is below the mean current incidence of their dependencies.

### 4. Residual structural combo

Frozen weights:

    0.40 * residual_target_leaf
  + 0.35 * residual_markowitz
  + 0.25 * residual_dependency_contrast

No weights are tuned.

### 5. Deterministic pseudo-random control

Use a SHA-256-derived deterministic candidate/state score.

## Deterministic threshold calibration

All deterministic residual methods use:

    tau in {
        0.05, 0.10, 0.15, 0.20, 0.25,
        0.30, 0.35, 0.40, 0.45, 0.50,
        0.55, 0.60, 0.65, 0.70, 0.75,
        0.80, 0.85, 0.90, 0.95
    }

Calibration objective and tie-breaks are identical to the learned rollout:

1. maximize mean residual additional solver savings,
2. lower final solver ops,
3. fewer checker proposals,
4. higher threshold.

No final-set threshold tuning is permitted.

## Final comparators

Report on the untouched final set:

1. frozen target-leaf only,
2. each calibrated deterministic residual baseline,
3. selected learned residual tree,
4. exact residual greedy teacher.

All begin from the same frozen target-leaf state.

## Primary metrics

For every final method:

- verified retention
- unsafe accepted reduction count
- mean final solver ops
- mean total solver savings
- mean residual additional solver savings
- residual savings recovery relative to the exact residual greedy teacher
- positive residual gain rate
- mean residual accepted count
- mean checker/materialization proposal count
- fail-closed proposal count
- per-cell metrics

For the learned tree additionally report:

- feature dimension
- selected max depth
- fitted tree depth
- fitted node count
- fitted leaf count
- threshold
- candidate score evaluations
- decision-node comparison proxy

Do not merge tree comparisons, checker materializations, solver ops, or verification ops into one synthetic compute score.

## Interpretation of teacher recovery

Define:

    teacher_residual_gain
        = target_leaf_ops - exact_residual_teacher_ops

    method_residual_gain
        = target_leaf_ops - method_ops

Aggregate recovery:

    mean(method_residual_gain)
        / mean(teacher_residual_gain)

This may exceed 1 because greedy teacher trajectories are path-dependent and are not globally optimal.

## KEEP contract

KEEP means the experiment is methodologically valid.

Required:

1. v0.0.37 train/calibration/final are mutually disjoint,
2. all are disjoint from v0.0.33-v0.0.36,
3. target-leaf first stage is frozen at 0.10,
4. feature dimension and formulas match this pre-registration,
5. no feature uses k, n-k, oracle dependency labels, or final labels,
6. final data do not select tree depth or thresholds,
7. deterministic residual formulas are frozen before final,
8. learned and deterministic residual proposals remain advisory,
9. every final method verifies the original full problem,
10. unsafe accepted reductions are zero,
11. all final scale cells contain exactly 32 examples,
12. teacher-search work remains separate from deployable-policy work.

KEEP does not require the learned tree to win.

## Learned-component retention rule

A learned residual component is retained only if all safety conditions hold and at least one of these two performance conditions holds:

### Route A — material solver advantage

Compared with the best deterministic residual baseline:

    learned mean final solver ops
        <= 0.90 * best deterministic mean final solver ops

and:

    learned checker/materialization proposals
        <= 2.0 * best deterministic proposals

### Route B — Pareto advantage

The learned tree has:

- lower mean final solver ops than every deterministic residual baseline,
- and no more checker/materialization proposals than the deterministic method with the closest solver performance.

In addition, the learned method must recover at least:

    75% of exact residual teacher aggregate gain.

Decision:

- retention conditions satisfied -> KEEP_LEARNED_RESIDUAL
- learned reaches >=75% teacher recovery but lacks deterministic advantage -> KEEP_DETERMINISTIC_RESIDUAL
- learned recovery <75% while meaningful teacher headroom remains -> ESCALATE_MODEL_CLASS
- no meaningful teacher headroom on the new final distribution -> DELETE_RESIDUAL_MODEL

"Meaningful teacher headroom" for this decision means:

    mean exact residual teacher additional solver savings
        >= 5% of mean target-leaf solver ops.

This threshold is a research continuation gate, not an economic break-even claim.

## Claim boundary

A positive learned result would support only:

> on this generated exact affine-linear family, a very small state-aware learned residual ranker can improve verified structural compression after a frozen cheap deterministic first stage, beyond the pre-registered deterministic residual policies tested here.

It would not establish:

- globally optimal compression,
- natural-language Structural Compression,
- domain generality,
- asymptotic complexity improvement,
- end-to-end energy or latency superiority.
