# v0.0.68 — End-to-end iso-capability compression gate

Status: protocol frozen before timing final cases.

## Question and scope

Can the frozen 289-parameter learned affine dependency scorer beat both exact direct
solving and the frozen target-leaf heuristic in **total verified inference time**?
This is a gate for one synthetic exact-linear family, not a claim that NEUMANN 1
is already a general high-efficiency model. The follow-on program must also
test semantic parsing, other domains, memory, and matched neural baselines.

## Frozen comparison

- Direct: solve the original full system exactly, then verify every original row.
- Learned: frozen v0.0.33 checkpoint; v0.0.34 global threshold 0.40; enumerate,
  feature extraction, inference, candidate checking (including **all repeated
  trial solves**), reconstruction, and original-system verification.
- Cheap: v0.0.35 target-leaf threshold 0.10 and identical checker.
- No method is told the generator's oracle elimination count. Model fitting is
  excluded from per-query latency but explicitly reported as an additional,
  unamortized development cost. Checkpoint import/warm-up is likewise excluded
  from steady-state latency for all methods.
- Frozen code paths are timed as actually implemented, without rewriting the
  checker in favor of one method. All methods must produce identical exact
  original-system answers; rejection and verification time count toward cost.

## Test and timing protocol

Generate 8 cells (k in {2,4}, n in {4,8,16,32}), 4 new cases per cell,
seed = 680000 + 1000*k + n. Exclude exact signatures from v0.0.33–0.0.36,
including the v0.0.36 final set. No parameter selection on these cases.
Warm each method once outside timing; perform 5 interleaved repetitions per
case and report per-case median wall-clock milliseconds with the Python
`perf_counter_ns` clock, then cell medians and sums of per-case medians.
Pin BLAS/OMP threads to one. Record platform and dependency versions.
The timed learned/cheap portions are separately `score` and `checker`;
the checker contains each tentative exact solve, reconstruction, and full
verification, plus the final materialization. Direct records `solve` and
`verify`. Timing in-process is vulnerable to interpreter/CPU noise, so
secondary operation counts and repeated case-level timings remain visible.

## Decision rule (registered before final measurement)

Capability: 32/32 exact original-system verification and ground-truth
agreement for each method; no unsafe accepted reduction.

Evidence for a *local learned compute advantage* requires learned total
median per-case time <= 0.8 × cheap time in **both** n=16 and n=32 for each
k, while never more than 1.1 × cheap on either n=4 or n=8 cell, and less
than direct time in both n=32 cells. Otherwise the learned branch fails this
gate and is not promoted on this family. This is not a statistical proof
of performance on unseen distributions; 4 cases per cell are exploratory.

The primary measurement is end-to-end wall time. Solver arithmetic counts
are a separate diagnostic, not added to model FLOPs or elapsed time as if
these were interchangeable units. A purported scaling advantage requires
separate larger-n replication with complete-path measurement.

The previous solver-arithmetic proxy did not include the many tentative
solutions performed inside the checker. For example, k=2,n=32 has median
final-solve counts of 5651 direct, 848.5 learned, and 478.5 target-leaf,
yet complete latency is 3.23, 103.72, and 123.37 ms respectively. This is
not a contradiction: those counts cover **only the final** solve.

**Gate decision: FAIL** for learned total-compute advantage, and also for
the deterministic compression route versus direct exact solving on this
family. The learned scorer sometimes has better elapsed time than target-leaf
at large n, but remains ~28–32× slower than direct at n=32. It also misses
the small-cell no-regression rule. Do not deploy the learned branch here.

Boundaries: this is a Python exact-rational implementation, not a comparison
against an optimized compiled solver or a matched general-purpose language
model. Timing noise and only 4 cases/cell preclude a population-level speed
claim; both observed runs agree in gate outcome. The next core question is
whether a *single-pass, fail-closed* checker can ever recover the lost cost
without degrading correctness. More broadly NEUMANN must pass equal-capability
total-compute gates across genuinely hard problem families, not merely
demonstrate a smaller final reduced solver operation count.
