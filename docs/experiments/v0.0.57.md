# v0.0.57 — Verified-compute floor and leaf-elimination screen

## Scope and disclosure

This is a **descriptive, nonblind screen** of the same 13 NIST BCSSTRUC1
matrices used in v0.0.55–56. An exploratory scan of their degree counts and
iterative leaf counts preceded this implementation. It is neither an
independent holdout nor a preregistered performance test. Input files are
checked against the frozen SHA-256 hashes in `natural_reuse_v055.py`.

The candidate is narrow: repeatedly delete vertices of structural degree
at most one in the symmetric off-diagonal sparsity graph. `benchmark_v057.py`
reports the **maximum graph count** this candidate might remove. It does
not construct a reduced system, certify pivots, solve it, or establish an
end-to-end saving. Counting a vertex is deliberately permissive: a numeric
elimination could fail due to a zero/unstable pivot or cost more than solving
the original system. This graph count says nothing about block Schur
compression, larger separators, symmetries, or a different workload.

| bcsstk11, bcsstk12 | 50 / 1473 each (3.39%) |
| Other eight matrices | 0 |

No matrix reaches the **screening heuristic** of 10% removable variables;
even passing that heuristic would not imply a compute advantage. Do not
build a general leaf-elimination runtime on this corpus. The positive
constructed examples and the previous negative Schur-cost result are not
overwritten by this narrower observation.

Reproduce with:

```sh
python benchmark_v057.py --data-root /path/to/bcsstruc1 \
  --output docs/experiments/results/v057_descriptive_screen.json
```

## Fixed-capability cost floor

For an explicitly supplied sparse system `Ax=b` with `n` solution entries
and `m` stored nonzeros, an explicit reconstructed answer requires
Ω(n) writes. An independent exact residual check that accepts arbitrary
changes to the input coefficients generally needs Ω(m+n) reads/operations:
when the corresponding solution entry is nonzero, any uninspected
coefficient can change an original equation. This is a conditional lower
bound for **this explicit-input, full-output, independent-check contract**,
not a universal complexity theorem for all problem representations or
probabilistic checks.

Therefore the stronger scaling question should compare the full verified
path with this compulsory floor. A reduction may lower superlinear solver
growth toward the input/output floor while preserving the full check;
it cannot make the total explicit verified path sublinear in the growing
original input or output size. A claimed improvement must report discovery,
certificate checking, reduced-system construction, solve, reconstruction,
and original verification, and must compare against the best relevant
native solver or presolver at the same numerical acceptance criterion.

The next workload should expose real, independently specified constraints
or repeated query structure that creates substantial eliminable solver work,
and should show that a strong existing solver does not already capture it.
Synthetic duplicated variables alone do not establish that opportunity.
