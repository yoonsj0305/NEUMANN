# v0.0.95 — Same-support graph-refinement attribution closure

## Question

Does the v0.0.94 compact graph discover a new compressed variable support, or
does it only re-rank columns that the pointwise selector already chose?

No new model fitting, inference, solver execution, timing, input generation, or
holdout is used in this version. This is a code/authority closure over the
already-published v0.0.94 route.

## Program-equivalence boundary

For an LP with m rows and n columns, the v0.0.94 route executes:

1. the frozen point head scores all n columns;
2. `selected = top2m(point_score)`;
3. compact mode sets `keep = selected`;
4. the graph scores exactly those 2m columns;
5. compact `shortlist = keep[argsort(graph_score)[:2m]]`.

Because `keep` itself has exactly 2m unique columns, step 5 can only permute
that set:

`set(shortlist_compact) = set(shortlist_point)`.

Therefore the restricted native LP receives the same variable support as the
point-only Direct route, modulo column permutation. The graph can change the
ordered top-m basis proposal and column order, but under this contract it
cannot add, remove, or discover a different 2m support.

The new v0.0.95 contract tests exercise the real v0.0.94 `propose` function
across multiple matrix sizes and protect negative controls where support
actually changes or is corrupted.

## Consequence for the current candidate

The v0.0.94 opened diagnostic already recorded only 0/48 and 1/48 compact
exact-m original-LP certificates for seeds 87001 and 87002. Its first paid cost
screen was conservatively stopped, and its timings remain explicitly
contaminated and unusable for a clean speed claim.

v0.0.95 does not reinterpret those timings. Instead it closes the attribution
loophole: any future claim that this same point→2m→graph contract wins because
the graph discovered a smaller/better compressed support would be false by
construction. Once the exact-m candidate is rejected, the downstream restricted
problem has the same variable set as point-only.

Decision:

`STOP_SAME_SUPPORT_GRAPH_REFINEMENT_NO_NEW_FIT`

Do not spend another fit or holdout on this same-support graph-refinement
contract. This does **not** close Q3 or Q4 globally and does not rule out a
learner that can change the admissible support, produce a different verified
structural program, remove constraints/variables in another way, or operate on
another task family.

## Next admissible target

A successor must create structural authority that the strong cheap Direct path
does not already possess. Before fitting, require at least one of:

- a learned/graph route that can change the retained support under equal
  verifier/executor authority;
- an independently verifiable transformation that reduces downstream degrees
  of freedom beyond the point selector;
- a different problem family where a zero-model or deterministic headroom
  screen leaves enough complete verified cost budget.

Strong deterministic and matched executable Direct comparators remain
mandatory. Native stays default. Q3/Q4 remain OPEN.
