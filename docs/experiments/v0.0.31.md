# v0.0.31 - Matched Tiny Transformer Direct-vs-Structure Challenger

## Research question

v0.0.30 failed to find a Direct break-even point inside a shallow MLP frontier.

That leaves a major alternative explanation:

> perhaps Direct failed because the fixed-position MLP has poor sequence and algorithmic inductive bias.

v0.0.31 attacks that explanation with a small learned sequence model.

The experiment compares two models with the exact same architecture:

    token categories + numeric scalar channel
      -> learned token embedding
      -> learned positional embedding
      -> 2-layer Transformer encoder
      -> masked mean pooling
      -> identical 82-way output head

The only intended difference is the learning objective.

## Direct sequence path

Training data:

- 8,192 unique positive linear systems
- all 81 integer solution-pair classes represented

Target:

- one of 81 exact ordered solution pairs
- output class 81 remains unused by positive Direct supervision

Inference:

    raw text
      -> tokenizer
      -> Tiny Transformer
      -> exact solution-pair class
      -> evaluation verifier

The deterministic compiler is not available to Direct inference.

It is used only as an evaluation oracle so the existing verifier can judge the predicted exact solution pair.

## Structural sequence path

Training data:

- 4,096 positive systems
- 4,096 paired near-negatives
- total training examples = 8,192

Targets:

- class 0 = LINEAR
- class 81 = ABSTAIN

Classes 1 through 80 are unused by Structural supervision.

Inference:

    raw text
      -> same tokenizer
      -> same Tiny Transformer
      -> LINEAR / not-LINEAR decision
      -> deterministic compiler
      -> deterministic solver
      -> deterministic verifier

Only class 0 grants a proposal to the deterministic compiler. Every other model output fails closed as abstention.

## Why the 82-way head is intentionally identical

A two-class Structural head would have fewer output parameters than the Direct 81-class answer head.

v0.0.31 deliberately avoids that advantage.

Both models have the same 82-way output head, so:

- total parameter count is identical
- parameter bytes are identical
- learned architecture weighted-sum proxy is identical on the same input length

The unused Structural output classes are an intentional parity mechanism.

## Training-cardinality parity

Both models see exactly 8,192 training examples.

Direct is intentionally favored in positive solution supervision:

- Direct positive systems: 8,192
- Structural positive systems: 4,096
- Structural near-negatives: 4,096

So Direct receives twice as many solved positive systems.

- max tokens: 32

- d_model: 64
- attention heads: 4
- Transformer layers: 2
- feed-forward width: 128

- CPU execution

## Learned arithmetic proxy

The Transformer proxy counts selected matrix weighted-sum terms:

- numeric scalar projection
- Q/K/V projections
- attention score dot products
- attention-weighted value products
- attention output projection
- feed-forward matrices
- final output head

It excludes:

- token and position embedding lookup
- layer normalization
- softmax
- GELU
- bias additions
- memory traffic
- cache effects
- kernel overhead
- hardware energy

It is not a FLOP, instruction, latency, or joule measurement.

## Fixed v0.0.29 MLP reference

For context, the existing 640 -> 8 -> 2 Structural MLP is also evaluated on the new sequence validation/final splits.

It is not used to train or select the Transformer models.

## KEEP contract

KEEP validates the experiment, not a winner.

Required:

1. Direct and Structural total parameter counts are identical
2. parameter bytes are identical
3. learned weighted-sum proxy is identical on the same positive inputs
4. total training cardinality is identical
5. all 81 Direct solution classes appear in training
6. new corpus splits are mutually text-disjoint
7. new corpus is text-disjoint from v0.0.29/v0.0.30
8. Structural compiler-gated near-negative false-route rate is zero

Not required:

- Direct losing
- Structural winning
- either model reaching 100%
- any wall-clock ordering

## Claim boundary

This experiment is much closer to a language-model-like learned architecture than the previous shallow MLP tests, but it is still tiny and task-specific.

It does not establish:

- frontier-LLM efficiency
- total-compute superiority
- GPU FLOP savings
- memory-bandwidth savings
- energy savings
- open-domain reasoning superiority

The supported question is narrower:

> when a tiny Transformer has identical architecture and training cardinality, is it more effective to learn the final numeric answer class directly or learn when a deterministic structure should execute?

## Interpretation

v0.0.31 substantially weakens the simplest alternative explanation for v0.0.29-v0.0.30:

> the Direct path lost only because a fixed-position shallow MLP had the wrong sequence inductive bias.

That explanation is insufficient for this controlled experiment.

The Direct challenger now has attention, learned embeddings, learned positional embeddings, the same 75,538-parameter architecture as the Structural model, the same learned arithmetic proxy on the same inputs, the same total training cardinality, and twice as many positive solved examples. Yet its final exact verified coverage is **31/243**, while the matched Structural model reaches **243/243**.

The narrow supported result is:

> in this generated 2x2 linear-system setting, with the specific pre-registered Tiny Transformer and training protocol, allocating the matched learned model to recognize executable structure produced much higher verified task completion than training the identical learned architecture to classify the final exact solution directly.

This still does **not** establish lower total computation. Structural execution additionally pays deterministic compilation, Gaussian elimination, and verification. Those deterministic costs are intentionally not collapsed into the learned weighted-sum proxy.

It also does not establish that Transformers cannot learn the algorithm. The Direct model is still tiny and receives only final-answer supervision. Larger/deeper models, curricula, autoregressive intermediate steps, coefficient extraction, program supervision, scratchpads, arithmetic modules, or other algorithmic inductive biases could move the Direct frontier dramatically.

That is now the most important falsification direction: improve the **Direct learning objective and intermediate supervision**, rather than simply increasing another shallow capacity grid.
