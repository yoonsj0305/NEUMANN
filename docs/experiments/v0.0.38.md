# v0.0.38 — Coupled Block Structural Compression Oracle

Status: pre-registered research specification

## Motivation

v0.0.37 showed that the current exact affine-linear family is saturated by
cheap local structural heuristics.

The frozen scalar architecture:

    target-leaf @ 0.10
        -> deterministic checker
        -> Markowitz residual @ 0.05
        -> deterministic checker

outperformed the learned residual policy.

The correct next step is therefore not more learned capacity.

v0.0.38 changes the structural family and the compression operator.

The central question is:

> Can NEUMANN safely remove computational degrees of freedom that are invisible
> to every single-row affine elimination, but become reconstructible when a
> coupled relation block is considered jointly?

## New structural motif

Each compressible motif contains two dependent variables:

    x_a, x_b

and two equations:

    U [x_a, x_b]^T + D c = r

where:

- c is a vector of retained core variables,
- D contains small integer coefficients,
- U is a 2 x 2 integer unimodular matrix,
- det(U) is exactly +1 or -1,
- every nonzero coefficient in the two block rows has absolute value >= 2.

Pre-registered base U matrices:

    [[2, 3], [3, 5]]   det = +1
    [[3, 5], [5, 8]]   det = -1
    [[2, 5], [3, 7]]   det = -1
    [[5, 8], [8,13]]   det = +1

Row/target permutations and sign flips may be used only if:

    abs(det(U)) = 1

and all nonzero coefficients remain outside {-1, +1}.

Because U is unimodular:

    U^-1

is integer-valued.

Therefore both target variables can be reconstructed exactly as affine integer
functions of the retained variables.

## Why the existing scalar operator must fail

The existing scalar affine candidate enumerator requires a row-target
coefficient of +1 or -1.

The v0.0.38 generator forbids all nonzero coefficients with absolute value 1.

Required generator invariant:

    scalar_affine_candidate_count = 0

for every v0.0.38 system.

This is deliberate.

v0.0.38 is an operator-capability gate, not a fair discovery contest between
scalar and block methods.

## Family construction

Scale grid:

    k in {2, 4}
    n in {4, 8, 16, 32}
    n >= k

The number of coupled 2-variable blocks is:

    b = (n - k) / 2

Thus:

- k=2: b in {1, 3, 7, 15}
- k=4: b in {0, 2, 6, 14}

The k=4, n=4 cell is the no-compression control.

Per cell:

    final = 32 systems

Total:

    256 systems

No train or validation split is used because v0.0.38 fits no model and selects
no threshold.

## Core subsystem

The k retained core variables are constrained by an exact invertible integer
core system.

All nonzero core-system coefficients must also satisfy:

    abs(coefficient) >= 2

so the no-unit-coefficient invariant applies to the entire full system.

The full system is square and exactly solvable.

Rows and columns are independently permuted after construction.

Variable names are generic.

The generator-provided block identities are retained only as oracle metadata
for v0.0.38.

## Oracle block certificate

A block certificate contains:

- exactly two distinct original row indices,
- exactly two distinct target variables,
- the 2 x 2 target coefficient matrix U,
- two derived affine reconstruction rules,
- all reconstruction coefficients and constants as exact integers.

The deterministic validator must independently verify:

1. both rows exist,
2. both targets exist,
3. rows and targets are unique,
4. the declared 2 x 2 target matrix matches the original rows,
5. abs(det(U)) = 1,
6. each derived reconstruction rule is algebraically implied by the two
   original rows,
7. the final retained system is square,
8. reconstruction is acyclic,
9. the reconstructed full answer verifies the ORIGINAL full system exactly.

Generator metadata never grants execution authority.

## Oracle compression

For b coupled blocks, the generator oracle proposes exactly b block
certificates.

Each accepted block removes:

    2 rows
    2 variables

Therefore the oracle target retained dimension is:

    n - 2b = k

The retained exact solve is performed only after all certified block
reductions have been applied.

## Baselines

### A. Full exact solve

Solve the original n-dimensional system with the existing exact Gauss-Jordan
solver.

### B. Frozen scalar NEUMANN path

Run the existing scalar candidate pipeline unchanged.

Because the family forbids unit coefficients, it should discover no scalar
affine candidates.

This is a negative control.

### C. Generator block oracle

Use the generator-provided block identities as proposals, but require the new
deterministic block validator and original-problem verifier to authorize every
reduction.

This is a capability oracle, not a deployable discovery policy.

## Primary metrics

For every example report:

- core dimension k,
- apparent dimension n,
- coupled block count b,
- scalar affine candidate count,
- oracle block proposal count,
- accepted block count,
- retained dimension,
- baseline exact solver arithmetic ops,
- scalar-path solver arithmetic ops,
- block-oracle solver arithmetic ops,
- block-oracle solver savings,
- block-oracle solver savings fraction,
- reconstruction operation counts,
- original-problem verification operation counts,
- certificate size in integer scalars / bytes if available,
- final verified flag,
- ground-truth equivalence.

Report all metrics by (k, n) cell and in aggregate.

## Scaling diagnostic

For each fixed k, regress mean solver arithmetic ops against n for:

- full exact solve,
- scalar path,
- block oracle.

The block-oracle slope is expected to be near zero because the retained solve
dimension is fixed at k.

This is a diagnostic, not a formal asymptotic proof.

## End-to-end cost boundary

v0.0.38 may claim solver-work reduction only.

It must not silently combine:

- discovery work,
- certificate validation,
- reconstruction,
- verification,
- solver arithmetic,

into a synthetic total unless the units are explicitly comparable and fully
instrumented.

Reconstruction and verification costs must be reported separately.

No energy, latency, dollar-cost, or total-compute superiority claim is allowed.

## Pre-registered continuation gate

Proceed to v0.0.39 block discovery only if all conditions hold:

1. scalar affine candidate count is exactly zero for every final system,
2. block-oracle verified retention is 1.0,
3. unsafe accepted block reductions are zero,
4. retained dimension equals k for every final system,
5. every compression cell with n > k has positive mean oracle solver savings,
6. at n=32, for both k=2 and k=4, mean oracle solver savings fraction is at
   least 0.80.

If conditions 1-4 pass but condition 5 or 6 fails:

    HOLD_BLOCK_DISCOVERY

and first analyze whether the new operator creates enough downstream value to
justify discovery work.

If any safety / exactness condition fails:

    REJECT_BLOCK_OPERATOR

## KEEP contract

KEEP means the experiment is methodologically valid.

Required:

1. exactly 8 scale cells,
2. exactly 32 final systems per cell,
3. no fitted model,
4. no threshold calibration,
5. all nonzero generated coefficients have abs(value) >= 2,
6. scalar affine candidate count is zero for every system,
7. oracle block count is exactly (n-k)/2,
8. every accepted block passes deterministic algebra validation,
9. every final reconstruction verifies the original full problem,
10. unsafe accepted block reductions are zero,
11. no final result changes the block matrix set, scale grid, or continuation
    rule.

KEEP does not require the continuation gate to pass.

## Claim boundary

A positive v0.0.38 result would support only:

> on a generated exact linear family with coupled unimodular 2 x 2 dependency
> blocks, certified block Structural Compression can remove degrees of freedom
> that the current single-row affine operator cannot express.

It would not establish:

- learned discovery of block structure,
- natural-language Structural Compression,
- domain generality,
- global minimality,
- end-to-end total-compute superiority,
- asymptotic complexity improvement.
