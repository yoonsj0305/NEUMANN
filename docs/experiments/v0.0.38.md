# v0.0.38 — Harder Structural Family Gate: Row-Mixed Affine Invariance

Status: pre-registered research specification

## Motivation

v0.0.37 showed that the current generated affine-linear family is saturated by
cheap local structural heuristics.

The frozen deployable path:

    target-leaf @ 0.10
        -> deterministic checker
        -> Markowitz residual @ 0.05
        -> deterministic checker

outperformed a 193-parameter state-aware residual MLP and even outperformed the
exact one-step greedy residual trajectory.

Therefore v0.0.38 does not add model capacity.

It asks a more basic question:

> Is the current affine-family performance invariant to a semantics-preserving
> change of equation representation, or does it depend on local row form?

## Paired-family construction

For every latent affine example, construct two observed systems.

### A. Unmixed control

Use the existing v0.0.33-style affine system exactly as generated.

### B. Row-mixed hard representation

Starting from the same exact system, apply a deterministic random sequence of
integer elementary row additions:

    row_dst <- row_dst + s * row_src

where:

    s in {-1, +1}
    src != dst

Each accepted operation is unimodular and therefore preserves the exact
solution set.

No column transformation is introduced in v0.0.38.

The mixed system has:

- the same variables,
- the same exact ground-truth solution,
- the same latent affine dependency semantics,
- a different row representation.

The local row form that exposed easy variable definitions is intentionally not
preserved.

## Mixing contract

For apparent dimension n:

    accepted row-add operations = 4 * n

The generator may reject a proposed elementary operation only to enforce the
pre-registered coefficient-growth bound:

    max absolute A coefficient <= 128

and:

    max absolute b value <= 100000

Rejected operations do not count toward the 4n accepted operations.

Generation fails closed if it cannot obtain the required number of accepted
operations within:

    200 * n proposals

No heuristic score, candidate count, solver result, or downstream performance
metric may be used to accept or reject a mixed example.

This prevents tuning the generator toward a desired result.

## Data

Scale grid remains:

    k in {2, 4}
    n in {4, 8, 16, 32}
    n >= k

Final-only paired audit:

    24 latent systems per cell
    192 latent systems
    384 observed representations

The k=4, n=4 cell is retained as a no-compression control.

All latent base signatures must be disjoint from every v0.0.33-v0.0.37 split.

No training or calibration occurs in v0.0.38.

## Frozen local policy

The same frozen deployable policy is used unchanged on both representations:

    target-leaf @ 0.10
        -> deterministic checker
        -> Markowitz residual @ 0.05
        -> deterministic checker

Neither threshold may be recalibrated.

Final inference receives neither k nor n-k.

The local policy is not given the row-mixing history.

## Latent oracle diagnostic

The latent oracle uses the generator-known affine dependencies from the unmixed
base representation.

It:

1. solves only the retained latent core system,
2. reconstructs the full variable assignment,
3. verifies that full assignment against the row-mixed ORIGINAL system.

The latent oracle is diagnostic only.

Its access to generator-known latent structure is not available to deployable
methods.

The oracle execution metric includes retained-system exact solver operations.

Reconstruction and verification counts are reported separately.

Row-unmix/discovery cost is not included and therefore no end-to-end efficiency
claim is permitted.

## Primary measurements

For every paired latent example report:

- unmixed full-system solver ops,
- mixed full-system solver ops,
- latent-oracle retained solver ops,
- unmixed frozen-policy final solver ops,
- mixed frozen-policy final solver ops,
- unmixed candidate count,
- mixed candidate count,
- accepted reductions for each representation,
- original-problem verification for each representation,
- mixed latent-oracle verification,
- reconstruction operation count,
- verification operation count.

## Representation-sensitivity metrics

For compression-capable cells n > k:

### Final-work inflation

    work_inflation
        = mixed_policy_solver_ops
          / max(1, unmixed_policy_solver_ops)

### Oracle-gap multiplier

    oracle_gap_multiplier
        = mixed_policy_solver_ops
          / max(1, latent_oracle_solver_ops)

### Candidate retention

    candidate_retention
        = mixed_candidate_count
          / max(1, unmixed_candidate_count)

### Paired degradation rate

Fraction of paired examples satisfying:

    mixed_policy_solver_ops
        > unmixed_policy_solver_ops

## Hard-family gate

v0.0.38 is considered a useful harder-family gate if all methodological
requirements pass and at least **two of the following three** representation
stress criteria hold on compression-capable cells:

1. aggregate work_inflation >= 1.50
2. aggregate oracle_gap_multiplier >= 1.50
3. aggregate candidate_retention <= 0.75

The paired degradation rate is reported but is not a gate.

Interpretation:

### HARD_FAMILY_CONFIRMED

At least two stress criteria pass.

Meaning:

> the frozen local affine policy is materially representation-sensitive while
> latent compressibility remains available.

Next work should target representation-invariant structural discovery.

### LOCAL_POLICY_ROBUST

Fewer than two stress criteria pass.

Meaning:

> row mixing alone is not enough to defeat the frozen deterministic policy.

Do not tune the mixing process after seeing final results.

Move to a qualitatively different harder motif such as block dependencies,
equivalence classes, or long-range redundant relations.

## No-compression control

For k = n:

- no positive latent compression claim is made,
- the frozen policy must retain original-problem verification,
- unsafe accepted reduction count must remain zero.

False compression is reported.

## KEEP contract

KEEP means the experiment is methodologically valid.

Required:

1. all v0.0.38 latent base signatures are disjoint from v0.0.33-v0.0.37,
2. mixed systems are produced only by exact unimodular row additions,
3. mixing uses exactly 4n accepted row additions,
4. mixing rejection depends only on coefficient-growth bounds,
5. target-leaf threshold remains exactly 0.10,
6. residual Markowitz threshold remains exactly 0.05,
7. neither representation provides k nor n-k to the deployable policy,
8. latent oracle verifies the reconstructed answer against the mixed original,
9. deployable verified retention is 1.0 on both representations,
10. unsafe accepted reduction count is zero,
11. all eight cells contain exactly 24 paired latent systems,
12. no post-result mixing-strength, threshold, or policy tuning occurs.

KEEP does not require HARD_FAMILY_CONFIRMED.

A LOCAL_POLICY_ROBUST outcome is scientifically valid.

## Claim boundary

A HARD_FAMILY_CONFIRMED result would support only:

> on this paired exact affine-linear audit, the current cheap local Structural
> Compression policy is sensitive to semantics-preserving row representation,
> while generator-known latent compression remains available.

It would not show:

- that a learned model can recover the hidden structure,
- total-compute superiority,
- natural-language Structural Compression,
- domain generality,
- globally minimal structure,
- superiority to general sparse linear algebra.
