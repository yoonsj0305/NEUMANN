# v0.0.43 — Incremental row index for deterministic peeling

Status: pre-registered before implementation and final audit. The frozen
implementation was committed as `51fa723` before the first full audit. No
model is trained and the v0.0.42 family is unchanged.

## Problem and frozen comparator

v0.0.42 E2 recovered all declared eliminations on its engineered sparse
family, but examined 1,305.5 row pairs per active system on average. On
16 two-variable controls it proposed a full-system 2x2 reduction which the
materializer correctly rejected. The primary question is whether we can
delete repeated all-pairs enumeration without changing selected blocks or
original-problem authority.

F0 is the exact frozen v0.0.42 E2. F1 is an incremental inverted index:

1. Run the same frozen incidence-one local router.
2. Index each remaining variable with original row incidence in {2,3,4}
   to its nonzero remaining rows. A target with exactly two remaining rows
   contributes to a row-pair → target set index. Maintain that index as
   accepted rows and targets are removed.
3. Only inspect indexed row pairs with exactly two eligible targets. Derive
   and validate the same exact 2x2 candidate. Choose the same smallest
   canonical (row pair, target pair) candidate as E2.
4. Reject a candidate before derivation when accepting it would leave no
   retained row or variable. This guard removes the known (2,2) control
   waste and does not relax the exact checker.
5. Jointly materialize only the final selected set. Preserve the verified
   full-solve degraded mode for any joint failure.

No oracle identity, k, arm label, generated block count, or ground truth may
enter discovery. The local router and exact checker remain unchanged.

## Metrics and gates

Primary equivalence: compare exact local candidate keys and accepted block
keys from F0 and F1 on each active system, and compare final verified answer,
retained dimension, and solver arithmetic operations. All must agree in all
192 active systems. F1 must leave all 32 controls uncompressed, verified, and
with zero rejected joint materializations. Both methods must verify all
224 original full systems, with zero unsafe accepted reductions.

Primary search-work gate: mean F1 indexed row-pair examinations must be at
most 10% of F0 all-pairs examinations **in each active arm**. Also report
posting construction edges, posting removal updates, derivation and exact
checker calls, and materialization attempts separately. Pair examinations
alone are not total cost.

Diagnostic runtime: time the whole execution path (local routing, discovery,
exact checking, retained solve, reconstruction and original verification),
excluding only frozen scorer fitting, dataset creation, the oracle and
benchmark-only baseline solve. Run F0 and F1 three times each per final
example, with alternating method order by example index. Use
`time.perf_counter_ns`, single-thread numeric libraries, report paired
per-example medians in milliseconds and the median F1/F0 ratio by arm.
This is a noisy local runtime measurement, not energy, peak RAM, or
deployment latency. A paired ratio above one is a negative result even if
pair examinations fall. Do not use timing to tune F1 after seeing final
data.

KEEP_INDEXED requires fresh-data, equivalence, safety, controls and the
search-work gate. Timing is a reported diagnostic, not a PASS criterion.
Failure to meet any gate is recorded; do not rewrite F1 on the same final
data and call a later run a fresh confirmation.

This experiment tests a motif-specific low-degree index. A success cannot
establish global minimality, total-compute dominance, general structural
reasoning, or an AI-model improvement. High-incidence distractors and
alternative valid decompositions remain out of scope.

## First and only final audit

`docs/experiments/results/v043_first_audit.json` records the first 224-system
result. All signatures were unique and disjoint from prior frozen audits;
every cell was complete. All 224 old and new solutions verified against the
original equations. All 192 active cases matched on exact accepted local
and block keys, full rational answer, retained dimension, and solver
arithmetic operations. Each active arm recovered 100% of its oracle solver
savings and declared eliminations. No unsafe accepted reductions occurred.

| Arm (64 each) | F0 pairs / system | F1 pairs / system | F1/F0 | F1 posting edges / updates | F0/F1 derivations and checkers | Median paired runtime F1/F0 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| COEFFICIENT | 1,305.5 | 58 | 4.44% | 38 / 19 | 58 / 58 | 0.877 |
| OVERLAP | 1,305.5 | 9.5 | 0.73% | 72 / 36 | 9.5 / 9.5 | 0.855 |
| COMBINED | 1,305.5 | 9.5 | 0.73% | 72 / 36 | 9.5 / 9.5 | 0.893 |

The 32 controls remained uncompressed and verified. F1 made zero joint
materialization attempts or rejections; F0 attempted and rejected 16
whole-system (2,2) proposals. The indexed method did not reduce derivation
or exact checker calls in the active arms; it reduced repeated unproductive
pair enumeration. Index construction and posting updates are additional
work, so pair counts must not be interpreted as total compute.

Three paired measurements per method and example included routing, discovery,
checking, materialization/retained solve, reconstruction and original
verification. Per-arm medians of the per-example medians, F0 → F1, were
11.007 → 9.073 ms (COEFFICIENT), 14.322 → 11.081 ms (OVERLAP), and
11.113 → 8.996 ms (COMBINED). Paired ratios above are medians of each
example's F1/F0 median, not ratios of arm-level medians. These are noisy
single-machine wall times, not energy, peak RAM or deployment latency.

Decision: **KEEP_INDEXED** under the registered equivalence, safety,
controls and per-arm ≤10% search-work gates. The evidence is specific to
these generated low-degree exact systems; it does not establish a faster
general-purpose solver or learned structural intelligence. Run
`python benchmark_v043_smoke.py` for the contract and
`python benchmark_v043.py` to reproduce the deterministic audit (timings
will vary).
