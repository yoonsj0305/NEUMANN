# v0.0.45 — Exact Schur repair and full-path cost

Status: pre-registered before implementation and final audit. The
implementation and evaluator were frozen in `277ebc0` before the first full
run. v0.0.44 demonstrated two limits of frozen F1. This is a deterministic
repair and a cost audit, not training of a structural model. Preserve F1
unmodified.

## Frozen comparison and candidate rules

F0 is v0.0.43 `execute_peeling(indexed=True)`. F2 uses the same local
router and exact checker. Its incremental residual index includes targets
with **original row incidence 2 through 6**, instead of 2 through 4. It
selects the same canonical smallest validated two-target row pair at each
step; retained rows and variables must remain. Jointly materialize sparse
peeling as before, with verified full-solve fallback.

Only when sparse discovery has found no local or block reduction and the
system dimension is 6 or 8, F2 performs a bounded dense fallback: inspect
row pairs in canonical order for exactly four common variables with original
incidence four. For the first such pair, inspect pairs of those four targets
in canonical order and choose the first nonsingular, exact-validated 2x2
rule. Use exact rational substitution of the two eliminated targets in
**every retained equation** (Schur complement), solve the retained system,
reconstruct and verify the original full system. If any step fails, solve
the original full system and verify it. This heuristic neither sees oracle
labels nor selects by ground truth or benchmark solver count. The dense
fallback is deliberately limited to this four-variable motif; no claim of
general dense-compression search.

## Fresh adversarial audit

Reuse the v0.0.44 HIGH_DEGREE and ALTERNATIVES construction mechanisms, but
not any prior final system. HIGH_DEGREE: (2,16),(2,32),(4,16),(4,32),
24 each, seeds 2,110,000+1000*k+n. ALTERNATIVES: (2,6),(4,8), 48 each,
seeds 2,210,000+1000*k+n. Controls (2,2),(4,4), 16 each, seeds
2,310,000+1000*k+n. Total 224. Fixtures start at 2,090,000. Signatures
must be unique and disjoint from v0.0.44 and all predecessors. Freeze
implementation, evaluator and contracts before the first full final audit.

The HIGH_DEGREE complete oracle and the two independent dense witnesses
must again verify the original system. Both F0 and F2 must verify all 224
answers against original equations with zero unsafe accepted reductions.
The 32 controls must remain full dimension, with no rejected proposals.

## Measurements and gates

Report by arm and cell: accepted keys and dimensions, baseline/oracle/F0/F2
retained solver arithmetic, row-pair examinations, derivations, exact-checker
calls, posting edges/updates, Schur construction scalar operation count,
and materialization/rejection counts. For HIGH_DEGREE F2 must recover all
declared eliminations and 100% oracle solver arithmetic savings in each of
96 examples. For ALTERNATIVES F2 must eliminate exactly two variables in
each of 96 examples, verify the same answer as both witnesses, and have
retained solver arithmetic below a full solve. Controls must be unchanged.
Otherwise mark `REPAIR_FAILED`. If all these and freshness/safety hold,
mark `STRUCTURAL_REPAIR_CONFIRMED`; this decision is **not** a claim of
end-to-end benefit.

Cost diagnostic: three paired repetitions of F0 and F2 on each example,
alternating method order by example and repetition. Time
`perf_counter_ns` around the entire execution path, including routing,
index creation, candidate search, exact derivation/checking, substitution,
retained solve, reconstruction, original verification, and any fallback;
exclude generator creation, frozen scorer fit and benchmark-only baseline
and oracle solves. Report per-example medians in ms and the median paired
F2/F0 ratio by arm. A ratio above one is a negative local runtime result,
even when retained solver arithmetic falls. These noisy local times are
not energy, memory, deployment latency or asymptotic complexity. No
runtime threshold determines the structural repair decision. Report
Schur construction scalar arithmetic separately from retained solver ops;
this omits rational bit complexity and candidate-search overhead.

Do not use final results to tune F2 or relabel a rerun as independent.
The question is whether a narrow exact deterministic repair closes the
constructed gaps and what it costs; it does not establish learned
reasoning, general-purpose optimal elimination or scalability.

## First and only final audit

`docs/experiments/results/v045_first_audit.json` contains 224 unique fresh
systems with complete cells. F0, F2 and the benchmark baseline verified
the original answer on all 224; there were zero rejected joint proposals.
The reference oracle in HIGH_DEGREE and both exact dense witnesses in
ALTERNATIVES were valid on all corresponding examples. Controls remained
uncompressed and verified.

| Arm | F0 → F2 variables removed (mean) | F0 → F2 retained solver ops (mean) | F0 → F2 indexed/scan pairs (mean) | F2 extra work | Median paired full-path F2/F0 |
| --- | ---: | ---: | ---: | --- | ---: |
| HIGH_DEGREE (96) | 19 → 21 | 149.81 → 55.77 | 48.5 → 56 | Posting edges 34 → 46; updates 17 → 23; exact checks 48.5 → 56 | **1.060** |
| ALTERNATIVES (96) | 0 → 2 | 393.54 → 168.44 | 0 → 4.55 | Mean Schur construction 44.96 scalar operations; 2 checker calls | **1.487** |
| Controls (32) | 0 → 0 | 55.75 → 55.75 | 0 → 0 | No materialization or rejection | 1.004 |

The HIGH_DEGREE F2 result equaled the full oracle retained dimension and
solver arithmetic in **96/96**, including 24/24 in every cell. ALTERNATIVES
F2 eliminated exactly two variables with positive retained-solver arithmetic
savings in **96/96**. The production F1 method remained untouched. The
diagnostic runtime instead became slower: high-degree paired ratio 1.060,
with each cell above 1.04, and dense paired ratio 1.487. Per-arm median
per-example times were 15.747 → 17.653 ms (HIGH_DEGREE), 0.641 → 0.950 ms
(ALTERNATIVES). These medians can vary on a different machine; all measured
F2/F0 ratios above one are reported as negative local runtime outcomes.

Decision under the registered structural gates: **STRUCTURAL_REPAIR_CONFIRMED**.
Deployment/performance decision: **do not promote F2**. Its narrower
retained solves did not pay for discovery, exact checking, substitution and
verification on these cases. Even the 44.96 counted Schur scalar operations
omit candidate-search overhead and rational bit complexity. The next
research question is whether a *selective*, cost-aware gate can predict
when structural work actually reduces the verified end-to-end path on new
data. No model improvement, energy saving, general-purpose speedup or
real-world scaling is established. Reproduce with `python benchmark_v045.py`
or run the small contract with `python benchmark_v045_smoke.py`.
