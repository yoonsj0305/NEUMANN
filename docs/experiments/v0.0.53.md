# v0.0.53 — Exact repeated-component reuse on real matrix copies

Status: **preregistered; freeze code and this protocol in a commit before
the first full audit**. This tests exact *factorization reuse*, not reduced
degrees of freedom, learned discovery, hidden generalization or novelty.

## Workload and fixed comparators

Take the two connected NIST BCSSTRUC1 stiffness matrices `bcsstk05` (n=153)
and `bcsstk09` (n=1083), with pinned original compressed hashes and sources
from v0.0.52. Form `kron(A, I_k)` at k=1,2,4,8,16, which interleaves k exact
copies of the real matrix. Each component has a different planted solution
`sin(i*0.03+j*0.17+1)`; its right-hand side is computed from the original
assembled system. This is a controlled derived workload with readily
discoverable and *identically ordered* copies. It does not claim natural
occurrence or graph-isomorphism canonicalization.

Fixed baseline: one SuperLU factorization plus solve of the entire assembled
matrix using `NATURAL` column order, which was the fastest native policy for
all four v0.0.52 matrices. Also report default `COLAMD`. Per-instance better
of these is only a diagnostic, not a zero-cost selector. Candidate: detect
connected components on the whole matrix, extract each submatrix, hash exact
CSR shape/indices/pointers/values and check equality on a hash hit, factor
each unique submatrix once with NATURAL, solve every distinct RHS, reconstruct
the complete solution and verify the *original assembled equation*.
Every scan, extraction, hash, comparison, factorization, component solve,
reconstruction and verification is inside the timed path. Common generation
of matrix/truth/RHS and external I/O are outside both paths. Cache lifetime is
one trial; no free preprocessing across trials. Count unique factors and L+U
nonzeros separately; timings are not FLOPs, energy or memory.

Run one discarded complete warmup and seven fixed-seed shuffled repetitions
for each of ten cases and three policies, single process with
`OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1`. Original backward error must be
<=1e-10 and planted-solution relative infinity error <=1e-7 on every trial;
abort on failure. Preserve all 210 timed rows and median complete-path times.

## Decision before outcomes

`REUSE_OPPORTUNITY_VISIBLE` requires at least **three of four** large cases
(two bases × k=8,16) to beat fixed NATURAL by >=20% in full-path median
time. Otherwise `NO_REUSE_OPPORTUNITY`; do not add reuse to runtime. Even a
pass is only evidence for this exact repeated-block workload. Report k=1
overhead and all other cases, native diagnostic, verification errors and the
descriptive log-log slopes over five k values. No slope comparison alone
establishes a changed complexity class. A runtime promotion would require
a separate, representative workload and deployment cost gate.

## Reproduction

Reuse the externally fetched original NIST files and run:

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python benchmark_v053.py \
  --data-root /path/to/bcsstruc1 --output docs/experiments/results/v053_first_audit.json
```

CI uses a synthetic two-variable contract smoke and no external downloads.
