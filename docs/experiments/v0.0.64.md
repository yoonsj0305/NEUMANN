# v0.0.64 — Exploratory SEMI2 recourse decomposition

Status: **nonblind developmental result, not a frozen capability audit**.
The 20-second budget and SEMI2 were chosen after v0.0.63 exploratory native
timings. The dual cut code and acceptance checks were debugged with access
to this very instance. No independent holdout, paired latency distribution,
machine-checked dual certificate, or fixed-capability speed claim follows.

## Candidate and baseline

The full original SEMI2 deterministic equivalent has 20,216 variables,
including 612 first-stage integers and two 9,802-variable continuous
recourse blocks. A simple classical decomposition moves recourse blocks out
of the master: the master has 612 integer columns, two continuous scenario
value columns and the two original first-stage rows. For a master decision
`x`, solve each scenario's LP separately. The cost of parsing SMPS is shared
and excluded from the timing of both exploratory paths; decomposition model
construction, each master/subproblem solve and original-model verification
are charged to the candidate. Native HiGHS retains its native presolve and
solves the full deterministic equivalent, with its model construction,
transfer, execution and verification charged. This is a descriptive
comparison with one run per path, not an iso-capability ratio.

The first-stage master can propose recourse-infeasible `x`. The candidate
therefore solves an elastic LP in each scenario, minimizing one common
nonnegative row-violation slack `t`. If its optimum `f_s(x0)>0`, the LP row
duals produce a supporting gradient `g_s`; the necessary feasibility cut is

```text
g_s · x <= g_s · x0 - f_s(x0).
```

For feasible `x0`, the original continuous recourse LP gives `Q_s(x0)` and
a dual-derived subgradient `h_s`; the master value column gets the lower
bound `theta_s >= Q_s(x0) + h_s · (x-x0)`. These are classical Benders-style
cuts. The program trusts HiGHS's LP duals and spot checks two cuts against
a verified native incumbent; it is **not** an independent dual-certificate
checker or a novel reduction theorem. A 3-second native incumbent's fixed
first-stage decision yielded optimal recourse LPs in both scenarios;
the probability-weighted recourse objectives plus first-stage cost agreed
with its original objective. At `x=0`, the feasibility supporting cuts did
not exclude that known feasible decision; one optimality cut was also below
the neighboring feasible recourse value in each scenario.

## First exploratory result

`results/v064_first_exploratory.json` preserves the first 20-second
candidate execution. The master completed six iterations, adding two
feasibility cuts per iteration. No original-feasible complete solution was
produced before the budget expired (19.838 seconds recorded within the
candidate function). The master objectives progressed 0, 3, 10, 11, 15,
19 but are **not** valid original objectives; recourse remained infeasible
at those master proposals. Its JSON reports `best_original_feasible: null`.

`results/v064_native_diagnostic.json` records a fresh native diagnostic
with a 19-second solver cap inside the 20-second total-path allowance.
At 19.089 seconds complete path, native returned a feasible original
objective `1711.3473359053723`, dual bound `1362.9874613768761`, gap
`0.2035588377`; independent original normalized primal error was
`1.98e-12`, integrality error zero and objective agreement `2.27e-13`.
Native timed out rather than proving exact optimality. The independent
verification succeeds despite timeout. The candidate yielded no accepted
answer, so **there is no candidate/native iso-capability time ratio**.

Decision: **NO_20S_DECOMPOSITION_OPPORTUNITY_ON_SEMI2** for this simple
from-scratch cut policy. Do not deploy, train a router for, or tune more
parameters on the same inspected instance. The safe default remains the
native path. This does not invalidate decomposition generally; a mature
solver, different initialization or stronger cuts could behave differently,
but those would need a separately frozen protocol and fresh data.

Reproduce the exploratory modes with the hash-pinned local source archive:

```sh
python benchmark_v064.py --archive /path/to/semi.ZIP --budget-s 20 \
  --mode candidate --output docs/experiments/results/v064_first_exploratory.json
python benchmark_v064.py --archive /path/to/semi.ZIP --budget-s 20 \
  --mode native --output docs/experiments/results/v064_native_diagnostic.json
```

Next direct core gate: choose a family and **one verified structure witness**
with a cheap enough construction path, establish a target both paths can
