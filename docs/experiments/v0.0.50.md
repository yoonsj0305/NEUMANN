# v0.0.50 — Sparse pivot-order opportunity gate

Status: pre-registration before first full final audit. This begins a new
structural-proposal axis after v0.0.37's deterministic residual win and
v0.0.48–49's absent cost-routing headroom. No learned model is trained
in v0.0.50. The candidate output for a future learner would be a pivot
ordering, never an unchecked answer.

## Problem and exact interface

Each example is a 12-node undirected graph with a cycle and one or two
edge-disjoint random perfect matchings, hence degree 3 or 4. Construct
the symmetric positive-definite integer matrix `I + graph Laplacian`,
select an integer ground truth and compute the right-hand side. The
orderer sees the graph/matrix before solving, not the ground truth.
Exact sparse symmetric elimination uses rational arithmetic and checks
the answer against all original equations. Positive pivots are required;
failure aborts or degrades to the verified existing full-system solver.

The declared sparse scalar-arithmetic proxy at a pivot with d current
neighbors is `d*d + 6*d + 1`: factoring each neighbor once, updating
the RHS and upper-triangular Schur complement, and back substitution.
Count fill edges separately. In this SPD M-matrix family there are no
structural fill cancellations. The proxy counts exact scalar operations,
not integer bit complexity, energy, wall time or hardware instructions.
The exact solver returns the same declared count; independent original
verification is authoritative.

## Baselines and bounded teacher

Compare original index order, greedy min-degree and greedy min-fill,
with stable vertex-index tie-breaking. The stronger of min-degree and
min-fill per example is a diagnostic *best-of-two* comparator, which is
not itself an executable selector without paying both searches. The
teacher performs globally optimal symbolic-order dynamic programming on
the 12-node graph for the declared operation proxy. Its search states and
wall time are separately reported and are excluded from the deployable
solve cost. Teacher results are reference labels only; do not claim a
practical win from paying an exponential search on these small graphs.

## Final audit and decision

Contract seeds begin 3,700,000. First final audit uses 24 new examples
per degree with seeds `3,710,000 + 1000*degree + i`, 48 total. All graph
and system signatures must be distinct. Freeze generator, solver,
ordering methods, evaluator and thresholds before the final audit. On
every example, exact answers from natural, min-degree, min-fill and
optimal orders must equal the known ground truth and verify all original
equations; the teacher's count must equal exact ordered-solver count
and not exceed either greedy count. No unsafe accepted answer.

Define headroom as `(best_greedy_ops - optimum_ops) / best_greedy_ops`.
`ORDERING_HEADROOM_VISIBLE` requires at least 8/48 systems with headroom
>=10%, at least two in each degree arm, plus all validity/freshness
conditions. Otherwise `SPARSE_ORDER_SATURATED`, or `INVALID_FAMILY` on
contract failure. Even a visible gap is only permission to preregister
a subsequent small learned orderer against min-degree, min-fill and a
topology-aware deterministic rule on a separate holdout graph mechanism.
No neural performance claim or cross-domain transfer is made here.

## Guardrails

Degraded mode for a future advisory learned order is verified baseline
solve on invalid order, nonpositive pivot or failed original check;
failed proposal/search work remains charged. No oracle-order labels at
inference. Do not conflate fill proxy, exact arithmetic count, search
time, full-path time and bit complexity. A learned component is deleted
if strong cheap orderers saturate the teacher, even if it predicts the
teacher sequence accurately.
