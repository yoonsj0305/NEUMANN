# v0.0.86 — Native warm-start comparator interface

Status: correctness interface only, 2026-10-01. No trained model, performance
audit, learning admission or Q3/Q4 pass. Base: PR #94 head
`87cf7565b51386dec4192ed5664702a90dd76b89` (v0.0.85).

## Hypothesis and one acceptance criterion

An equal-authority Direct comparator can supply a candidate basis to native
HiGHS simplex and let it repair an incorrect/singular proposal, rather than
discard it and restart through a cold SciPy wrapper. The criterion is original
primal/dual certificate acceptance on cold, optimal, nonoptimal and singular
basis fixtures, and fail-closed handling of malformed inputs, denied
certificates, infeasibility, unboundedness and budget expiry. This is a
correctness hypothesis, not a claim that warm starts are faster.

## Interface and accounting

`solve_native_checked(A,b,c,head=...,cold_fallback=True,budget_s=5)` accepts
only original observables and an advisory basis/abstention. It builds a fresh
HiGHS model for every attempt, with single-thread simplex, parallel off and
native presolve on. A valid typed head supplies m distinct original columns
through `setBasis`; equality-row logical variables are nonbasic at their fixed
bounds. No independent invertibility precheck withholds native repair.

Native optimal status alone is insufficient. Original coefficients and the
returned full primal/dual witness must pass the unchanged v081 numerical
verifier. Keep rejected witnesses and exceptions. If warm execution or
verification fails, a permitted cold attempt receives only the remaining
shared deadline. Invalid heads/abstention use the same paid cold degraded
mode when enabled. Budget overruns retain evidence but cannot be accepted.

Stage times include setup/conversion, basis supply, native solve and original
verification. Whole-call time also includes input validation, decoding and
failed attempts. Explicit call counters count native run, basis supply and
certificate invocations, including exceptions. These counters are not FLOPs.
The routine does not interrupt synchronous setup/verification at the deadline;
it rejects a late result. This is an acceptance budget, not an OS hard timeout.

Upstream basis proposal/model cost is outside this primitive and must be added
for any full model experiment. Cold dependency imports/model loads must also
be reported separately; callers should pre-import highspy for warm timing.
Fresh solver setup prevents hidden persistent-state reuse. A known/oracle basis
fixture is not a deployed predictor. Basis supply may affect native presolve;
the solver's actual behavior must be recorded in a future benchmark.

## Validation and limits

Focused tests use fresh-process real HiGHS integration to avoid scheduler
state contamination. The supplied optimal basis, a nonoptimal basis and a
singular basis are checked against the same original LP; native repair is
available equally to Direct and NEUMANN. Negative controls deny verifier
acceptance even after native optimal status, inject verifier exceptions, and
exercise infeasible/unbounded models. Fault fixtures retain both failed warm
and cold work, share the deadline, and reject late certificates. These tiny
fixtures establish interface behavior only. No benchmark speed ratio is
computed and no first timing archive is rerun.

First local focused run: 11 PASS on Python 3.12.14, highspy 1.15.1,
NumPy 2.3.5 and SciPy 1.17.0, single-thread environment. This differs from
the v082-v085 frozen audit runtime. It is correctness validation only, never
a timing replication or a replacement of their retained measurements.
The existing v085 focused replay also passed all 15 tests in this environment.

Install optional dependency: `pip install -e '.[native_lp]'`.
Run: `python -m pytest tests/test_lp_native_warm_start_v086.py -q`.
