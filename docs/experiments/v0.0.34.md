# v0.0.34 — Structural Baseline Gauntlet + Confidence Stopping

Status: pre-registered research specification

## Purpose

v0.0.33 showed that a frozen tiny learned scorer can rank useful compression candidates under an oracle-cardinality scaffold:

    proposal budget B = n - k

v0.0.34 removes that scaffold.

The system must now decide both:

1. which candidate reductions are promising,
2. when to stop proposing reductions.

The experiment also pre-registers a stronger deterministic baseline suite before reading v0.0.34 final results.

## Central questions

### Q1 — Does learned ranking still help against stronger deterministic structure heuristics?

The learned scorer is compared with deterministic baselines using the same candidate universe, calibration protocol, checker, and final corpus.

### Q2 — Can the learned scorer stop without receiving n-k?

The learned path uses a calibrated score threshold:

    propose candidate iff learned probability >= tau

No oracle k or n-k is supplied at final inference.

The number of proposals therefore varies by example.

### Q3 — Does certified compression remain useful after removing oracle cardinality?

Final metrics include:

- proposal precision / recall / F1 against the generator dependency reference,
- certified accepted eliminations,
- retained-dimension error,
- solver-operation reduction,
- full original-problem verified retention.

## Frozen learned scorer

The v0.0.33 learned scorer is reused without architecture, feature, or training-corpus changes:

- feature dimension: 16
- hidden units: 16
- tanh MLPClassifier
- random_state: 33
- same v0.0.33 training corpus
- same deterministic candidate feature contract

v0.0.34 does not increase learned capacity.

Only the stopping threshold is calibrated on the new v0.0.34 calibration split.

## New evaluation data

The affine-linear generator remains the v0.0.33 leakage-hardened family:

- generic variable names,
- randomized row order,
- randomized column order,
- affine dependency rules,
- chained dependencies,
- no fixed core/derived blocks.

v0.0.34 uses new deterministic seeds and forbids every exact full-system signature used by v0.0.33 train / validation / final.

Scale grid:

    k in {2, 4}
    n in {4, 8, 16, 32}
    n >= k

Per cell:

    calibration = 24
    final       = 32

The final set is never used to select thresholds.

## Candidate universe

The candidate enumerator is frozen from v0.0.33.

Each candidate is an exact row-target affine rearrangement permitted by the original equation.

Candidate enumeration itself does not decide whether the candidate should be used.

## Pre-registered scorer suite

Every scorer emits a confidence in [0, 1].

All methods use the same threshold grid and calibration objective.

### 1. Learned MLP

    score = v0.0.33 predicted positive probability

### 2. Deterministic pseudo-random control

A SHA-256-derived deterministic score in [0,1].

This is a repeatable chance-ranking control.

### 3. Target-leaf heuristic

Prefer a target variable that appears in fewer full-system equations.

    confidence = 1 - target_column_incidence / n

### 4. Row-sparsity heuristic

Prefer algebraically sparse dependency rows.

    confidence = 1 - row_nonzero_count / n

### 5. Sparsity + incidence heuristic

Frozen from the v0.0.33 post-result diagnostic:

    confidence =
        1 - 0.5 * (
            row_density
            + target_column_incidence
        )

### 6. Dependency-contrast heuristic

Prefer targets whose graph incidence is lower than the mean incidence of the variables they depend on.

Let:

    d_t = target column nonzero count
    d_dep = mean dependency-column nonzero count

Then:

    confidence =
        clip(
            0.5 + 0.5 * (d_dep - d_t) / n,
            0,
            1
        )

### 7. Markowitz-style heuristic

Use a sparse-elimination-inspired local fill proxy:

    M = (row_nnz - 1) * (target_column_nnz - 1)

and:

    confidence = 1 / (1 + M)

Smaller local elimination degree receives higher confidence.

### 8. Fixed structural-combo heuristic

No weights are tuned.

    confidence =
        0.35 * target_leaf
        + 0.35 * row_sparsity
        + 0.30 * dependency_contrast

The coefficients are frozen here before final measurement.

## Common stopping calibration

No method receives oracle cardinality at final inference.

Every method selects one global threshold from the same pre-registered grid:

    tau in {
        0.05, 0.10, 0.15, 0.20, 0.25,
        0.30, 0.35, 0.40, 0.45, 0.50,
        0.55, 0.60, 0.65, 0.70, 0.75,
        0.80, 0.85, 0.90, 0.95
    }

On the calibration split only:

1. score every candidate,
2. propose every candidate with score >= tau,
3. compare proposal keys with generator dependency reference keys,
4. compute global micro precision, recall, and F1.

Threshold selection:

    maximize micro F1

Tie-breaks, in order:

1. higher precision,
2. higher threshold,
3. deterministic numeric ordering.

The checker is not used to choose tau.

This prevents the threshold search from exploiting fail-closed checker behavior to simply propose everything.

## Final inference

For each final example and each method:

    score candidates
        ↓
    keep score >= calibrated tau
        ↓
    deterministic checker in descending-score order
        ↓
    safe accepted subset
        ↓
    retained solve
        ↓
    reconstruction
        ↓
    verify ORIGINAL full problem

There is no B=n-k cap.

## Deterministic authority

The v0.0.33 reduction checker remains unchanged in authority.

A proposed candidate is accepted only if the tentative set preserves:

- exact row algebra,
- unique removed rows,
- unique eliminated targets,
- acyclic reconstruction,
- square retained subsystem,
- exact retained solvability,
- exact reconstruction,
- verification against the original full problem.

False proposals may be rejected.

Unsafe accepted reductions must remain:

    0

## Reference terminology

The generator dependency DAG is a **reference certificate**, not assumed to be a globally minimal or unique compression.

A valid non-reference reduction is not automatically an error.

Therefore v0.0.34 separates:

- reference-rule recall,
- certified elimination count,
- certified retained dimension,
- solver savings.

Ratios against the generator reference may exceed 1 if a method finds additional valid reductions.

## Primary final metrics

For every method:

### Raw proposal quality before checker

- proposed candidate count
- micro precision
- micro recall
- micro F1
- false proposals on n=k controls

### Certified reduction quality after checker

- examples with any accepted compression
- mean accepted eliminations
- mean accepted reference eliminations
- mean accepted non-reference valid eliminations
- fail-closed rejection count
- unsafe accepted reduction count
- full verified retention

### Stopping / retained dimension

For each example:

    inferred retained dimension
        = n - accepted eliminations

Report against generator core k:

- mean absolute retained-dimension error
- mean signed retained-dimension error
- exact retained-dimension match rate

Because the generator reference may not be globally minimal, these are reference-relative diagnostics rather than absolute optimality metrics.

### Solver consequence

Report:

- baseline full-system solver arithmetic ops
- generator-reference compressed solver ops
- method compressed solver ops
- solver savings vs baseline
- fraction of generator-reference solver savings recovered

If a valid method beats the generator reference, savings recovery may exceed 1 and must not be clipped.

### Proposal cost

For learned scoring, retain the v0.0.33 learned weighted-sum proxy.

For deterministic heuristics, report candidate count and heuristic identity only.

Do not combine learned proxy, heuristic operations, checker work, solver work, or verification work into one synthetic total-compute number.

## Main comparisons

Primary descriptive comparisons:

1. learned vs deterministic random
2. learned vs frozen v0.0.33 sparsity/incidence heuristic
3. learned vs best pre-registered deterministic heuristic on the final set

The "best deterministic heuristic" is identified only after final evaluation and is descriptive.

No method-specific final threshold tuning is permitted.

## KEEP contract

KEEP means the v0.0.34 experiment is methodologically valid.

Required:

1. v0.0.34 calibration/final signatures are disjoint from all v0.0.33 signatures,
2. calibration and final signatures are mutually disjoint,
3. scorer formulas match this pre-registration,
4. all methods use the same threshold grid and selection rule,
5. final data are not used for threshold selection,
6. learned scorer capacity/features/training corpus remain frozen,
7. no final method receives k or n-k,
8. deterministic checker remains authoritative,
9. full original-problem verified retention is reported for every method,
10. unsafe accepted reduction count is zero for every method,
11. all scale cells are populated,
12. final aggregate is deterministic across repeated execution.

Not required:

- learned scorer beats every heuristic,
- learned retained dimension matches generator k,
- learned solver savings exceeds deterministic baselines,
- any total-compute win.

A heuristic win is a valid and important negative result for the learned-compression hypothesis.

## Claim boundary

A positive learned result would support only:

> under this generated affine-linear family, a frozen 289-parameter learned candidate scorer can use confidence-based stopping, without oracle cardinality at final inference, to identify a certified compression subset that may outperform the pre-registered deterministic heuristics tested here.

It would not establish:

- globally minimal structure,
- best possible heuristic superiority,
- domain-general Structural Compression,
- natural-language Structural Compression,
- end-to-end total-compute superiority,
- asymptotic complexity improvement.

## Decision rule for the next milestone

If learned stopping remains competitive with or exceeds the strongest deterministic heuristic:

    proceed to harder structural families
    and/or learned retained-dimension modeling

If a deterministic heuristic matches or beats learned scoring:

    preserve that result
    and treat the heuristic as the new baseline architecture.

NEUMANN should absorb the cheapest mechanism that works rather than defend learned components for their own sake.

## Interpretation

v0.0.34 changes the research target.

The previous learned-compression framing implicitly treated generator dependency recovery as the main learning objective.

The gauntlet shows that this proxy can be misaligned with the actual computational objective.

A method may match fewer generator-reference rules yet remove more expensive solver work.

The more appropriate hierarchy is now:

    valid reduction
        ↓
    verified original-problem equivalence
        ↓
    marginal computational utility
        ↓
    reference-certificate similarity

Reference recovery remains useful for diagnostics, but it should no longer be the primary optimization objective.

### Generator reference is not the unique optimum

Markowitz accepted a small number of non-reference but valid reductions:

- mean accepted non-reference valid eliminations: **0.0234 per final example**

At k=2,n=4 its mean generator-reference savings recovery exceeded 1.0.

This is allowed by the pre-registered terminology: the generator DAG is a reference certificate, not a proof of global minimality.

That observation further weakens the use of exact reference-rule matching as the central target.

## Final decision

**KEEP — v0.0.34 methodology and safety contract are valid.**

But the learned-compression hypothesis is narrowed.

The experiment does **not** justify treating the learned scorer as the preferred compression policy.

The strongest empirical lesson is:

> **The best predictor of a reference compression certificate is not necessarily the best policy for reducing verified computation.**

For the next milestone, NEUMANN should absorb the cheapest mechanism that works.

A natural v0.0.35 target is therefore **utility-directed Structural Compression**:

- freeze deterministic Markowitz / target-leaf baselines,
- measure marginal solver-work reduction per candidate,
- train or design policies against verified downstream computational utility rather than reference-rule labels,
- preserve deterministic checking and original-problem verification,
- include checker / reconstruction / verification costs explicitly before making any total-compute claim.

## Interpretation

v0.0.34 removes the v0.0.33 oracle-cardinality scaffold successfully.

The learned scorer can stop by calibrated confidence without seeing (k) or (n-k), and its raw proposal classifier remains substantially stronger than the pre-registered deterministic baselines at reproducing the generator dependency reference.

However, **reproducing the generator reference is not the same objective as minimizing verified computational work**.

A simple target-column leaf heuristic, despite much worse reference-rule F1, produces more downstream solver savings than the learned scorer.

This means the current learned objective is misaligned with NEUMANN's actual North Star.

The experiment therefore falsifies a tempting but incorrect design assumption:

> better oracle-rule classification necessarily implies better Structural Compression.

It does not.

The better architecture-level lesson is:

> candidate discovery, reduction authority, and compression utility should be separate primitives.

A proposal should not be rewarded merely because it matches a generator label. Its value depends on the **verified computational consequence** of accepting it.

### Why the generator reference is insufficient as a sole target

The generator dependency DAG is one valid certificate basis, not proven globally minimal.

v0.0.34 also confirms that certified non-reference reductions can exist.

Therefore future systems should distinguish:

1. **validity** — can this reduction be certified?
2. **utility** — how much verified downstream work does it remove?
3. **minimality / stopping** — is further safe reduction worth attempting?

These should not be collapsed into one binary label.

## Decision

**KEEP — with a research pivot inside Structural Compression.**

The v0.0.34 experiment is valid, reproducible, safe under the checker, and removes the oracle-cardinality scaffold.

But it does **not** support keeping learned candidate classification as the privileged core mechanism.

The cheapest mechanism that works should be absorbed.

For the current affine-linear family:

- deterministic structural heuristics are strong,
- one simple heuristic beats the learned scorer on the measured downstream solver-work objective.

### Recommended next milestone

v0.0.35 should be framed as:

> **Compression Utility / Value-of-Reduction**

Rather than asking only:

    Is this candidate an oracle dependency?

ask:

    If this certified candidate is accepted now,
    how much verified downstream computation is expected to disappear?

Pre-register at least:

- deterministic target-leaf / Markowitz baselines as first-class components,
- marginal solver-work reduction from each accepted candidate,
- checker / reconstruction / verification overhead,
- learned value prediction only if it can beat deterministic utility estimates,
- a greedy or search policy over certified marginal utility.

The research target becomes closer to:

    discover valid reductions
        ↓
    estimate verified computational value
        ↓
    choose reductions by utility
        ↓
    stop when marginal value no longer justifies cost

This is more faithful to Structural Compression than optimizing reference-certificate imitation.
