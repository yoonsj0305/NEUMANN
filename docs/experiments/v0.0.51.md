# v0.0.51 — External PACE ordering opportunity gate

Status: preregistration. Freeze this document, parser, ordering algorithms,
evaluator, and tests in a commit **before** the first full audit. No learned
model is trained here. The candidate interface remains `graph -> pivot order`;
an invalid order or failed downstream solve would degrade to the independently
verified baseline, charging all failed proposal work.

## Source and scope

PACE 2017 Track B's minimum-fill challenge published 100 public and 100
post-contest-released hidden graphs. Pin the official instance repository
`https://github.com/PACE-challenge/Minimum-Fill-In-PACE-2017-instances`
at `8cb56d0b9a832401713aa8c1456b619bf3e47ea2` (CC0 1.0). Parse all
`public/*.graph` and take **all 28** with 2–128 distinct endpoint vertices,
including 11 whose original density is below 0.20. Selection uses only graph
size, before viewing algorithm outcomes. Record each original file's SHA-256.
The repository README says vertex IDs are at least 1, but its actual files
include vertex 0; accept nonnegative IDs and record this source discrepancy.
Do not use any released `hidden/` graph in this opportunity audit: those 24
with n <= 128 remain a possible mechanism-level holdout, not a claim of
secrecy or untouched data after this report is public.

This is a *graph structural* experiment. PACE's official objective is number
of fill edges; NEUMANN's primary prospective execution proxy stays the v0.0.50
scalar-arithmetic count `d² + 6d + 1` per pivot. Report fill separately.
Neither is numeric wall-time, bit complexity, memory, energy, or contest rank.
The graph-to-SPD-matrix transformation and original-equation verification are
deferred to a separate downstream experiment; **do not assert verified
linear-system solutions or full-path advantage from this gate**.

## Fixed comparison

Map sorted external vertex labels to `[0,n)`. Count structural operations
and fill by bitset elimination and an independent set-based counter. Compare
deterministic min-degree and min-fill (index ties). The per-instance better of
these two is a **diagnostic** baseline, not a free deployable selector.

The bounded search makes 16 seeded min-fill restarts per graph, choosing
among the top three at each pivot with fixed weights 6:3:1. Seeds are the
first 64 bits of SHA-256 of `PACE-v051/{filename}/{restart}`. The best observed
cost includes both greedy baselines, so it can never degrade the structural
proxy. Search time for *all* proposals is reported and not omitted from a
future learned-model total-cost comparison. These are feasible upper bounds
on the optimum, not an optimal-order teacher. Never describe failure to find
a gap as proof that no gap exists.

## First and only full audit decision

Require 28 distinct file SHA-256 values, exactly 11 sparse cases, valid
permutations and independent reference equality for every evaluated order.
Define arithmetic headroom `(best_baseline_ops - best_bounded_ops) /
best_baseline_ops`. `BOUNDED_OPPORTUNITY_VISIBLE` requires **at least four
of 11 sparse graphs** to show >=10% improvement. Otherwise report
`NO_BOUNDED_OPPORTUNITY`, or `INVALID_CORPUS` for a contract failure. This
threshold only allows a future, separately preregistered learner investigation
using actual solves and proposal/fallback work. It does not promote a model.
Also report all 28 rows, dense cases, fill, and measured search time.

## Reproduction and limits

Clone the source repository at the pinned commit outside NEUMANN, then run
`python benchmark_v051.py --pace-root /path/to/checkout`. The checkout is
read-only; original PACE data are not redistributed here. CI runs independent
parser/counter/smoke tests without requiring an external network fetch.
No optimization or threshold may be changed after the first full audit based
on the observed rows. If the gate fails, stop this bounded approach rather
than inventing a favorable subset; a different external workload would need
a new question and preregistration.

## First complete audit (after preregistration commit `7f205cf`)

`docs/experiments/results/v051_first_audit.json` contains all 28 original
file hashes and every case. Independent bitset/set structural counters agreed
on all 18 evaluated orders per graph (two greedies and 16 restarts); all
permutations were valid. The 11 sparse graphs had mean arithmetic headroom
0.252%, median 0%, and **0/11** reached 10% (required: at least 4/11).
Only four sparse graphs improved at all: `11.graph` 0.679%, `13.graph`
0.730%, `31.graph` 0.562%, and `5.graph` 0.804%. The maximum across all
28 was 0.804%. Median two-greedy ordering search was 24.1 ms per graph;
the 16 additional restarts cost a further 196.4 ms median (local diagnostic,
not a portable timing claim). The per-instance best-of-two and best-of-18
are diagnostic comparisons; choosing the best order incurs the searches.

**Decision: NO_BOUNDED_OPPORTUNITY.** Do not train an orderer on these
near-greedy labels or describe them as a compute win. This is only a negative
result for this bounded 16-restart search and selected public subset; it
does not prove globally optimal orderings are close, nor that the remaining
PACE graphs or actual sparse matrix workloads lack headroom. No matrix was
solved in this iteration. The next credible experiment would need to replace
the objective/workload or provide an independently stronger search reference,
then measure end-to-end proposal, solve, and original-equation verification
against deployable deterministic ordering. Do not unlock the released hidden
graphs for training on the basis of this failed opportunity gate.
