# v0.0.14 — Static Installed-Package Discovery

## Question

Can NEUMANN discover manifests shipped by installed Python distributions without importing the plugin module?

## Convention

A distribution may ship one or more JSON manifests under a path segment named:

neumann_plugins/

Examples:

package/neumann_plugins/matching.json
neumann_plugins/custom_solver.json

Discovery uses importlib.metadata distribution file listings and reads matching JSON files directly.

It does not resolve the manifest entry point.

## Safety / robustness rules

- only JSON files under a neumann_plugins path segment are considered
- each manifest is limited to 64 KiB by default
- malformed manifests become DiscoveryIssue records
- one malformed distribution does not abort discovery of every other distribution
- duplicate plugin/family/kind conflicts remain hard failures when building a catalog
- discovery never activates plugin code

## Provenance

Each discovered manifest records:
- distribution name
- distribution version
- relative manifest path
- canonical manifest digest

## Important boundary

This is static package discovery, not package trust.

A malicious package is already installed code on the Python environment. Reading its manifest without import reduces accidental execution during discovery, but does not make installation itself safe.

Still missing:
