# v0.0.78 — Natural arithmetic program opportunity screen

Status: preregistered before local data analysis or training.

## Single question

Does the authors' SVAMP arithmetic-program workload contain enough executable
computational redundancy to justify a learned Structural Compression experiment,
after granting Direct the same short trusted arithmetic-program interface?
This is task admission, not a model experiment. NL parsing difficulty and
execution compression are separate. Zero learning will occur unless this
screen admits this bounded *numeric execution compression* target.

## Authority and fixed methods

At deployment a model may see only Body + Question. Equation, Answer, Type and
ID are reference/evaluation data and must never enter a model's features.
This screen uses Equation as a **non-deployable teacher-program diagnostic**;
it does NOT solve the raw word problem. Gold-answer agreement is dataset-label
agreement, not independent verification of natural-language semantic fidelity.

D0: bounded trusted AST arithmetic (+,-,*,/, unary +/-), exact rational leaves.
D1: exact common-subexpression sharing of identical AST subtrees; no value-based
folding to the answer, no commutative reordering, no solver/predictor advantage.
Both Direct and Structural would be allowed D1; it is a strong shared compiler
optimization, never an exclusive NEUMANN capability. A separately implemented
token/precedence parser checks the original expression's exact rational result.
Compare both outputs to the supplied label, reporting EXACT_MATCH, ROUNDING_ONLY,
LABEL_DISAGREEMENT and UNSUPPORTED separately; never silently drop a row.

Declare limits before audit: 512 expression characters, 127 AST nodes,
18 significant literal digits, rational numerator/denominator <=4096 bits,
no exponent, identifier, function, attribute, eval/exec or arbitrary code.
Report whether reference literal values occur in observable numeric tokens;
this is a provenance warning, not semantic verification or number-role binding.

## Fixed gate before any training

Require all of:
- 100% rows supported and independently expression-verified with exact label match;
- >=1/3 rows with >=20% arithmetic-operation reduction from D0 to shared D1;
- median D0 complete expression parse + exact execute + independent check >=1 ms.

The 1 ms floor is an engineering screening assumption, not a model inference
measurement. The gate excludes source parsing/model inference, so a pass only
justifies further investigation; it cannot be Q3/Q4. A failure stops *this
numeric-execution-compression candidate*, not all semantic/latent reasoning
compression, all SVAMP uses or the NEUMANN hypothesis.
The teacher-side repeated-subtree counts are upper-bound diagnostics about
this available optimization, not an oracle guarantee over every algorithm.

One untimed per-row correctness check and nine deterministic shuffled timed
passes (seed 7801); timing is charged for parse, execution and original-expression
checker, each row and pass retained. Do not replace the first audit by a faster
rerun. Check source SHA256, blob SHA and IDs; store all row hashes/counts/status,
all timing samples and environment. No peak memory/energy/$ claim.
Also report exact Body collisions with distinct verified program signatures;
this challenges only Body-only shortcuts, not every question-aware method.

## Degraded mode and next action

Malformed/unsupported or arithmetic budget failure -> UNKNOWN with recorded
reason; no successful summary ratio for rejected/unequal-capability rows.
If rejected, no model is trained on this numeric target. The next substantive
Q3/Q4 candidate must target residual *model discovery/planning* cost with an
actual same-budget executable Direct learner, shared optimized runtime,
no-compression ablation, held-out data and identical evaluation authority.
Do not select a weaker answer-only Direct route to manufacture a win.


## First local audit (preserved)

Preregistered local protocol commit: `0adac3a8b5b41ad4ec2449be112d1f1f151ddad5`.
Implementation fixed before the first measurement: `55aa55be612de73a0fe469f9d3205febc64326c5`.
Raw archive: `results/v078_first_audit.json`. No final rerun occurred.

- 1,000/1,000 reference equations supported; both implementations agreed exactly.
- 999/1,000 exact source-answer matches; one LABEL_DISAGREEMENT (`chal-680`):
  reference expression evaluates to 5 while the source Answer field is 1.
  This identifies an annotation disagreement, not which field matches the prose.
- Arithmetic-operation histogram: 0: 1 row; 1: 762 rows; 2: 237 rows.
- >=20% CSE gain: 0/1,000 rows; identical reference subtrees did not lower work.
- Nine repeats across both paths: all 18,000 expression-level runs verified.
- Per-row median, then corpus median: Direct 0.040462 ms, shared 0.041069 ms.
  These exclude raw-text semantic inference and are not model speed ratios.
- Exact-Body groups with distinct verified program signatures: 0 in this audit.
  This does not validate Body-only predictors or refute the paper's other tests.
- One row has a reference literal value not appearing in numeric observable tokens;
  six rows have duplicated literal values with unresolved role binding.
  Numeric-value occurrence is not semantic provenance or a sufficiency certificate.

All three numerical gate conditions failed. Frozen disposition:
`REJECT_SVAMP_NUMERIC_COMPRESSION_TARGET`.
No training, learned-parameter or model-level efficiency result follows.
Do not generalize the absence of CSE to every algebraic transformation, input
compression or latent semantic/reasoning compression. Keep this candidate out
of the runtime. A hand-written compiler for these reference expressions is
not a raw-natural-language solver.

## Consequence for Q3/Q4

The actionable bottleneck for a future natural-language pilot must be model-side
semantic discovery/planning, not executing these two-operation expressions.
Direct is permitted to emit the same compact arithmetic program and to use the
same shared CSE. Any proposed future architecture must expose actual inference
cost and equal observable inputs; answer-only Direct or exclusive tooling would
repeat the v0.0.31 comparison confound. Admit a new target before fitting a model.
Peak memory, energy, amortization and independently faithful NL verification
remain unmeasured. The proposed 1 ms screen was an assumption, not a measured
lower bound on every possible learner.
