# v0.0.58 — Existing-presolve workload triage

Status: descriptive, **nonblind** selection audit. The official source files
and `beasleyC3` were inspected before this evaluator was written. This is not
a performance preregistration, held-out sample, or NEUMANN compression test.

## Sources and interface

The [MIPLIB 2017 download page](https://miplib.zib.de/download) publishes
`raw_data.zip`, with original and after-**trivial**-presolve features. Its
README describes these as raw selection data with NaNs, rounded columns and
duplicates. The [official benchmark set](https://miplib.zib.de/set_benchmark.html)
contains 240 instance names. The code joins the two feature tables by the
instance basename, validates all 5,718 source rows and the 240 unique names,
and pins the downloaded archive and HTML bytes by SHA-256. Counts reported
by the raw feature files may be rounded for large instances. We use only
the variable count, constraint count and aggregation-row count for triage;
no objective or solution quality is inferred from them.

The [beasleyC3 source page](https://miplib.zib.de/instance_details_beasleyC3.html)
identifies a fixed-cost network-flow instance with 2,500 variables, 1,750
constraints and 5,000 nonzeros. A separate hash-pinned original MPS is read
by HiGHS 1.15.1. The optional probe calls its native presolver and records
the reduced model shape. It neither solves nor postsolves the instance.
Original MPS and MIPLIB raw source files remain outside the repository.

## Observations

| Official benchmark set | Count |
| --- | ---: |
| Matched benchmark instances | 240 |
| Unchanged variable count after trivial presolve | 104 |
| At least 50% fewer variables after trivial presolve | 20 |
| Median fraction removed by trivial presolve | 0.0604% |

The metadata-only shortlist is defined as 1,000–10,000 original variables,
at most 10,000 original constraints, at least 100 labeled aggregation rows,
and at most 10% variable removal under **trivial** presolve. Nine names meet
these thresholds: `n5-3`, `nu25-pr12`, `neos-3083819-nubu`, `beasleyC3`,
`milo-v12-6-r2-40-1`, `mcsched`, `uct-subprob`, `n9-3`, `binkar10_1`.
These thresholds were selected after inspecting source features and have
no statistical or performance-gate meaning. Duplicate/similar model groups
and the selection process prevent treating 240 rows as independent samples.

For `beasleyC3`, MIPLIB's trivial presolve keeps 2,471/2,500 variables.
HiGHS's stronger native presolve instead keeps **1,704/2,500** variables,
**1,153/1,750** constraints and **3,408/5,000** nonzeros: it removes 796
variables (31.84%) without any NEUMANN reduction. The 1,704 retained
variables are not a measured opportunity: we have not established that any
of them can be safely deleted or that a separate reduction could outperform
HiGHS on a verified complete path.

## Decision and next gate

**Do not use original-minus-trivial-presolve variable count as a headroom
estimate.** It substantially exaggerates the unexplored opportunity on the
one inspected native-presolver instance. A future numerical experiment must
start from an independently specified and checkable reduction witness,
measure the full path (discovery, checking, translation, solution,
reconstruction and original-model feasibility/objective), and compare to
HiGHS with its own presolve enabled. It must preserve the original integrality
and numerical acceptance contract. If the native presolver already captures
the witness, delete the extra path. Failure of one solver or one instance
does not imply a general impossibility result.

Reproduce the selection and optional native probe with:

```sh
python benchmark_v058.py --raw-zip /path/to/raw_data.zip \
  --benchmark-html /path/to/set_benchmark.html \
  --beasley-mps /path/to/beasleyC3.mps.gz \
  --output docs/experiments/results/v058_miplib_presolver_screen.json
```

`highspy==1.15.1` is needed only for the optional probe; it is not an
NEUMANN runtime dependency. `results/v058_miplib_presolver_screen.json`
records each of the 240 source feature counts, the shortlisting fields,
the three SHA-256 values and the native-presolve shape.
