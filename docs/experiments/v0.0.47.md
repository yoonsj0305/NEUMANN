# v0.0.47 — Row-overlap impossibility boundary

Status: pre-registered before implementation and final audit. This is a
contract and negative-control experiment, not a new compressor or a learned
model. Keep F1/F2/F3 frozen.

## Claim and assumptions

Let the active residual be a nonsingular square matrix after valid local
eliminations. A sparse candidate pair is eligible only when exactly two
distinct active target columns have support equal to the same two active
rows, as in F3. Two distinct eligible candidate pairs cannot share one row:
their four distinct target columns would be supported on at most three
rows and hence be linearly dependent. A target cannot belong to two pairs
because its active support is unique. This claim is conditional on residual
nonsingularity and the exact-two-row support criterion. It says nothing
about dense Schur candidates, approximate systems or rectangular systems.

## Contract and audit

Implement a small support-pair analyzer independent of F3's heap. For a
square integer matrix, identify support pairs with exactly two target
columns and nonsingular 2x2 pivot, then classify whether any two pairs
share a row. Check exact rank using rational elimination, not floating
point. A row-overlap fixture has four columns supported in three rows; it
must have rank less than four, even though each local 2x2 pivot is valid.
Repair the fourth column by adding support in a fourth row; the matrix
must become full-rank while the second pair ceases to be eligible. A
disjoint-pair fixture must be full-rank with both pairs eligible. Run 128
fresh seeded integer variants of each of these three arms (384 total),
with distinct matrix signatures. Contracts use separate seeds. The result
file records the first and only complete audit, arm counts, rank, eligible
pairs and overlap. No oracle labels enter the analyzer.

PASS requires 128/128 in each declared arm: the overlap arm is singular
with two individually valid overlapping pivot pairs; repaired arm is
nonsingular with exactly one eligible pair; disjoint arm is nonsingular
with two eligible disjoint pairs. Every audit signature must be unique.
Any failed assertion is a boundary counterexample to investigate, not an
invitation to adjust the generated examples after seeing the audit.

## Consequence and scope

If PASS, delete “overlapping eligible cached pairs in a nonsingular exact
residual” as a target for the next F3 benchmark. This does not prove that
all heap invalidation paths are unreachable; a candidate may become
eligible after another elimination or other inputs may violate these
assumptions. Next useful gate is a new problem family where the fixed
dense-abstention rule is not trivially sufficient, with an explicit
learned-vs-deterministic comparison, full-path cost and degraded fallback.
