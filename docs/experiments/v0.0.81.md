# v0.0.81 — Certificate-first LP verification contract

Status: enabling contract only. No model is trained and no performance gate is
claimed in this version.

## Why this version exists

v0.0.80 showed that an independent checker can erase nearly all apparent
planning headroom when the checker simply resolves the original task.  The
next task therefore needs a witness whose validity is independently checkable
without repeating the expensive optimization.

This version fixes one such contract for the standard-form linear program

```
minimize      c^T x
subject to    A x = b
              x >= 0
```

with primal/dual certificate `(x, y)`.

The verifier accepts only when the original coefficients satisfy, within the
frozen numerical tolerances,

```
A x = b
x >= 0
A^T y <= c
c^T x = b^T y
```

and it also reports complementary slackness as a diagnostic. Primal and dual
feasibility plus equal objectives are the optimality authority; complementarity
is deliberately not a second acceptance gate because approximate feasible
certificates can accumulate the same floating-point error in a different form.
The verifier
does not call HiGHS, `linprog`, a reduced solver, a gold-answer lookup, or a
hidden planted certificate.

## Fixed numerical boundary

The prototype uses IEEE-754 float64 and

- absolute tolerance: `1e-8`
- relative tolerance: `1e-8`

with componentwise backward-error scaling recorded in every result. Equality
residuals are normalized by |A||x|+|b|, dual-feasibility residuals by
|A|^T|y|+|c|, and the primal/dual objective gap by the magnitude of the two
original objective evaluations. This is an engineering numerical certificate,
not a formal rational proof. A future claim outside this numerical regime
requires a separate protocol.

During pre-merge hardening, an exploratory 128x8192 constructed LP exposed a
false rejection from the earlier global residual scaling even though HiGHS
reported an optimum. That observation is **not** a performance result and is
not part of a frozen audit. It motivated the componentwise backward-error
contract before any v0.0.82 timing data were collected.

## What is tested

`tests/test_lp_certificate_v081.py` checks:

1. a constructed primal/dual optimum is accepted;
2. a HiGHS-produced candidate is accepted only after the independent
   solver-free verifier checks the original LP;
3. monkey-patching `scipy.optimize.linprog` to fail does not affect the
   verifier, demonstrating that verification does not silently re-solve;
4. primal equality, non-negativity, dual/objective and malformed-certificate
   faults fail closed;
5. a cancellation-heavy equality checks residuals against original dot-product
   scale rather than only the small right-hand side;
6. shape, non-finite and invalid-tolerance inputs are rejected.

`benchmark_v081_smoke.py` is only a bounded integration smoke.  It contains no
timing threshold and must not be cited as efficiency evidence.

The planted fixture is test authority only.  It is opened development data and
must never become inference input, a future performance label, or a production
verifier.

## Complexity boundary

For sparse `A`, certificate checking consists primarily of `A @ x` and
`A.T @ y` plus vector scans, so its algorithmic work is proportional to the
original sparse matrix representation, `O(nnz(A) + m + n)`.  That is an
operation-count statement, not a measured wall-clock, energy or memory claim.

The direct and NEUMANN paths must pay the same original-certificate check.
A future compressed route does not get to verify only the reduced problem.

## Prior-art boundary

Learning or predicting an LP basis is not a NEUMANN novelty claim. Two direct
predecessors are:

- Fan et al., *Smart Initial Basis Selection for Linear Programs*, ICML 2023:
  https://proceedings.mlr.press/v202/fan23d.html
- Lu and Yan, *Learning Initial Basis Selection for Linear Programming via
  Duality-Inspired Tripartite Graph Representation and Comprehensive
  Supervision*, ICML 2025:
  https://proceedings.mlr.press/v267/lu25q.html

Both motivate strong learned-basis comparators for any later Q3/Q4 experiment.
A future positive result therefore cannot be reported as "learning the basis is
new." NEUMANN must instead test whether a structure/certificate path reduces
complete verified compute against strong deterministic and learned direct
routes under matched authority and training budgets.

## Next gate: v0.0.82

Before training any active-set or basis predictor, run a non-deployable
zero-model headroom screen:

1. freeze fresh standard-form LP instances and a strong HiGHS Direct path;
2. give a diagnostic oracle the optimal basis/support for free only to measure
   the maximum plausible structural-compression headroom;
3. reconstruct a full primal/dual certificate and run this exact original-LP
   verifier on every path;
4. charge basis-system solve, reconstruction, verification and all failures;
5. reject the target before training unless the oracle-compressed complete path
   clears the predeclared cost gate against Direct.

Even a positive v0.0.82 would establish only mechanism headroom.  Q3 would
still require learned discovery to beat cheap deterministic basis/active-set
tests, and Q4 would require a matched runnable Direct learner, a no-compression
ablation, equal training authority and complete cost accounting.
