# v0.0.62 — Residual motif screen after native MIP presolve

Status: **descriptive, nonblind opportunity screen**. All three source names
and their original/native shapes had been inspected in v0.0.58–61. The
motifs and screening decision were selected after exploratory inspection.
No paired timing, new compression rule, holdout or solver advantage is
claimed. This is a way to delete weak candidate work before implementation.

## Interface and method

Read three hash-pinned original MIPLIB MPS files locally with HiGHS 1.15.1,
one thread. Record the original `HighsLp`, call native `presolve()`, then
inspect `getPresolvedLp()`. Count finite equality rows containing a
degree-one continuous column, exact identical columns including row indices,
coefficients, objective coefficient, bounds and integrality, and connected
components of the row/column incidence graph. Report component row/column/
nonzero/integer counts. These are **structural counts only**: the presolved
model's columns are internal to HiGHS and no original solution is generated
or reconstructed. Original MPS files remain outside the repository.

`benchmark_v062.py` verifies SHA-256 before reading each source and writes
`results/v062_residual_motifs.json`. Reproduce with:

```sh
python benchmark_v062.py \
  --beasleyC3 /path/to/beasleyC3.mps.gz \
  --n5-3 /path/to/n5-3.mps.gz \
  --binkar10-1 /path/to/binkar10_1.mps.gz \
  --output docs/experiments/results/v062_residual_motifs.json
```

## Observations

| Instance | Original variables | Native presolved variables | Equality leaf rows after native | Exact duplicate columns after native | Components after native |
| --- | ---: | ---: | ---: | ---: | --- |
| `beasleyC3` | 2,500 | 1,704 | 0 | 0 | one 1,704-column component |
| `n5-3` | 2,550 | 2,139 | 0 | 0 | one 2,128-column component and five tiny components totaling 11 columns |
| `binkar10_1` | 2,298 | 2,013 | 728 | 0 | one 2,013-column component |

`beasleyC3` has no detected instance of these three simple motifs after
native presolve. `n5-3`'s five small components have 1 row each and 2–3
integer columns; they account for 11/2,139 presolved columns (0.514%).
Separating them in Python would incur detection, model transfer, multiple
solves, reconstruction and original verification, none of which is justified
by this incidence count. This does not establish whether HiGHS already
exploits these components internally. `binkar10_1` retains 728 equality
leaf rows after native presolve, but the tested affine route on its original
LP and MIP is slower in v0.0.59 and v0.0.61; a residual count cannot reverse
those measured decisions.

Decision: **NO_SIMPLE_RESIDUAL_MOTIF_CANDIDATE** for a new reducer on these
three already inspected instances. Do not build a generic leaf, duplicate
column or component splitting path from this screen. The unexamined
structures, larger components and other problem families remain open.

Next gate: obtain an independently specified workload where a structure
witness is available **at the problem interface**, with a declared verifier
and a strong native solver baseline. Before coding a reducer, show what
native presolve leaves, why the witness is safe, and which complete-path
operation it could remove. Freeze a capability and cost protocol on a fresh
instance family before measuring a speed claim.
