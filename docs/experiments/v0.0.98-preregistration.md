# v0.0.98 — Fresh Q34 holdout preregistration

## Purpose

v0.0.97 admitted exactly one Pareto development survivor: the frozen
`B_POINT` support system using the two v0.0.88 `point16` checkpoints.
v0.0.98 tests that unchanged system on newly generated, separately registered
cases that have never been used for fitting, model selection, architecture
selection, threshold selection, or the v0.0.97 tournament.

No new model fit, checkpoint selection, support-factor tuning, fallback tuning,
or Q34 threshold change is permitted.

## Two-phase holdout discipline

The holdout is separated into two irreversible phases.

1. **Registration phase**
   - generate and byte-freeze the new inputs and independently certified oracle
     labels;
   - no model checkpoint is loaded;
   - no B_POINT inference, Direct timing, Oracle timing, or route comparison is
     executed;
   - commit the gzip source archive and SHA256 manifest.

2. **Evaluation phase**
   - start only from the committed source archive;
   - restore the already-frozen v0.0.88 point16 checkpoints;
   - run Direct, Oracle and both B_POINT seeds exactly once under the timing
     protocol below;
   - preserve the complete first result byte-for-byte.

A setup/invocation failure before any holdout observation must be retained as an
invalid attempt and may be corrected only at the infrastructure boundary. It
must never authorize changing cases, routes, thresholds or checkpoints.

## Fresh source set

Exactly 24 cases, fresh seed base `98200`.

- `iid64`: 12 cases, rows=64, cols=1024, alternating condition number
  1 / 1000, no surface transformation, seeds 98200..98211.
- `size_surface_shift128`: 12 cases, rows=128, cols=2048, alternating
  condition number 1 / 1000, signed row permutation + positive column scaling,
  seeds 98212..98223.

All use the same width-factor-16 planted LP generator lineage as v0.0.88.
The shift group changes size and surface representation, not the planted
generative mechanism. Therefore even a pass remains a constructed-family
mechanism result, not natural/domain generalization.

Oracle labels are created only for source certification and the nondeployable
Oracle reference. B_POINT proposal code receives only A,b,c.

## Frozen routes

- `DIRECT`: full native solve + original-LP verification.
- `ORACLE`: exact certified support supplied for free to the same restricted
  native executor + original-LP verification.
- `B_POINT_s87001`
- `B_POINT_s87002`

Each B_POINT route:
CG5 observable features -> frozen point16 ranking -> top2m support ->
restricted native solve -> original-LP verification -> charged Direct fallback
if required.

Fallback is part of NEUMANN and is fully charged. A fallback-free result is
reported but is not a separate hard requirement.

## Runtime and timing

Exact retained LP runtime:
Python 3.12, NumPy 2.3.5, SciPy 1.17.0, torch 2.14.0+cpu, highspy 1.15.1.
OpenBLAS core HASWELL and numerical/model thread counts = 1.

For each route/case:
- 1 warmup;
- 3 retained timed repetitions;
- serial deterministic shuffled order, seed 98991 + repeat;
- 5 second complete-path deadline;
- proposal timer begins before CG5 feature construction;
- post timer includes restricted execution, original verification, every failed
  attempt and full fallback;
- learned discovery additionally charges
  `(v088 training_setup_ms + own point16 fit_ms) / 10000` per query;
- checkpoint restoration and source decoding are reported as setup costs and
  cannot rescue or fail this per-query gate.

No energy, peak-memory, natural-workload or cross-domain claim is made here.

## Q34 fresh gate

Compute medians across the 3 retained repetitions per case, then aggregate
costs before ratios exactly as v0.0.97:

`S_oracle = sum(C_D - C_O)`

`S_candidate = sum(C_D - C_post)`

`utility_recovery = S_candidate / S_oracle`

`discovery_burden = sum(C_proposal + C_fit_amortized) / S_candidate`

`complete_ratio = sum(C_proposal + C_fit_amortized + C_post) / sum(C_D)`

A seed/cell passes only if:

1. every retained observation has an original-LP-verified answer;
2. `S_oracle > 0` and `S_candidate > 0`;
3. utility recovery >= 0.80;
4. discovery burden <= 0.20;
5. complete ratio < 1.00.

The conjunction is required independently for:
- each seed on `iid64`;
- each seed on `size_surface_shift128`;
- each seed on all 24 cases combined.

Thus one favorable group cannot hide failure in the other.

## Decision

If every cell above passes:

`Q34_FRESH_HOLDOUT_PASS_ADVANCE_Q5`

Freeze this LP B_POINT mechanism and stop local Q3/Q4 architecture tuning.
Advance to Q5 scaling/cross-domain tests.

Otherwise:

`Q34_FRESH_HOLDOUT_FAIL_NO_Q5`

Do not tune on the holdout. Return to a higher-level representation/objective/
task-family decision rather than fitting against these 24 cases.

Even a pass means Q34 is sufficient **for this constructed LP mechanism** to
advance to Q5. Global/general Q3 and Q4 remain analytically OPEN.
