## Interface and matching

`neumann1.matched_cost_v079` supplies `Case`, `Path`, `Protocol`, `Verification`,
`measure` and `summarize`. `Case` contains an evaluation ID and observable
text only. A proposer receives just text, never the Case or an answer field.

Required roles: deterministic Direct, answer Direct, executable-program
Direct, NEUMANN, and NEUMANN without compression. Learned routes declare
the same training-data reference, example count and budget reference.
The ablation declares the same representation contract. Actual model/code
and checkpoint references must be supplied by the next experiment; these
five role names are not runnable models or an admitted task by themselves.

Every role uses the same supplied synchronous executor and verifier objects.
Proposal time includes all route-specific parsing, tokenization, model
inference, reduction and certificate preparation. The shared executor must
check reductions and reconstruct results where applicable. Original-task
verification is a separate shared callback. Attempts run serially in a
seeded shuffled schedule, with every case/role/repeat retained.

Warmup, hardware, runtime, verifier and protocol references are explicit.
No implicit warmup or training is performed. Cold load, training and teacher
generation milliseconds are declared separately. Callers must include failed
training and rejected teacher work in investment declarations and retain logs.
Reports preserve path declarations, corpus IDs, schedule parameters, stage
and total wall times, errors, and per-attempt verifier scopes.

## Failure and verification

Verifier scopes distinguish original-task verification, dataset-label match,
expression-only checking, rejection and unknown. Only original-task verification
counts toward the default exact capability tally. A non-original result can
trigger the same deterministic Direct fallback across learned routes; both
attempts stay charged. Callback exceptions are UNKNOWN; failed stage time is
retained. Incomplete capability never produces an iso-capability speed ratio.

Summaries reject missing/duplicate observations, differing input hashes,
contract/model/cost drift, invalid times, truncated stage sequences, deleted
fallback work, and totals smaller than component times. The reference is the
lowest whole-workload mean of the three Direct paths, not a per-case fastest
route oracle. A separate no-compression ratio is reported. All five routes
must attain full recorded capability before either ratio is produced.

Incremental training break-even is positive extra NEUMANN training plus
teacher investment divided by positive per-query savings against that Direct
path. Nonpositive savings have no positive break-even. This is warm workload
arithmetic, not an energy/$ or cold-start result. Peak memory is unmeasured.

## Trust and statistics

Python callback bodies are trusted. The interface does not sandbox them,
inspect model features, enforce actual training compute, prove equal hidden
tool access, verify declaration source hashes, or establish semantic
independence. Text-only arguments avoid accidental exposure through this
interface; callbacks could still close over hidden data. ORIGINAL_TASK is
caller metadata, not a proof simply because an enum exists.

The next real experiment must audit these facts and supply original-task
evidence, immutable protocol/checkpoint references, matched hardware and
sealed independent data. Summaries are descriptive arithmetic means, with
no confidence bounds, seed variability or statistical acceptance decision.
Q3/Q4 stay OPEN in every output, including successful fixtures. Fabricated
times test ratio arithmetic only; they are never archived as model measurements.
