# v0.0.28 - Tiny neural structural proposer contract

## Question

Can NEUMANN replace the linear/logistic proposal heads with a genuinely nonlinear learned proposer while preserving the same deterministic authority boundary and the same auditable cost vocabulary?

v0.0.27 measured the current TF-IDF + logistic proposer.

v0.0.28 adds a deliberately tiny neural alternative:

    TF-IDF features
      -> 4-unit ReLU hidden layer
      -> open-set / family output
      -> deterministic compiler gate
      -> deterministic solver
      -> deterministic verifier

This is the first nonlinear learned proposer in the NEUMANN measurement track.

## Why this is a separate milestone

The project should not jump directly from logistic regression to an LLM and then attribute every observed difference to "structural intelligence."

A smaller controlled step lets us ask:

1. does the measurement contract survive a nonlinear model?
2. does the neural proposer preserve known-task quality?
3. does it change proposal-layer false routing?
4. how much fitted model state and weighted-sum work does it actually add?
5. does exact proposal reuse still amortize learned inference work?

## Architecture

The neural model has no solver authority.

Its output is only a family proposal.

A proposal becomes executable only when the deterministic family compiler independently accepts the original raw text and emits the same family.

Therefore:

    neural proposal != solver-ready authority

## Cost accounting

For the neural proposer, report:

- TF-IDF input feature dimensions
- MLP layer shapes
- fitted MLP weight and bias scalar count
- TF-IDF IDF-state scalar count separately
- sparse active input features
- executed stages
- weighted-sum term proxy
- diagnostic wall-clock time

The weighted-sum proxy counts:

- first layer: nonzero input features x hidden units
- later layers: dense weight-matrix terms

It excludes:

- bias additions
- activation operations
- TF-IDF vectorization work
- probability conversion
- CPU instructions
- memory traffic
- cache effects
- hardware energy

It is therefore not a FLOP or joule measurement.

## Baseline

The v0.0.27 TF-IDF + logistic proposer is measured on the same final corpus in the same benchmark.

This lets v0.0.28 report:

- model parameter ratio
- learned arithmetic-proxy ratio
- proposal false-route difference
- compiler-gated false-route difference

## Pre-registered KEEP gate

Using the existing training, validation, and final corpora:

1. neural validation known coverage = 1.0
2. final known proposal coverage = 1.0
3. final known family accuracy = 1.0
4. deterministic compiler acceptance on known tasks = 1.0
5. deterministic end-to-end verified coverage = 1.0
6. unsupported final false-route rate after compiler gate = 0.0
7. all measured neural items have positive weighted-sum proxy
8. repeated neural proposal decisions are stable
9. 8 exact repeated uses produce an 8.0x weighted-sum reuse factor

Not a KEEP condition:

- neural model being cheaper than logistic regression
- neural model having fewer parameters
- lower wall-clock latency
- zero proposal-layer false routes
- any LLM, GPU, token, memory, or energy claim

A more expensive neural proposer that preserves the contract is still a valid result. It tells us that nonlinearity alone does not create compute efficiency.

## Boundary and next step

This MLP is neural, but it is still not a language model. It consumes TF-IDF features rather than learned token embeddings.

The next milestone should introduce a direct learned task-solving baseline or a genuinely token-based small model under the same quality and cost contract. That is where NEUMANN can begin testing whether structure-first computation beats a learned system asked to solve the task directly.
