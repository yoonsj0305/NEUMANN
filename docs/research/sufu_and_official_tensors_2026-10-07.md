# NEUMANN 1: 구조적 계산 절약의 강한 비교와 원본 증거 검증

2026-10-07. **압도적인 총비용 우위와 학습된 새로운 지능 메커니즘은 아직 입증되지 않았다.**
동결한 North Star, Q1~Q7, 기존 실패 판정과 Decision 3 봉인은 유지한다.
이번 공개는 코드·실험 계약·독립 감사 결과의 백업이며 G0/G1/G2 통과 선언이 아니다.

반올림 차이를 허용하는 상대오차 검증이며 IEEE bit identity를 주장하지 않는다.

## 선행연구와 원본 자료 재사용

[SuFu 공식 구현](https://github.com/jiry17/SuFu)의 revision
`c2b3ff0637460c568b0533f992007278f88d0f55`를 고정했다.
1,953개 파일을 Git blob과 대조해 보존했다. 저자 알고리즘 수정 없이 설치 경로와
Jsoncpp include/library 경로를 별도 build repair 계약으로 변경했다.
빌드 실패·수정 빌드·실행 바이너리·표준 출력·등록 입력의 첫 증거를 각각 보존했다.
Gurobi 유료 기능은 사용하지 않았고 `use_gurobi=false`를 고정했다.
최상위 코드 재배포 license를 확인하지 못했으므로 이 저장소에는 SuFu 원본을 vendoring하지 않는다.

[Einsum Benchmark 공식 자료](https://zenodo.org/records/11477304)의 551,789,940바이트
원본 ZIP과 168개 member를 로컬에 보존했다. ZIP SHA-256은
`b65e9f8f80d27346442479311dbc295f29834481c3a07cb8cc7a438b8adbb82a`다.
`pickle.load`를 실행하지 않고 opcode를 비실행 자료구조로 읽었다. GLOBAL/REDUCE/BUILD는
함수 실행 권한을 얻지 않는다. 숫자 dtype whitelist와 shape/byte 검사를 통과한 배열만 사용한다.
제공 경로와 checksum은 O 권한이고 public worker에는 equation/shapes만 전달했다.

최초 metadata 읽기는 163개 완료·5개 memo budget 거절이다. 그 첫 기록은 유지한다.
별도 고정 예산(8M opcode, 2M memo) 복구는 4개 완료·1개 거절로, 누적 목록은 167개다.
복구된 사례는 78,784~230,848개 operand여서 원래 128개 선별 상한을 초과한다.
기존 30개 비교의 선별이나 결과를 소급 변경하지 않았다.
수백 MB의 metadata 보고서는 로컬에 남기고 공개 저장소에는 작은 요약과 해시를 넣었다.

## 실패와 복구를 구분한 기록

최초 C++ 어댑터는 operator 초기화 누락으로 183개 모두 실패했다. 다음 어댑터는
AddressHolder 소유권 문제로 183개 모두 실패했다. 두 첫 실행은 삭제하지 않았다.
소유권 수정 어댑터의 별도 실행에서 179쌍이 완료됐다. 수치 예외 48행은 정답 일치로 세지 않았다.
저자 최종 verifier와 같은 산술 크기 제한 50,000을 적용했다. 일반 overflow 안전성 증명이 아니다.

남은 4쌍은 저자 출력기의 상호 재귀 datatype 표현을 저자 입력 문법의 `with`로
연결했다. term body, 파싱된 AST와 erased type signatures가 동일함을 확인했다.
첫 수정 전송은 CRLF를 저자 lexer가 거절해 4개 모두 실패했다. LF 전송을 별도 등록한
복구에서 4쌍·276개 원본/변환/기대 출력이 일치했다. 원래 179/4 판정은 그대로다.

이전 OCaml 5.0.0의 26개 실행은 당시 화면 결과가 있었으나 ZIP을 로컬로 받기 전에
세션이 유실됐다. 그 최초 실행을 독립 감사 완료라고 바꾸지 않는다. OCaml 4.14.1
새 환경에서 동일한 26개 입력 뷰를 별도 등록해 복구했다. 7,818개 원본/변환/기대 출력이
일치했고 바이너리·compile/run 로그를 포함한 370개 통합 복구 파일을 로컬에서 확인했다.
20개 원본 byte group, 11개 공개 AST이므로 26개 독립 문제로 세지 않는다.
생성한 유한 OCaml fragment의 검증이며 원래 전체 OCaml protocol이나 모든 machine-int 증명이 아니다.
서로 다른 환경의 3.108초와 이전 시간을 속도 개선으로 비교하지 않는다.

## 학습용 자산과 현재 연구 경계

원본 public 함수형 입력 290개, 제공 변환 203개(미검증 partial 20개 포함),
검증된 반례 373개, 모든 290개 최초 실행 결과를 H/D/F/O 권한으로 분리했다.
최초 인덱스는 원본 SHA를 ID로 사용해 동일 byte 5그룹이 충돌했다. 첫 인덱스와
그 오류는 보존하고 별도 인덱스에서 290개 실행 ID와 285개 exact byte group을 분리했다.
모든 payload byte는 그대로이며 3,219개 금지 역할/용도 조합을 loader에서 거절했다.
이 검사는 API 권한 검사이며 운영체제 수준 격리나 일반 수학적 동치 분류가 아니다.

새 관점 생성 학습 모델은 아직 구현·훈련하지 않았다. 지금 있는 생성기는 알려진
기호 연산과 검증기의 개발 기반이다. 기존 데이터가 fresh holdout이 되지 않는다.
현재 결과로 텐서 경로 선택이나 기존 재귀 요약에 GPU를 투자할 근거가 생기지 않았다.
다음 진입 판단은 새로운 구조의 검증 가능한 계산 여유와 강한 기존 방법 이상의
학습 가치를 보여야 한다. 작은 모델 정확도 개선이나 기존 solver 포장을 돌파구로 부르지 않는다.

## 공개한 검증 자료

[공개 증거 목록](../experiments/results/structural_evidence_2026_10_07/publication_manifest.json)에
독립 감사 보고서, 동결 계약, 로컬 원본 ZIP의 SHA-256/크기를 연결했다.
실행 ZIP, 원본 dataset, 모델 가중치와 외부 무허가 소스는 로컬 `Continuation/`에 있다.
따라서 Git checkout만으로 외부 원본이 자동 제공되는 완전 재현 패키지는 아니다.

새 코드 관련 테스트 40파일·387개가 Windows Python 3.12에서 통과했다.
전체 pytest 수집 시 기존 Linux `resource` 모듈에 의존한 4파일은 Windows에서 실패했다.
이를 통과했다고 기록하지 않았다. Linux CI에는 recursive/tensor optional dependencies를
추가했다. GitHub CI 완료 여부는 별도 확인해야 한다.
