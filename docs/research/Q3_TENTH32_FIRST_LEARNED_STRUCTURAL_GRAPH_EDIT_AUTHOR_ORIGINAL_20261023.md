## Why this is mechanistically DIFFERENT from prior #548

In [PR #548](https://github.com/yoonsj0305/NEUMANN/pull/548), the little MLP learns which primitive operators `CUBE, SIN, LOG` etc to rank, but the two-branch AST shape and local OMP fitter were fixed human code. **New PR #549 trains the neural conditional preference over real graph structure ACTION TYPES**, with legal actions:

`ADD_BRANCH` (connect a second feature via addition), `MULTIPLY_BRANCH` (connect two feature macros via multiplication), `COMPOSE_UNARY` (wrap a given macro in a new unary operation), `RATIONAL_REWRITE` (define a rational program), `REUSE_BINDING` (load a named lambda previously discovered and source-verified in independent numeric training).

These typed action **semantics, primitive atom catalog and local fitting/numerical source verifier** remain preprogrammed by HUMAN. No neural model discovers the elementary operators or creates a new graph-edit type; the neural action model is a small sklearn MLPRegressor trained to predict the task-conditioned NUMERIC SOURCE REWARD of proposing each type. Training data are actual exploration rolls from 128 distinct original public author equation numeric sources: 3 uniformly selected action types from 5 per usable independent training source task. **369 self-rolled source numeric action rewards**, **49,880 candidate evaluations** and **18 self-reward-verified named source macros** retained for reuse. 48 original source-only x-y sample points per task; no human gold formula labels, no teacher fully successful AST. These are *source-valid numeric macros* rather than original whole analytic author gold-equivalent proof. OFF-POLICY contextual reward regression, not true end-to-end differentiable source program generation and not online RL with learned-policy rollouts. Learned chosen graph types then dynamically construct named executable symbolic lambda programs and independent exact-rationalized source verification.

## Mechanistic postgrade failure audit

After immutable four artifact SHA assertions the [audit #39934881753](https://github.com/yoonsj0305/NEUMANN/actions/runs/39934881753) actually examined the frozen policy choices on the 32. D executed: `ADD_BRANCH` 20 times, `REUSE_BINDING` 20, `COMPOSE_UNARY` 7, `MULTIPLY_BRANCH` 5, `RATIONAL_REWRITE` **only 6**. As each original gets 2 actions, 32 cases with insufficient X/Y explain fewer than 64 total choices. `REUSE` was frequent in D yet produced **no distinct author-exact reusable macro** scored under its source candidate provenance; the random strategy had 2 exact candidates marked reused, though complete A already found those equations via other actions (duplicate candidate ASTs are deduplicated in first-method order). The simple `ADD + RATIONAL` baseline solved 1 original not solved by D because the policy often spent its limited budget on REUSE rather than RATIONAL. **This is a specific learned reward/calibration and instruction-priority problem, not a global impossibility theorem for learned graph editors.** Reward was `1/(1+log1p(1e4*numeric_source_error))` for imperfect source candidates and 1 for exact source numeric candidates; maximizing it is NOT training to optimize entire original author correct/compute ratio. The one extra fixed-baseline original demonstrates an explicit quality regression from model policy.
