## The candidate generation mechanism, not another task-specific fixed opcode
This research-only classical student receives original TRAIN grids and original TEST inputs. It creates typed executable ASTs of the form `out = IF(guard, alternate_action, base_action)`. Guard syntax is **generated by AND/OR/NOT composition** of local pixel, coordinate, source-panel and relational features. Actions are source cell / second-panel cell / learned palette literal. Shape modes include whole-grid, two equal halves, and bounded coordinate shifts. Independent generic shapes include unique component crop and counting components to construct a vector. Must/forbidden output constraints on TRAIN pairs prune candidate expressions before full original-grid replay; minimum-description-length ties disagreeing on TEST inputs lead to ABSTAIN.

No external GPT-6 teacher forward, neural model forward, previously saved P2.2 program callback, task-ID check or target TEST label is present in inference. However the **feature vocabulary and grammar were human-designed**, and the student learns programs only **within an individual task**, not a persistent discovery policy across tasks. This is a bounded classical program synthesizer, not learned Q3 autonomy.

### The concrete new execution AST
On `e345f17b`, training pairs (4) inferred:
```
IF(left_pixel != right_pixel, 0, 4)
```
for each corresponding position of two equal-width vertical halves. A generalized, executable program cropped to half width and emitted **4** for equality and **0** for inequality. Independent separately implemented formula `output[r][c] = (input[r][c] === input[r][c+width/2]) ? 4 : 0` matched ALL **4 training** and **2 original public test** grids cell-by-cell. Mutating original target gold did not alter execution and invalidated correctness as required. [Independent audit](docs/experiments/results/q3_typed_guard_ast_p23_INDEPENDENT_AUDIT.json) PASS. No task-specific if-ID branches or cached gold.

## Controls and limits
- Seven in-container Node contracts PASS covering generated row-between fill, two-panel zero relation, shifted source + fill, component count, unique component crop, invalid input and source/test isolation. These are **development synthetic tests**, not original task wins.
- First new-cohort original accuracy remained very low (**2/32**), mostly because the condition language cannot explain original training grids. The extra program family is relative to prior evaluated B/Q/P20/C211 source, not an entirely unprecedented mathematical primitive.
- This proof does not establish independent cross-family transfer, no-contamination frontier performance, 10× total cost, or a teacher-free **persistent** program discovery learning policy.
- The 10.327 s scan itself is a new cost bottleneck. Repeated row/column searching and bounding-box computations are safe deletion candidates. If optimized, require exact **output/ABSTAIN parity on another preregistered fresh cohort** and benchmark against full source-shape/pruning cost. Do NOT retune P2.3 first score.
