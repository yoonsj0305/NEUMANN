# NEUMANN 1 — 연구 후보 압축과 생성 가능한 상태 표현

2026-10-07. 사용자의 요청은 실패 뒤 후보를 하나씩 바꾸는 연구가 아니라,
여러 가설을 함께 검토하고 목표에 필요한 계산 메커니즘을 빠르게 좁히는 것이다.
이번 작업은 과거 결과의 통합 판단과 **새로운 표현을 받을 수 있는 실제 실행·검증
기반의 구현**이다. 새 모델 학습, G0/G1 통과, 프런티어 성과가 아니다.

이 판단은 각 등록 범위의 증거와 **아직 없는 기능**에서 내린 연구 우선순위다.
모든 AI 아키텍처의 불가능성이나 이 후보의 전역 최적성을 증명한 것은 아니다.
서로 다른 실험의 시간·점수를 합쳐 순위 점수나 성공 확률을 만들어내지 않는다.

최근 실험은 주로 알려진 축약이나 한 표현 안의 계산 경로를 검사했다. 이 범위의
공짜 좋은 경로가 충분한 여유를 주지 않으므로, 같은 선택기를 훈련하는 것은 목표와
멀어진다. 남길 질문은 **계산할 상태와 반복 자체를 바꾸는 표현을 생성하는가**다.

## 구현한 공통 핵심

`neumann1/inductive_perspective.py`는 공개 입력으로 정수 상태의 초기값, 전이 함수,
원래 출력 목표를 받는다. 제안은 정해진 변환 ID가 아니라 다음 다섯 개의 생성된
프로그램이다: 좌표 인코딩 Φ, 새로운 초기값, 새 상태 전이 U, 반복 결과의 닫힌
식 R, 원래 목표의 decoder D. 임의의 허용 다항식 조합·계수를 제안할 수 있다.

입력·출력 프로그램은 기존 `representation_program.py`의 정확 정수 DAG와 compiler를
재사용한다. 관측·Oracle·승인 flag·학습 답을 공개 명세에 섞으면 거절한다. 원래
문제의 ordered output을 바꾸거나 불필요하다고 주장한 상태가 목표에 필요한 경우도
거절한다. API 검증은 운영체제 보안 경계가 아니다.

다섯 가지 조건을 정확 다항식 항등식으로 검사한다. p는 고정 입력 매개변수,
s는 원래 상태, I는 초기화, F는 전이, G는 원래 목표, n은 반복 횟수다.

1. `Φ(I(p),p) = I_latent(p)` — 초기 상태 보존.
2. `Φ(F(s,p),p) = U(Φ(s,p),p)` — 원래 전이와 새 좌표가 교환.
3. `G(s,p) = D(Φ(s,p),p)` — 줄인 표현에 원래 목표에 필요한 정보가 남음.
4. `R(p,0) = I_latent(p)` — 닫힌 식의 base.
5. `R(p,n+1) = U(R(p,n),p)` — 닫힌 식의 inductive step.

모두 성립하면 귀납적으로 모든 정수 p와 모든 0 이상의 정수 n에서 원래 목표가
보존된다. 이 검사기는 충분 조건이며, 도달 가능한 상태에서만 맞는 더 일반적인
축약을 모두 받아주는 완전한 증명기는 아니다. 노드·다항식 항·곱 전개 예산을
넘으면 미검증으로 처리한다. 부동소수점, 조건 분기·외부 효과·변하는 매개변수,
일반 C/Python 코드에는 이 정리와 실행 권한이 자동 적용되지 않는다.

공통 executor는 인증 뒤 닫힌 식과 decoder를 실행한다. n회 상태 전이를 반복할
필요가 없다는 구조적 사실과 전체 비용에서 강한 알고리즘보다 빠르다는 주장은
다르다. 큰 정수의 bit 연산 비용은 n의 값에 따라 늘 수 있고, 식 생성·증명·compile
투자도 있다. 실제 비용 배수·상각·메모리·에너지 우위는 이번에 측정하지 않았다.

## 강한 비교군도 생성한다

`neumann1/inductive_symbolic_baseline.py`는 기존 설치된 SymPy 1.14.0을 재사용한다.
공개 목표의 의존성 폐쇄를 구하고, 차수 ≤3의 기호 보간으로 닫힌 식을 제안한다.
몇 개의 반복 결과가 맞았다는 사실은 승인 근거가 아니다. 같은 다섯 조건을 통과한
제안만 실행하며, 기하급수 상태처럼 문법/귀납 조건에 맞지 않으면 abstain한다.

별도로 차수 ≤3의 단항식 공간에서 `P(F(s))-P(s)=0`의 계수를 nullspace로 풀어
새 다항식 불변량을 생성한다. 각 결과를 다시 항등식으로 검사한다. 불변량 하나를
찾았다는 사실만으로 목표 충분성을 승인하지 않는다. 이 비교군은 알려진 기호
합성법이며 학습된 NEUMANN이나 새로운 발명이라고 주장하지 않는다.

불변량 제안과 검증은 이미 연구됐고, 재귀 구조의 표현과 요약을 합성하는 도구도
있다. [Microsoft의 불변량 생성·검증 연구](https://www.microsoft.com/en-us/research/publication/finding-inductive-loop-invariants-using-large-language-models/),
[Synduce 공식 저장소](https://github.com/synduce/Synduce). 프로그램 라이브러리 생성·
압축도 [LILO](https://arxiv.org/abs/2310.19791)의 비교 의무가 있다. 이번에는 SymPy와
기존 로컬 IR을 실제 재사용했으며, Synduce/LILO 코드·모델을 설치하거나 능가한 것은
아니다. nullspace 구현은 [SymPy 공식 문서](https://docs.sympy.org/latest/modules/matrices/matrices.html)에 따른다.
이는 선택적 1차 출처 확인이며 포괄적인 최신 문헌 조사나 독창성 판정은 아니다.

## 실제 확인한 것과 그 한계

4개는 사람이 만든 열린 **engineering fixture**다. 3개 원래 상태에서 새로운
좌표 1~2개로 목표를 보존하고, quadratic/cubic recurrence의 반복을 닫힌 식으로
바꾸는 사례다. 사람이 제공한 참조 제안과 공개 기호 생성 제안 8개를 검사했다.
기호 방법도 4개 전부 해결했다. 이 쉬운 예제를 학습시킬 필요가 있다는 결론은 없다.

- 8개 제안의 보편적 항등식 40개 PASS.
- 원래 loop 48개 재생과 두 제안의 출력 비교 96개 PASS.
- 반복 횟수 10^30에 대한 식 계산 24개 PASS. 전체 원래 반복을 실행한 것이 아니며,
  귀납 증명과 독립적인 fixture 공식으로 확인했다. 어렵거나 프런티어가 푼 문제라는
  뜻도, 10^30배 가속했다는 뜻도 아니다.
- 원래 목표 변경, 전이의 조건 변경, n=0..3에서만 맞는 가짜 닫힌 식 세 제안 거절.
- bounded polynomial native가 지수 상태를 다항식으로 대신하는 것을 승인하지 않음.
- 원래 정확 다항식 검사와 별도로 SymPy 식 전개로 40개 항등식 재검증. compiler를
  쓰지 않는 DAG interpreter로 96개 출력 재검증 및 false proposal 세 개 거절.
- 관련 기존/신규 테스트 총 116개 PASS(4.09초); 새 induction 테스트는 21개다.

이것은 **생성된 표현을 검증해 원래 목표를 실행할 수 있는 기반의 동작 증거**다.
학습된 직관·새 문제 발견·범용성·10배 headroom·전역 Q 해결의 증거가 아니다.
새 neural policy는 아직 구현·학습하지 않았다.

## 다음 작업을 결정하는 하나의 분기

이제 문제 몇 개를 바꾸거나 모델을 하나씩 교체하는 방식을 기본 행동으로 삼지
않는다. 후속 G0는 남긴 표현 생성 후보와 강한 기호/고정 표현 비교군을 **같은
공개 문제와 목표 검사기에서 묶어 선별**해야 한다. 다음을 모두 갖춘 영역만 남긴다.

- 공개 문제에서 필요한 구조를 식별할 정보가 충분하고 Oracle이 runtime에 없음.
- 제공된 유효 표현이 강한 native에도 실제 큰 비용 여유를 줌. 이번 fixture처럼
  기존 기호 생성이 쉽게 해결하면 그 생성 문제의 neural 학습을 배정하지 않음.
- 발견·증명·실패·fallback·투자를 포함한 동일 자원 단위의 비교가 가능함.
- 현재 fixture/기존 opened 원본과 독립적인 구조 계보를 평가 전에 분리 가능함.

제안 표현에 여유가 있지만 기호 발견이 비싸다는 증거가 있어야 **학습된 생성**의
구체적인 budget이 생긴다. 그때 한 G1 계약 안에 A 직접 해결 / B 강한 기호 생성 /
C 학습된 고정 표현 선택 / D 생성 policy와 세 제거 실험을 넣는다. B도 이미 새 식을
생성하므로 D가 C만 이겨서는 부족하다. 별도 영역의 재귀 요약은 계약·전용 검증기와
강한 기존 도구 비교가 먼저이며 현재 다항식 fixture를 두 독립 영역으로 세지 않는다.

후속 표본·분포·budget·합격 수치는 아직 등록하지 않았다. 현재 engineering 실행을
새 G0 합격으로 바꾸거나 근거 없이 GPU/G1/G2를 시작하지 않는다.
