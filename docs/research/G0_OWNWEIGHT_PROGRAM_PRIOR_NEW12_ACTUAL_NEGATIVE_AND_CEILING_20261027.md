## Critical upper bound from actual frozen executable candidates

**11/12 future input tasks had exactly ONE unique predicted output across all three source-valid programs.** Thus program ranking policy cannot change exactness on those tasks regardless of training, architecture, score or oracle-access-free "intelligence". Only task **`PRE_icfp_gen_8.5`** (index 9) had two distinct predictions: cvc5 arm0/arm1 were wrong, arm2 was right. Classical MDL selected arm2 because its literal program text was shorter (**380 characters vs 724 for arm0/arm1**), so it recovered this one possible decision. Another task **`PRE_icfp_gen_2.5`** (index 7) was wrong for **all** three programs; no candidate reranker could fix it without generating another executable structure. Therefore, for the actual frozen candidate pool, **oracle-best candidate selection upper bound = 11/12**, and MDL already matches that upper bound. This is a finite candidate set exhaustive argument, **NOT** a bound on general algorithms or source grammar's full version space. All candidate program predictions were frozen BEFORE original gold, and the upper-bound diagnostic was computed POST-FIRST.

This explains A's failure more mechanistically than aggregate accuracy: **ranking expressivity is not the bottleneck, candidate *semantic diversity* and missing executable correct programs are**. Training larger networks on the same 3-per-task candidates cannot exceed that ceiling by reranking.

## Real bounded cost and serious limitations

- Native cvc5 C0 only, all original twelve tasks **1.409549 CPU seconds**.
- Native cvc5 all 3 source-only candidates, all twelve **6.319787 CPU seconds**, incurred for A, B and MDL candidate selection (before model forward inference).
- Native C1 with one extra original label per task **1.512579 CPU seconds** for native solver process only, plus 12 genuine labels.
- Six A/B PyTorch trained models together consumed **1.42534 process CPU seconds** (as recorded in trainer), of which each independently deployable learned A/B could amortize its share over tasks.
- All numbers EXCLUDE data acquisition, Python/Z3 parsing/verification, cvc5 installation, evaluation overhead, memory/network/energy/dollars. All same task authors/project family; original PBE 12 tiny for statistical generalization and not nonpublic OOD. The MDL comparator uses program *text length*, not normalized DAG cost; its correctness here is genuine but this proxy has syntactic representation artifacts.
- MDL matching the finite 11/12 ceiling is sufficient to reject adding more reranker capacity in this study; not enough to claim that simplicity is generally optimal or learned inductive priors cannot work on richer semantic search distributions.
