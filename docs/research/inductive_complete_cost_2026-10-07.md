# NEUMANN 1 — 실제 비용 우위 검사

2026-10-07. **이번에 검사한 좌표 변환은 압도적 비용 우위를 보이지 않았다.**
공개 전이식에서 좌표를 복원하는 강한 기호 알고리즘과, 유효한 좌표를 무료로
제공받는 경로의 전체 운영 시간은 거의 같았다. 등록 판정은
`NO_10X_OPERATIONAL_HEADROOM_IN_REGISTERED_SCOPE`다.

이는 학습된 NEUMANN의 성능 결과가 아니다. 현재 학습된 관점 생성 모델은 없다.
제공 좌표의 전역 최적성, 다른 문제군의 불가능성, 프런티어 능력은 입증하지 않았다.
이번 문제군에 대한 GPU 학습 투자 근거가 생기지 않았다는 제한된 결론이다.

## 사전 등록과 비교

계약 `INDUCTIVE_COMPLETE_COST_V1`은 실측 전에 소스 7개와 SymPy/mpmath 설치
identity를 동결했다. 계약 SHA256은
`01cbbe917adf0809a678a313c860f93f1aa619f4051679d8ba3a7cacb377251c`.

정확 정수 전이식의 차수 2/4/6과 결합 계수 −2/3을 조합한 개발 문제 6개를
구성했다. 공개 입력은 원래 초기화·전이·출력의 DAG이며, 숨은 좌표와 정답은
별도 O 자료다. 같은 문제를 네 경로로, 두 사용 조건에서 각각 3회 실행했다.

| 경로 | 작업과 권한 |
| --- | --- |
| COMPILED_DIRECT | 원래 전이 반복. 목표 의존성을 분석해 무관한 상태 제거, compiler DCE/CSE 재사용 |
| PUBLIC_INTEGER_NATIVE | 공개 계수의 상쇄와 다항식 차분 적분으로 좌표·닫힌 식 생성. Oracle 읽지 않음 |
| PUBLIC_CAS_FACTOR | 같은 공개 생성 결과에 기존 CAS factor/CSE 적용 |
| FREE_COORDINATES | 오프라인에서 제공한 유효 좌표 사용. 실행 안에서 원래 문제의 증명과 compile 재수행 |

생성 경로는 모두 같은 정확 정수 귀납 검사기, compiler, 절차 재사용 권한을
받는다. 공개 native는 알려진 한정된 상쇄·차분 알고리즘이며 학습된 발견이나
새로운 발명으로 취급하지 않는다. 불필요한 전이를 반복하는 경로만 기준선으로
삼지 않고, 모든 요청을 정확히 처리한 가장 빠른 기존 경로와 비교했다.

처음 조건은 새 프로세스에서 100,000회 반복에 해당하는 입력 1개를 처리한다.
재사용 조건은 새 프로세스에서 서로 다른 매개변수/반복 횟수의 실제 입력 16개를
처리하며, 양쪽 모두 증명·compile을 한 번만 한다. 문제당 서로 다른 요청은 16개,
전체는 96개다. 경로·반복 실측을 포함한 1,122개 출력은 독립 문제 1,122개가 아니다.

동결 합격 기준은 **6개 전부 평가 가능, 비용 비율 기하평균 ≥10배, 6개 중
5개 이상 각각 ≥10배, 두 사용 조건 모두 통과**다. 한 계산 영역의 검사이므로
통과했더라도 G1 자동 진입이나 전체 North Star 달성을 뜻하지 않는다.

## 전체 운영 비용 결과

아래 비율은 `가장 빠른 적격 기존 경로 / 무료 제공 좌표 경로`다. 큰 값일수록
제공 좌표의 이득이다. 각 시간은 같은 경우의 3회 실측 중앙값이다.

FREE_COORDINATES는 O 정보를 명시적으로 사용하는 연구용 비교군이다. 그 경로의
실측이 O를 실제 NEUMANN 추론 입력으로 허용하거나 학습된 발견으로 만드는 것은 아니다.

| 조건 | 기하평균 비용 비율 | 10배 이상 사례 | 판정 |
| --- | ---: | ---: | --- |
| 처음 입력 1개 | 0.9961× | 0/6 | 미통과 |
| 실제 입력 16개, 절차 재사용 | 0.9974× | 0/6 | 미통과 |

| 문제 | 처음 기존/제공 시간(초) | 처음 비율 | 16입력 기존/제공 시간(초) | 16입력 비율 |
| --- | ---: | ---: | ---: | ---: |
| 차수2, 결합−2 | 1.5533 / 1.5674 | 0.9910× | 1.5576 / 1.5655 | 0.9950× |
| 차수2, 결합3 | 1.5675 / 1.5674 | 1.0000× | 1.5548 / 1.5707 | 0.9899× |
| 차수4, 결합−2 | 1.5689 / 1.5583 | 1.0068× | 1.5614 / 1.5681 | 0.9957× |
| 차수4, 결합3 | 1.5569 / 1.5626 | 0.9963× | 1.5589 / 1.5576 | 1.0008× |
| 차수6, 결합−2 | 1.5761 / 1.5739 | 1.0014× | 1.5668 / 1.5620 | 1.0031× |
| 차수6, 결합3 | 1.5661 / 1.5959 | 0.9814× | 1.5619 / 1.5621 | 0.9999× |

6개 모두 가장 빠른 적격 기존 경로는 PUBLIC_INTEGER_NATIVE였다. 작은 시간
차이는 3회 실측과 시스템 변동에서의 기술 통계이며, 유의한 미세 우위로 주장하지
않는다. 원래 전이를 반복하는 DIRECT 대비 최대 3.4122배라는 더 유리한 숫자도
있지만, 그것은 강한 기존 알고리즘 대비 우위가 아니다.

총 144개 worker 관측 중 132개가 모든 요청을 정확히 완료했다. 나머지 12개는
차수6의 CAS 경로에서 다항식 증명 작업 예산을 넘었다. 판정은 `NOT_VERIFIED`,
오류는 `Polynomial verification work budget exceeded: UNKNOWN`이다. 수학적으로
틀렸다고 재판정하지 않았으며, 출력이나 비용을 0으로 채우지 않았다. 해당 실패의
실측 시간 합계 48.9635초와 제안·검사 결과·stderr를 원본에 보존했다. 다른 적격
native와 제공 좌표가 전부 완료했으므로, 사전 등록 규칙상 6개 모두 평가 가능하다.
실패한 CAS는 빠른 적격 경로의 중앙값에 포함되지 않는다. 이는 네 경로를 전부
순차 호출하는 배포 정책의 합산 비용 결과는 아니다.

전체 연구 실행은 310.3506초였다. 실측 환경은 Windows, Intel i5-10400F CPU,
로컬 Python 환경이다. 하드웨어 이름은 실행 후 기록한 설명 정보이며 사전
등록된 성능 보증이 아니다.

## 포함한 비용과 제한

주 지표는 부모 프로세스의 subprocess 시작부터 종료, 실제 모든 출력 읽기와
정확 정수 답 비교까지의 wall time이다. 프로세스·import 시작 비용, 공개 입력/
요청 읽기, 좌표 발견, 검증, compile, 계산, 출력 저장, 종료가 포함된다. 제공
좌표도 파일 읽기·원래 문제 인증·compile 비용을 부담한다.

문제·정답·제공 좌표의 오프라인 생성은 별도 0.0287초로 기록되며 주 지표에서
제외한다. 기존 알고리즘 연구 투자와 개발 투자는 `UNKNOWN`이다. 신경망 학습은
수행하지 않았다. 따라서 이 결과는 학습 투자까지 포함한 전체 NEUMANN 비용,
FLOPs, 실제 RAM/VRAM peak, 에너지 또는 금전 비용의 비교가 아니다.

현재 구현의 공통 Python/package 초기화가 약 1.5초의 전체 시간을 크게 차지한다.
해당 비용을 사후에 빼서 합격 배수를 만들지 않았다. 이는 현재 프로세스 실행
방식의 결과이며, 지속 서비스의 성능이나 지능의 근본적인 비용 하한이 아니다.
등록 소스는 핵심 7개와 두 패키지 identity를 포함하지만 모든 전이 의존성과
운영체제를 완전히 봉인한 환경 image는 아니다.

## 독립 검사와 보존

별도 replay에서 645개 manifest 파일의 hash, 동결 소스·패키지, 원본 결과 receipt를
검사하고 등록 seed에서 6개 자료를 재구성했다. 16개 서로 다른 적격 제안에 대해
기존 다항식 검사기와 별도의 SymPy DAG 해석으로 다섯 항등식을 확인했다. 96개
인증 worker의 원본 검사와 1,122개 실측 출력을 독립 정수 해석으로 재검증했다.
54개 짧은 원래 전이 실행도 별도로 대조했다. 큰 반복의 모든 원래 전이를 replay
한 것은 아니며, 큰 입력 검사는 귀납 항등식과 독립 닫힌 식 평가에 의존한다.
실패 12개의 원래 증명 예산/미검증 상태를 재현했고 비용 관측은 다시 측정하지 않았다.

128개 관련 회귀 검사가 통과했다. 최초 audit의 JSON 정수/문자열 key 비교 오류와
새 gate 테스트 fixture의 experiment_id 누락은 별도 개발 실패로 기록하고
audit/test만 수정했다. 동결 실행 코드, 비용 자료, 최초 판정은 변경하지 않았다.

6개 D 공개 문제와 6개 O 자료를 별도로 등록한다. 기존 D0 권한 검사와 엄격한
공개 정수 전이 schema를 재사용한다. 학습·fresh 평가와 O runtime 접근은 허용하지
않는다. 이 Python API는 운영체제 보안 격리가 아니다. 자료는 모두 개발용 공개
증거이며 fresh 적격 수는 0이다.

## 연구 결정

이 상쇄·다항식 차분 문제군에서는 **기호 방법도 싼 새 표현을 생성한다**. 여기에
신경망을 더하는 학습을 현재 성과의 확대판으로 시작할 근거가 없다. 같은 문제를
더 큰 반복 수로 만들거나 기준선의 절차 재사용을 막아 성공으로 바꾸지 않는다.

일반적인 목표 충분 표현 생성 가설과 재귀 요약 후보는 아직 검증되지 않았고
폐기한 것이 아니다. 다음 학습 투자에는 기존 생성기가 싸게 복원하지 못하는
독립적인 구조에서, 발견·검증·실행 비용을 함께 포함한 이득이 먼저 필요하다.
새 후보를 제시했다는 사실만으로 승인하지 않는다. Q1~Q7은 OPEN이고 G1 미진입,
G2·기존 Decision3 봉인은 유지한다. GitHub 원본/과거 실패/동결 North Star는
변경하지 않았으며 이번 작업에서 GPU 사용이나 원격 게시를 하지 않았다.

원본: `Continuation/INDUCTIVE_COMPLETE_COST_PREPARATION`,
`INDUCTIVE_COMPLETE_COST_FIRST`, `INDUCTIVE_COMPLETE_COST_AUDIT`.
실행 가능한 계약·source/result pins와 판정은 `docs/experiments`,
개발 자료 권한은 `experiments/inductive_complete_cost_asset_registry.json`에 기록한다.
