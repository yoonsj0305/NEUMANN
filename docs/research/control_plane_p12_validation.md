## Source, construction and disclosure

The catalog is newly authored literal repository source, not an external
benchmark or a sealed test. All twelve items are created before any validation
model scores and retained without selecting favorable results. `catalog()`
reproduces the public and reference JSON exactly. Source and file hashes,
ordered task identities, public-view digest and dedup receipt are frozen in
`control_plane_p12_validation.preregister.json` before the first execution.

Four arithmetic items use new alpha-AST structures (nested division, unary
rational sum, two sums multiplied, nested rational difference). Four coding
items require prefix sums, consecutive run encoding, longest increasing
contiguous run, and zero-sum index-pair counts, rather than the old distinct-set
aggregations. Four planning items use triangle coloring with an alias,
derangement, nonuniform domains with constants, and an anchored even cycle.
Existing typed input interfaces and instruction strings are intentionally kept.

Dedup checks all original twelve P1/P1.1/P1.2/Decision2 views and three original
Runtime0 development tasks. It ignores background/instruction-only changes,
alpha-renames arithmetic variables, normalizes coding specifications and
canonicalizes CSP graphs over every variable bijection, with domain cardinality
and constant markers. All fresh structural keys must also be unique. This is
conservative exact/structural dedup, not proof that every coding specification
has different semantics or that training-data contamination is absent.

Original `verify_original` remains answer authority. Literal rational references
are checked against the supplied expression. Planning witnesses satisfy every
original domain and constraint. Coding witnesses run in the original bounded
Python worker against five fixed vectors per task (including empty/edge cases);
this is finite-spec testing, not proof for all inputs. Each checker must also
reject a deliberately wrong witness. Twelve positive and twelve negative
construction controls are checked on CPU before model execution. No judge model.

Family, reference route, witness, private tests and semantic-kind metadata are
in a separate reference file. Scoring receives only `row.view` through the
unchanged `public_view` and prefix encoder; IDs are bookkeeping only. Source
verification hashes reference bytes without decoding them. The scoring process
decodes references only after all forward scoring for admission accounting.
The model cannot call tools or read those references. Examples in the public
specification are disclosed inputs, not hidden labels.
