## D0 — 원본 보존과 권한을 실제 로더에서 구분

H: 원본 증거·해시·판정, 감사만. D: 열린 개발 문제의 명시적 public view.
F: 코드 회귀 fixture. B: 검증기·생성기·solver·비용 계측 코드.
O: 오프라인 Oracle/명시적으로 허용된 학습 감독. S: 봉인된 미사용 평가.
하나의 archive 안에 H 원본, D 문제 계수, O 정답이 함께 있을 수 있으므로 파일
폴더나 제목만으로 전체를 학습 입력으로 승인하지 않는다.

`neumann1.structural_data_rights`는 봉인 S의 내용 읽기·해시·디코딩 전에 접근을
거부하고, LP public view를 A/b/c만으로 한정한다. 원본 H와 Oracle O를 문제
입력으로 호출하면 거부한다. 현재 train/fresh_eval 진입은 제공하지 않는다.
G0/G1 계약 후 명시적 감독 view가 생겨야 한다. Oracle을 runtime 입력으로 주지 않는다.

같은 원본과 동등한 surface view는 동일 노출 영역에 배정한다. 과거 holdout도
이미 본 새 아키텍처의 개발 자료이며 다시 fresh로 표시하지 않는다. 생성기에서
equivalence group과 변환 조합의 계보를 선언하고, train과 unseen-composition
충돌을 등록 순서와 관계없이 검사한다. 임의의 수학적 동등성이나 그래프 동형성을
자동 판별했다고 주장하지 않는다. 새로운 motif/연산 계보의 producer는 아직 필요하다.

산출물은 원본 해시 ledger, 구조 경험, 비용 기록, 원래 검증기 registry, 누출
검사다. UNKNOWN 비용은 null/UNKNOWN으로 유지하며 환경·측정 범위·cold 처리
차이가 있는 시간들을 합쳐 새 우위를 만들지 않는다. 실패·중단·미평가·warmup도 남긴다.

## G0 — 학습 전 headroom 선별

서로 다른 그래프/관계 및 수학/프로그램 계열에서 strong Direct, 기존 결정론적
구조 최적화, 무료로 제공된 유효 구조를 비교한다. 비교 대상에도 같은 native,
specialization, caching 및 검증 권한을 준다. 발견 비용을 제외한 구조가 원래
정답을 보존하는지 먼저 확인한다. Direct가 능력/예산에 실패하면 속도비를 만들지 않는다.

**무료 구조와 진짜 최적 구조는 다르다.** 주어진 좋은 구조의 성공은 headroom의
구성적 사례다. 전역 최적 표현/최소 실행비용의 증명 없이는 이를 모든 구조의
절약 상한이라고 부르지 않는다. 실패의 veto는 사전 등록한 변환·문제·기준선
범위에 한정한다. 한 Oracle의 실패로 모든 관점 발견 가설을 기각하지 않는다.

원래 두 충분히 복잡한 계열에서 10배의 낙관적 가능성을 보자는 수치는 제안이었다.
이후 새 G0 v1에는 24개·3회 측정 반복·계열별 기하평균 10배 및 최대규모 3/4개의
10배 조건을 실행 전에 동결했다. 해당 계약에서 실패했으며 전역 기준의 변경은 없다.
표본 수·규모·baseline identity·완료 예산·cost axis·분포/실패 기준·cold/상각·정확성
권한과 함께 실행 전 등록해야 한다. 후속 계약에 수치를 사후 변경해 적용하지 않는다.
같은 LP backend의 두 구성 클래스는 서로 독립된 계산 영역의 증거가 아니다.

## G1 — 하나의 통제된 관점 생성 tournament

A Neural Direct, B Symbolic Search, C Fixed Representation Selector,
D NEUMANN Perspective Learner를 같은 입력·문제 권한·원래 검증기·fallback 및
cache 권한 아래 비교한다. 모델·기호 탐색의 투자, 후보 수, 제안/검증/실패 예산과
prior knowledge 차이를 기록한다. 한쪽에만 무료 정답/숨겨진 dual/변환 라이브러리
구축비용을 주지 않는다. 고정된 선택기는 새 표현 생성에 대한 비교군이다.

같은 통합 계약에 새 표현 생성 제거, 반증/검증 제거, 구조 전이 학습 제거를
포함한다. 검증 제거 arm도 최종 판정은 독립 원문 검사로 한다. 미관측 조합,
새 motif, 잘못된 유추를 유도하는 제약 변화, 규모 증가, 여러 초기화 조건을
포함한다. 표본/seed 수는 개발 변동성 기반으로 사전 고정하며 12문제로 범용성을
선언하지 않는다. 검증 데이터로 ablation을 재튜닝하지 않는다.

D>C와 D>B의 관측은 추가 가치의 근거이지만 그 자체로 독창성이나 범용 지능의
증명이 아니다. 재사용한 선행연구 효과와 새 계산 원리의 기여를 구분해야 한다.

## G2 — 독립적인 실제 Frontier Gap

작은 기준선의 실패와 실제 프런티어의 성공을 각각 실행하고 원래 문제에서
확인한 집합을 사용한다. 이름/평판으로 frontier success를 가정하지 않는다.
Capability, Compute, Memory, Latency, Energy, Cost를 자원별로 보고하며
초·FLOPs·줄·돈을 근거 없이 더하지 않는다. 실패/fallback/발견/검증/제어/파싱/
복원/이동/저장/cold/학습·라이브러리 투자를 기록하고 상각 횟수를 등록한다.
100배/1,000배는 장기 목표이고 관측 성과가 아니다. 독립 재현과 Edge/Cloud는
해당 계약에서 성공한 뒤의 단계다. 검증 범위 밖의 무제한 범용성은 주장하지 않는다.

## 사전 결정 규칙

- G0의 등록 범위에서 headroom 없음 → 해당 범위 학습 중단, 표현/문제 가설 재검토.
- 유효 구조가 있으나 발견 실패 → PERCEIVE/REFRAME 수정.
- 유효 구조를 발견하나 총 비용 초과 → 탐색/판별 비용의 아키텍처 수정.
- 기호 탐색보다 추가 가치 없음 → 학습된 구조 발견의 경제적 가치 재검토.
- G1 통과 후 G2 실패 → 전이/확장성/현실 능력 병목을 구분; 전역 질문 OPEN 유지.
- G2 통과 → 범위가 명시된 독립 재현 및 실제 장치 검증.
