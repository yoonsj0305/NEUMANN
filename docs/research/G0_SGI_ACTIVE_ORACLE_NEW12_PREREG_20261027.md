## Source-only / probe / heldout split
- For each chosen original source with N ground `constraint` clauses, use original first N-2 constraints as SOURCE, penultimate N-1 as optional PROBE, final N as sealed FUTURE evaluation. All original named helper functions and **author's original synthesis grammar** remain unchanged.
- Evaluation runner input receives only SOURCE constraints, **the hexadecimal probe INPUT but NOT probe OUTPUT**, and the original original heldout/future INPUT but **NOT future OUTPUT**. Gold labels must not enter candidate model/solver or proposal file. The first source-only program proposals and conditional probe-request decisions must be SHA256-frozen BEFORE using penultimate target label or final target label.
- A fixed three-arm professional native `cvc5 --lang=sygus2` portfolio with EXACT flags: `--seed=0`, `--seed=1`, `--sygus-enum=random --seed=1`, 10-second wall/arm and 8-second CPU; 512MiB sampled-RSS limit. No oracle, no neural, same first N-2 source IO per arm.
- Evaluate each of three source-consistent, syntactically parsed `define-fun f` candidate functions on the probe **input only**, using separate Z3 bitvector evaluation (not source code comment or author future output). Count distinct predicted byte-vector values. If all 3 valid program predictions are IDENTICAL → **SKIP extra probe query**, return arm0 prediction on final input; otherwise → **REQUEST ONE** original probe output label and then recompute `cvc5 --seed=0` using source+probe as a separate replay. If 0–2 valid candidates, do not equate lack of disagreement to certainty: **HOLD/REQUEST_ONE** under same rights. If source-only candidates disagree but no authorized probe label, HOLD.
- The comparator C0 is original cvc5 default with SOURCE only (no oracle), same source/test rights. The comparator C1 is original cvc5 default on SOURCE+one original PROBE label for ALL eligible tasks (so counts N eligible label requests). C_active gets label only for disagreement/uncertainty and is compared against both. Portfolio-of-three compute is CHARGED to C_active, with no inference-only misleading Pareto claim.
- Required pre-grade first receipt: exact 12 original source Git blob SHAs, 12 SOURCE split SHAs, all original PROBE+future INPUT-only values and the SHA256 of each removed PROBE/FUTURE full constraint, frozen C0 and 3-arm stdout/stderr, probe-input evaluated predictions or a parse HOLD, and decisions to request/skip. Freeze before ANY grade/probe answer reading. Do not use future label to choose query or regenerate candidates.
- Second stage grade: use previously sealed FIRST receipt to (a) reveal only the *requested* probe labels to conditional classical refits, (b) independently evaluate C0, C1, C_active on original final heldout output with fresh Z3 processes, (c) report EXACT, WRONG, HOLD and total spent oracle labels+CPU/wall/RSS, preserving first file SHA, no replacements. A stronger freely available non-portfolio full solver may be added as post-first comparator but cannot upgrade FIRST.
- Correct only original final output (not source-fit). If no original label available, HOLD. Candidate verifier must check all available source labels before scoring future; reading final source label earlier is prohibited by protocol.

## What this *cannot* show
- Success of a **classical** active-query policy is NOT own-weight learned discovery, novel base operator, new frontier model, or evidence of model policy self-improvement. Three output disagreements from a fixed budget are a bounded heuristic and **don't certify version-space unanimity**.
- If C1 and C0 already perfectly solve, no neural opportunity in this family. If Cactive=C1 with fewer labels but more CPU, only label-efficiency, not compute superiority. If any policy abstains, do not promote exact on fewer evaluated items.
- No claims of cross-individual-author unseen OOD, universal classical incompleteness, 10x all-in or Q pass.
- **Q1–Q7 OPEN, G1 HOLD** and research PR #616 unmerged.

## Failure handling
Output/program parser or tool unsupported → recorded per selected original; no cherry-picking. Source task with <=2 constraints ineligible but remains in denominator. First execute and **seal source-only predictions** before looking at original probe/future gold.
