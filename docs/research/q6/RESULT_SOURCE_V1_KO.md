비교군이 실패한 원래 문제 1개를 추가 해결했다. 강한 SOURCE 통계 게이트는
FAIL이고, 범용 Q6와 독립 의미 영역 전이는 OPEN이다.**

기준 커밋 `0d1baec723f249a62a901d100af6e941234a43ac`.
최초 실험 코드/계약 커밋 `c95fd10d016650485a1a38fcf45b855674863070`은

## 1. 문제 재정의

이번 질문은 ‘좋은 SOURCE 프로그램을 다시 실행할 수 있는가’가 아니다.
**SOURCE 절차의 연산 구조를 유지하면서, TARGET에서 그 절차가 읽을 상태를
스스로 재구성해 단순 기억·타입 대응·동일 발견 코어·전문 방식보다 실제
문제를 추가로 해결하는가?**

Q3 발견기·학습 정책은 Claude 소유로 유지했다. 이 브랜치는 Q6 경로에만
코드를 추가했다. 별도 언어모델·학습형 제2 코어·문제별 정답 생성기는 없다.
SECOND/THIRD 봉인·기존 실패·Q3 네 파일은 해시가 그대로다.

## 3. 제1원칙 요소와 공통 계약

Q3 산출물을 `artifact_id`, 생산 커밋, 원본 과제 해시, 관찰 스키마,
발견 표현, 실행 절차, SOURCE 검증, 출처, 자원 비용으로 전달한다.
불변량·전제조건이 원래 증거에 없으면 만들어 채우지 않는다.

각 프로그램의 원래 TRAIN·TEST를 모두 재확인해 57개를 인정했다. 신경망의

유지했다. 커밋·원본 파일·원래 프로그램·검증 결과는 함께 결합된다.

주입할 수 있는 `neumann1.q6.api.structural_transport`를 제공했다.

## 4. 새로운 최소 전이 구조

SOURCE의 typed AST에서 의존성이 있는 부분 절차를 추출하고 자유 변수를
역할로 정규화한다. 연산과 내부 바인더 구조는 유지한다. TARGET의 허용된
관찰에서 각 역할이 어떤 표현에 대응할지 찾는다.

T는 역할을 같은 타입의 변수·관찰 상수에 적용한다. C는 SOURCE 절차의
역관계가 허용하는 값으로 대응 후보를 제한하고, 기존 Q3 공개 검색 인터페이스로
복합 표현을 찾는다. 단사 역함수만 요구하지 않는다. 전체 TRAIN에서 틀린
후보는 반례로 제거한다. 구현은 한 번에 복합 역할 1개를 바꾸는 제한된
전이 언어이며, 일반적인 표현/불변량 전이 엔진의 완성은 아니다.

출력은 실행 가능한 원래 기판 AST, 발견한 대응, 남은 검증 의무, 반례,
측정 비용, UNKNOWN 이유다. TARGET TEST는 추론 프로세스에 전달하지 않았다.
독립 검증 전 상태는 TRAIN_CONSISTENT이며, 독립 정확성으로 승격하지 않는다.

공개 연구에서 가져온 것은 [HOUDINI](https://arxiv.org/abs/1804.00218)의 타입
기반 구성, [MIL/Metagol](https://arxiv.org/abs/1907.10953)의 관계/고차 구성,
[CEGIS](https://www2.eecs.berkeley.edu/Pubs/TechRpts/2008/EECS-2008-177.html)의
반례 제거 원리다. [Playgol](https://arxiv.org/abs/1904.08993)과 관련된 자기실험은
고정 후보 사이의 입력 탐침에만 사용했다. 해당 기술 자체를 새로운 발명이라고
주장하거나 그 신경망/Prolog 시스템 전체를 이식하지 않았다.

## 5. 실제 SOURCE 실험과 인과 사례

기존에 열린 rule SOURCE 125개만 사용했다. 과제 ID 해시로 5개 분할을 만들고,
각 평가 과제에는 다른 분할의 SOURCE 산출물만 제공했다. 평가 40개도 결과를
보기 전에 ID 해시로 골랐다. **과제 단위 분리이며 의미 계열/저자 분리는 아니다.**
모든 정상 군의 명목 process CPU 예산은 3초, BudgetOnly는 12초였다.

| 군 | 원래 TEST 통과 | 측정된 수신 처리 CPU 합계 |
|---|---:|---:|
| A: 기존 Q3 발견 코어 | 15/40 | 89.384초 |
| B: A + 전체 프로그램 기억 | 15/40 | 88.650초 |
| T: B + 타입 기반 역할 적용 | 15/40 | 88.991초 |
| C: T + 복합 상태 대응 | **17/40** | 93.203초 |
| C-no-map: 대응 제거 | 15/40 | 89.225초 |
| S: 명세 공간 전문 방식 | 15/40 | 88.733초 |
| V: 고정 역분해 전문 방식 | 16/40 | 86.199초 |
| BudgetOnly: T, 4배 허용 예산 | 17/40 | 274.514초 |

320/320 작업 완료, 오류·시간 초과 0건. C와 BudgetOnly는 성공 수는 같지만
성공 과제가 다르다. C만 `rule/c130`, BudgetOnly만 `rule/c178`을 해결했다.
따라서 두 군을 같은 능력이라고 놓고 총 CPU 배수를 계산하면 안 된다.

### 실제 대응: rule/c208 → rule/c130

시스템이 SOURCE 절차의 `비교 + fold` 구조를 유지하고 다음 대응을 찾았다.
표의 역할명은 Q3의 고정 관찰 스키마를 사람이 읽기 쉽게 설명한 것이다.
시스템에 TARGET 전용 대응표를 주지 않았다.

| SOURCE 상태 역할 | 자동으로 발견한 TARGET 표현 |
|---|---|
| 현재 원소/초깃값 | 상수 −2 |
| 남은 원소 수 | 현재 위치 − 1 |
| 뒤쪽 부분열 | 역순 앞쪽 부분열 |

SOURCE 부분 절차는 `threshold < fold_last(list, initial)`로 읽을 수 있다.
여기서 `fold_last`는 설명용 축약이며 새 기본 연산을 추가하지 않았다.
TARGET 실행 코드는 다음 기존 기판 표현으로 재구성됐다.

```
<zfilter ... | (lt (sub $1 1) (foldlI $6 -2 $3))>
```

이 프로그램은 원래 TRAIN 8개와 TEST **24개 전부**를 통과했다. 최초 worker
CPU는 1.126초, 대응 모듈 내부는 0.085초였다. 직접 재생·타입 적용·A/S/V는
명목 3초에서 실패했다. BudgetOnly는 12초를 허용받았지만 1.651초에 잘못된
TRAIN 적합 프로그램을 선택하고 종료했다. 실제로 12초를 썼다고 주장하지 않는다.

추가 확인은 최초 결과와 분리한 사후 SOURCE 진단이다.

- 전체 프로그램을 시간 제한 없이 재생해도 TRAIN 적합 0개.
- 허용된 T의 모든 역할/상수 적용 **894개**를 전수 확인해도 TRAIN 적합 0개.
  이는 이 유한 T 클래스의 결과이며 임의의 고차 타입 합성 전체에 대한 불가능성
  증명이 아니다.
- 복합 대응의 빼기 연산을 제거하면 TRAIN에서 실패한다.
- 고정 대응에서 SOURCE 비교 연산 또는 fold 방향을 타입 보존 변경해도 실패한다.
- 원래 대응과 재구성 절차를 독립 해석기로 비교한 4,096개 상태 탐침이 일치했다.
  이것은 전체 TARGET 의미에 대한 보편적 증명이 아니다.
- 같은 대응 검색에 SOURCE 절차 대신 기존 기본 연산 맥락만 제공한 추가 대조는
  15/40이며 `rule/c130`을 풀지 못했다. 이 대조는 1차 결과 이후 설계·등록했다.
- TEST를 주지 않은 별도 생성 재현에서 **동일 AST**가 다시 나왔다. 대응 제거군은
  다시 UNKNOWN이었다. 새 독립 평가로 세지 않았다.

같은 `rule/c208` SOURCE 부분 절차가 `rule/c013`에도 다른 대응으로 재사용됐다.
다만 그 과제는 BudgetOnly도 해결했으므로 전군 독점 해결은 1개다.

## 6. 생략한 계산과 비용·물리 구조

전체 TARGET 절차를 다시 조립하는 대신 SOURCE의 비교/fold 구조를 보존하고
작은 역할 대응을 구했다. 해당 사례에서 매핑 탐색 후보 1,807개와 SOURCE
관계 평가 20,975회를 기록했다. S는 전체 절차 후보 220,160개를 확인하고도
예산 안에 해법을 얻지 못했다. 후보의 단가가 다르므로 이를 연산량 배수로
바꾸지 않는다. **새 능력의 예산 내 획득이지, 같은 정답률에서의 가속 입증은 아니다.**

초기 결과 JSON의 SOURCE 투자/재사용 시나리오는 성공 donor만 합친
28.1955초다. 전체 비용으로 쓰기에 불완전하므로 `final_analysis.json`에
다음과 같이 보충했으며 최초 결과를 고쳐 숨기지 않았다.

| SOURCE 지식 준비 비용 | CPU |
|---|---:|
| 성공 57개 발견 | 28.1955초 |
| 실패 68개 발견 | **376.9182초** |
| 합계 125개 | **405.1137초** |
| 이번 추출·재검증·준비 | 0.1324초 |

고정된 40개 수신 분포의 균등 반복을 가정한 C의 측정 SOURCE 포함 시나리오는
N=1 약 407.576초, N=10 약 428.547초, N=100 약 638.253초다.
이는 회계 시나리오이며 실제 warm 실행 측정이나 손익분기점이 아니다.
과거 공통 역연산 발견 투자·V 매크로 학습의 CPU·queue-tail/OS 비용 일부는
미측정이다. 에너지·금전 비용도 UNKNOWN이다. 전체 비용 10배 우위는 미입증이다.

C의 측정 최대 RSS는 198.578 MiB였다. 이 실행 환경의 프로세스 수치이며
로컬 장치·엣지에서 같은 성능이 난다는 주장이 아니다. 디스크 원리 자료와 RSS는
구분했다. 순수 소프트웨어에서 원재료 가격이 정의되지 않아 Idiot Index는
적용하지 않았다.

## 7. 반례·실패·적용 조건

타입을 맞춘 SOURCE 절차 섞기 51개에 대해, 기존 검증 결합을 유지한 경우와
검증 문자열까지 다시 꾸민 경우 총 102개가 거부됐다. 16개 실제 타입 동일/
관계 불일치 사례, 빈 입력에서 정의되지 않는 실제 SOURCE 절차, 이름만 바꾼
재생 분류도 검사했다. 이 음성 대조는 Q6 능력 증거로 세지 않았다.

C가 TRAIN을 만족하고 TEST에 실패한 2개는 Q3 fallback 결과였다. 이를
전이 성공으로 올리지 않았다. 규칙이 없거나 대응을 못 찾은 경우는 유한
역관계 범위·대응 언어·검색 예산 중 무엇이 원인인지 아직 분리되지 않았다.
‘대응이 없다’는 보편적 결론으로 해석하지 않는다.

`rule/c013`의 전이 절차와 기존 SOURCE-검증 Q3 대안은 원래 예제에서는
일치하지만 일반 입력 탐침 36개 중 12개에서 서로 달랐다. **어느 쪽이 진짜
정답인지는 이 탐침으로 알 수 없다.** 별도 정답 생성기를 만든 것이 아니라
기존 두 프로그램을 실행한 결과다. 따라서 보편적 동등성/적용 전제가 확보된
것으로 간주하지 않는다. `rule/c130`에는 비교할 기존 Q3 해법도 없었다.

보존한 것은 SOURCE 부분 절차의 연산/바인더 구조다. 모든 SOURCE 전체 상태
불변량이나 물리적 인과관계를 TARGET에 옮겼다고 증명한 것은 아니다. 미래의
Q3 불변량·전제조건 증거가 없으면 그 필드를 추측해서 만들지 않는다.

추가 한계: 같은 저자·같은 I/B/L 기판의 열린 SOURCE이며, 의미 계열 분리도
아니다. 현재 T는 역할/상수 적용의 유한 클래스다. 더 강한 동일 표현 권리의
고차 타입 합성 비교가 독립 평가 전에 필요하다. Q3 정책 학습 최종 산출물과
통합된 결과도 아니다.

## 8. 삭제·단순화와 다음 고가치 선택지

삭제한 것은 새 언어모델, 새 Q3 발견기, 문제별 전이기, 새 정답 생성기,
공통 그래프 언어 강제 변환, e-graph 구축, 승인 없는 FRESH 개봉이다.
상수/변수 적용과 실행 의미 검증만으로 되는 일은 그대로 고전 실행기에 맡겼다.

10배를 겨냥할 수 있는 다음 선택지는 가설이며 성과가 아니다.

1. Q3가 실제 제공하는 불변량·전제조건으로 불가능한 역할 대응을 먼저 제거한다.
   전체 상태 불변량과 독립 부분 절차의 정의역을 구분한다.
2. 검증된 대응의 유효 범위와 반례를 같은 Q3 정책으로 돌려줘 새 과제의 후보
   생성을 개선한다. Q6에 별도 학습 코어를 만들지 않는다.
3. 동일 역할 합성 권리의 강한 타입 기준선과 SOURCE 사례를 확보한 뒤, 원리와
   대응의 재사용 경제성을 실제 반복 workload에서 검증한다. 후보 수·점수만
   늘리는 인프라는 만들지 않는다.
