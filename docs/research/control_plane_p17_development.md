# P1.7 opened development — source-bound evidence with lazy coded semantic choice

P1.6 remains an immutable first 1/8 FAIL. Its evidence showed two residual
failure classes: deterministic serialization still leaked into neural output,
and freely regenerated arithmetic operands could drift from the source.

P1.7 P0 removed operand regeneration. Numeric/entity occurrences are referenced
by source spans and stable IDs; complete bounded grammar interpretations compile
through unchanged P1.5/P1.3 machinery. Unique interpretations use zero neural
work. Only a bounded candidate ambiguity may invoke the frozen non-generative
full-S4 selector.

This document freezes the first actual P1.7 opened-development study before any
P1.7 Gemma score is observed.

## Study composition

Twelve newly authored raw obligations:

- 4 unique sequential arithmetic tasks
- 4 unique finite-CSP tasks
- 4 bounded pronoun-binding CSP tasks

The first eight must be solved through the deterministic source-bound path with
zero model calls and zero neural forwards.

The final four use one public instruction:

> Resolve the single bounded pronoun by choosing the candidate interpretation
> that makes all stated constraints jointly satisfiable, then return a complete
> assignment.

The parser enumerates every declared-variable binding for the one registered
`It equals literal` clause, up to four candidates. Construction checks prove
before model scoring that exactly one candidate yields an answer accepted by the
independent original-obligation checker. This avoids a hidden arbitrary pronoun
label: the public obligation itself defines the selection rule.

Candidate counts are frozen as 2, 3, 4 and 3.

Four additional out-of-grammar construction controls must stop before any model,
executor or verifier authority.

## Authority and information boundaries

Public model/controller input contains only the registered instruction/query and
source-derived evidence/candidate structures. Private exact answers and original
CSP references never enter the selector prompt, candidate builder, compiler or
specialist.

Numbers and entity names are not regenerated by the model. Candidate atoms point
to original source occurrences. The selector may choose only among the complete
registered candidates and cannot create a new literal, entity, relation or
candidate.

Unique interpretation:

```
raw obligation
-> deterministic evidence extraction
-> one complete candidate
-> canonical compiler
-> P1.3 admission
-> specialist
-> independent original verifier
```

Ambiguous interpretation:

```
raw obligation
-> deterministic evidence extraction
-> complete bounded candidate set
-> frozen teacher-forced coded selector
-> canonical compiler
-> P1.3 admission
-> specialist
-> independent original verifier
```

The selector uses the unchanged frozen Gemma identity and original one-token
codes, all 24 code permutations and three batch/order modes. It performs no
free generation and no retry.
