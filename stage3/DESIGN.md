# 3단계 설계 (설계 채팅)

## 1. 출발점과 방향 (2026-11-25)
- 2단계는 `stage2/DESIGN.md` 11.18절로 닫혔다. 확립된 결론은 둘이다.
  - 길이 일반화는 컴파일된 구조에서 나온다.
  - 학습기는 유한한 국소 함수만 배운다.
- 그래서 3단계의 병목은 실행기가 아니라 **구조 발견이 닿는 범위**다.
- 서준이 (가)를 골랐다(2026-11-25): 구조 발견의 범위를 넓혀, 지금 언어로는 표현할 수 없는 과제를 연다.
- **북극성 (서준, 판단 원칙):** "NEUMANN이 훨씬 커지는 순간이 아니라, 이전에는 불가능했던 새로운 문제를 스스로 구조화하고, 그 구조를 더 작은 계산으로 실행하는 순간."
  - 과제를 고르는 거름망으로 쓴다. 통과/중단 기준은 아니다. 다음 둘을 모두 만족하는 과제만 판정 묶음에 넣는다.
    - **이전에는 불가능:** 표준 기준선이 분포 밖에서 실패한다(결정적 이김이 가능한 과제).
    - **스스로 구조화:** 필요한 구조가 사람이 과제별로 넣는 특징이 아니라, 과제와 무관한 언어 안에서 찾아져야 한다.

## 2. 1원칙 분석: 지금 언어(L0)의 정확한 한계
- **L0:** 헤드마다 이동 = 표[헤드, 현재 입력 토큰의 종류]다. 이동은 6종이고 한 step에 한 번이다. 답 단계에서는 종류가 늘 "답 단계"라, 헤드가 매 step 같은 이동만 한다(`stage2/DESIGN.md` 7.3절).
- 즉 L0에는 **제어 상태가 없다.** 막힌 과제를 원인별로 나누면 다음과 같다.

| 원인 | 예 | 필요한 확장 |
|---|---|---|
| 제어 상태 없음 (몇 step마다, 무엇을 읽은 뒤에) | 원소 두 번 쓰기, 번갈아 읽기, 두 번 이어 쓰기, MQAR | **L1: 유한 제어 상태** |
| 한 step에 한 칸 넘게 이동 | 짝·홀 분리(unzip), 2칸 건너 읽기 | L2: 출력 없는 내부 step |
| 출력 하나에 읽기 여러 번 (개수가 길이에 따라 늘어남) | N×M 곱셈 | L2 |
| 끝내는 시점이 아직 읽지 않은 값에 달림 | 뺄셈 | 형식 문제 (별도) |
| 값에 따른 횟수·비교 | 길이 부호 풀기, 정렬 | 값 조건 제어 (L1 밖) |

- **순서 판단:** L2(내부 step)는 "언제 출력할지"를 정해야 하므로 제어 상태를 전제로 한다. 그래서 L1이 먼저다. 한 번에 하나만 바꾼다(2-0a의 교훈).

## 3. L1의 정의 (과제 무관, 사전 고정)
L1은 **다중 헤드 유한 오토마톤 제어**다. 표준 계산 모델이고, 과제별 특징을 넣지 않는다.
- **제어 상태:** q ∈ {0, …, Q−1}, Q ≤ 4. 모든 헤드가 함께 쓴다. 처음 값은 0이다.
- **이동:** step t의 헤드 h의 이동 = μ_h(q_t, κ(x_t)).
  - κ는 L0의 토큰 종류 7개를 그대로 쓴다(`stage1/pf.py` `token_classes`).
  - 이동 6종과 그 의미, 인과성(읽기 ≤ t)은 L0과 같다.
- **읽기:** r_h(t) = tape[p_h(t)].
- **전이:** q_{t+1} = δ(q_t, κ(x_t), κ(r_1(t)), …, κ(r_H(t))). 상태는 지금 토큰과 방금 읽은 토큰의 **종류**로만 바뀐다. 값은 쓰지 않는다.
- **학생 입력:** C-1과 같다(읽기 + 구획 비트 + 한 칸 이동). 여기에 q_t의 원핫을 더한다. q는 입력 토큰의 종류만의 인과 함수다. 그래서 구획 비트와 같은 지위(상태 없는 구조 표지)를 갖는다.
- **L0 ⊂ L1:** Q = 1이면 L0과 같다.
- **L1이 여전히 못 하는 것:** 2절 표의 L2 이하 줄들이다. 3단계 주장 범위를 그렇게 한정한다.

## 4. 선행 연구 (질문을 정하는 시점의 대조, 원문 확인은 3-1 설계 전)
- **다중 헤드 유한 오토마톤 (k-head 2-way FA):** L1의 계산 모델 자체다. 새 모델이라고 주장하지 않는다.
- **RNN에서 오토마톤 추출:** Omlin·Giles, 그리고 Weiss·Goldberg·Yahav(ICML 2018, L* 기반).
  - 차이 후보 [추정]: 우리는 언어 인식기가 아니라 **어디를 읽을지의 제어기**를 교사의 의존도에서 뽑는다. 그리고 그것으로 교사가 못 하는 길이 일반화를 얻는다.
- **Learning Transformer Programs**(Friedman 외 2023)과 RASP-L(Zhou 외 2023), Tracr: 이산 프로그램 학습과 길이 일반화 추측이다.
- **SAT 기반 최소 오토마톤 식별**(Heule·Verwer 2010): 3-1 컴파일(자동 합성)의 도구 후보다.
- NTM·DNC: 미분 가능한 주소 지정. 우리는 학습 후 이산 컴파일이다.
- 3-1 설계 전에 위 원문을 대조한다. 특히 "트랜스포머 교사에서 라우팅 오토마톤을 추출해 길이 일반화"한 선행 연구가 있는지 확인한다.

## 5. 3-0: L1 관문 (먼저 한다, 자동 합성 없음)
**질문:** 과제 무관한 L1에서, 표준 기준선이 분포 밖에서 실패하고 L0로는 표현할 수 없는 과제 4개 중 ≥3개가 다음을 모두 만족하는가?
- L1로 표현된다.
- 오라클 학생이 분포 밖으로 일반화한다.
- 교사가 그 구조의 "어디"를 안다.

**이 결과로 바뀌는 결정**
- 예: 통과한 과제를 3단계 판정 묶음으로 동결한다. 다음은 3-1(교사 의존도에서 L1 프로그램을 자동 합성)의 설계다.
- 아니오: L1이나 과제 묶음을 바꿀지 설계 채팅이 정한다. 자동으로 고치지 않는다.

### 5.1 과제 (판정 4개 + 기록 1개)
- 숫자 과제 규약은 G-0과 같다. 학습 1–10, 분포 안 1–10, 분포 밖 11–20 / 21–30 / 31–40이다. 어휘는 `stage2/g_tasks.py`이고, 생성 시드 규칙은 1단계와 같다.
- BOS는 기본으로 쓰지 않는다. 손 프로그램에 왼쪽 끝 감지가 필요하면 H-0 BOS 규약을 그 과제에만 쓴다. 이 선택은 학습 전 A1 단계에서 정하고 기록한다.

| 과제 | 형식 | 무엇이 L1을 요구하는가 [설계 채팅의 손 풀이 스케치] |
|---|---|---|
| dup (두 번 쓰기) | s =  →  s0 s0 s1 s1 … | 헤드 하나가 두 step에 한 번 오른쪽으로 간다. q가 번갈아 바뀐다(Q = 2). |
| interleave (번갈아 쓰기) | a + b =  →  a0 b0 a1 b1 … (\|a\| = \|b\| = n) | q = 0이면 A가, q = 1이면 B가 움직인다. 출력은 q에 따라 A 또는 B의 읽기다(Q = 2). |
| repeat (두 번 이어 쓰기) | s =  →  s s | A가 앞서 가다 `=`를 읽으면 q가 0에서 1로 바뀐다. 그 뒤 B가 0부터 움직인다. **상태가 읽은 종류로 바뀌는 과제다.** |
| pairswap (짝 바꾸기) | s =  →  s1 s0 s3 s2 … (n은 짝수: 학습·분포 안 2–10, 분포 밖 12–20 / 22–30 / 32–40의 짝수) | 두 헤드는 늦게 출발하는 것만 빼면 정렬된 흐름이다. 출력 선택이 q의 홀짝에 달린다(Q ≤ 3). |
| MQAR (기록만) | 1단계 형식 | `\|`에서 start, 질의 step에서 content, 답 step에서 start다(Q = 2). 기준선이 강해서(looped_rr 2구간 0.932) 판정에서 뺀다. L1이 내용 조회를 덮는지만 기록한다. |

- **스스로 구조화의 정직한 한계:** dup·interleave·pairswap의 q는 사실상 "답 step 수 mod m"이다. 사람이 그 특징을 넣으면 풀린다.
  - 상태가 입력에 따라 바뀌는 과제는 repeat 하나다.
  - 그래서 3단계 판정 묶음이 통과해도 "상태 자동 발견"의 증거는 repeat에서 가장 강하다. 이것을 미리 적어 둔다.

### 5.2 검사 (과제마다, 순서대로, 싼 것부터)
- **A0. 회귀 (전체 1회):** L1 구현에 Q = 1을 넣고 C-1의 15개 표를 실행한다. 기존 L0 읽기 경로와 모든 step이 일치해야 한다(1.000). 아니면 멈춘다.
- **A1. L1 표현력:** Claude Code가 손 프로그램(Q, μ, δ)을 쓰고, 2,000개(분포 안) + 구간별 500개(분포 밖)에서 검사한다.
  - (b) p_h(t) ≤ t: 1.000.
  - (c′) 인과 불변성: t 뒤 토큰을 바꿔도 t까지의 읽기 위치·구획 비트·q가 같다(t ≥ t0 step). 1.000.
  - 정답 읽기: `<eos>`를 뺀 채점 step에서, 손 프로그램이 지정한 **출력 공급 헤드**의 읽기가 출력 토큰과 같은 비율이다. 1.000. 다섯 과제 모두 복사 계열이라 정의된다.
  - (d) 국소 결정성: 키 = (읽은 토큰, 구획 비트, q, 이전 칸의 키). 모든 구간에서 충돌 0. 키 덮임은 기록만 한다.
- **A2. L0로는 안 됨 (오라클 의존도):** step마다 출력 공급 헤드의 읽기 위치 하나에 의존도 1을 둔다. 복사 계열에서는 이것이 참 의존이다. 이 오라클 의존도로 기존 L0 전수 컴파일(`stage1/c3_compile.py` 방식, 헤드 3개 탐욕 덮기)을 돌린다.
  - 다음 중 하나면 "L0 밖"이다: 최고 L0 표의 덮임이 0.99 미만, 또는 그 표의 읽기로 (d)를 쟀을 때(q 없이) 어느 구간에서든 충돌이 0보다 크다.
  - 둘째 조건이 필요한 이유: pairswap처럼 L0 헤드 둘이 읽기는 모두 덮지만, 출력 선택에 상태가 필요한 과제가 있다.
  - L0 안이면 그 과제는 L1 시험으로서 정보가 없다. 탈락한다.
- **D. 오라클 학생:** 손 프로그램의 읽기 + 구획 비트 + q를 받은 C-1 학생(d 128, 헤드 4, 4층, NoPE, 1단계 학습 규약)을 재시작 1개(시드 30)로 돌린다.
  - 분포 밖 1·2구간 ≥0.90이어야 통과다.
  - 대조로 q를 0으로 둔 같은 학생도 1개 돌린다. 기록만 하며, q를 실제로 쓰는지 보는 것이다.
- **C. 기준선 (판정 4과제):** `abacus`, `rope`, `looped_rr`, `gru`를 시드 0으로, 1단계 학습 규약대로 돌린다.
  - 기준선 최고 2구간 ≤0.60이면 "결정적 이김 가능(이전에는 불가능)"이다.
  - 허용 예산(20,000 step FLOPs 최대)도 기록한다.
- **B. 교사가 "어디"를 아는가:** rope 기준선(시드 0)의 판정 체크포인트를 교사로 쓴다. 의존도 추출은 C3과 같다(첫 2,000개, 기울기 노름).
  - 손 프로그램 읽기의 의존도 덮임이 전부 정지 표의 ≥2배여야 통과다(13.2절 규칙).
  - 교사의 분포 안 정확도와 헤드별 덮임은 기록만 한다. 완성은 요구하지 않는다(H-0b).

### 5.3 판정 (사전 고정)
- 과제가 통과하려면 A1, A2, D, C, B를 모두 만족해야 한다.
- **예:** 판정 4과제 중 ≥3개 통과. 통과 과제를 3단계 판정 묶음으로 동결하고 3-1을 설계한다.
- **아니오:** ≤2개. 과제별로 무엇에서 멈췄는지 보고하고, 설계 채팅이 정한다.
- 과제 교체는 이 관문에서 최대 한 번이다(규칙 7).
- **조기 종료:** A0 → A1 → A2 → D를 먼저 한다(학습은 D뿐, 분 단위). 여기서 통과 가능한 과제가 3개 미만이면 C·B(기준선 학습) 전에 멈추고 보고한다.

- C: 16회(4과제 × 4기준선)다. 4개 병렬로 4–8시간이다(1단계 MQAR 기준 회당 0.3–1.8시간).

### 5.5 검토 기록 (8항목)
1. **선행 연구:** 4절. 계산 모델(다중 헤드 FA)은 새것이 아니다. 주장은 "교사에서 자동으로 찾는다"에 둔다(3-1).
2. **결정을 바꾸는가:** 판정 묶음을 동결하거나, L1·과제를 다시 정한다.
3. **기준 충족 가능성:** 손 스케치가 4과제 모두에 있다(5.1). A1이 그것을 확인한다.
4. **교란:**
   - q는 입력 종류만의 함수라 정답 정보가 없다. (c′)가 확인한다.
   - 대부분의 상태가 step 계수기라는 한계는 5.1에 적었다.
5. **비용:** 5.4.
6. **재현:** 1단계·2단계 규약과 같다. `env.json`, 첫 결과는 덮어쓰지 않는다.
7. **비교 기준:** 4기준선, 시드 0이다. position coupling은 과제별 손 설계라 상한 참조로도 넣지 않는다(E-0 입장). 발표 전 확인 목록(`FUTURE.md`)에 올린다.
8. **누출:** (b)·(c′)·정답 읽기 검사다. MQAR은 질의가 프롬프트 밖(답 구간)에 있다. content 이동은 p < t만 보므로 인과적이다.

  - 허용 예산: dup 5.08e14, interleave 6.88e14, repeat 5.08e14, pairswap 3.46e14.
- **기록할 해석: 상태는 라우팅에 필요하고, 학생 출력에는 대부분 필요 없다.**
  - q = 0 학생은 dup·interleave·repeat·MQAR에서 1.000이고, pairswap만 떨어졌다(0.974 · 0.892 · 0.836).
  - L1의 상태가 하는 일은 주로 "읽기 경로를 만드는 것"이다(A2가 L0로는 안 됨을 보였다). 출력 선택까지 상태가 필요한 것은 pairswap이다.
  - 그래서 3단계 주장은 **라우팅의 자동 구조화**에 둔다. q를 학생 입력에 넣는 것은 3절 정의대로 유지한다(무해하고 인과적이다). 판정 묶음을 pairswap으로 좁히지 않는다.
- **설계 채팅의 오류 둘:**
  - 3-0 브랜치를 "main에서 새로 만든다"고 적었다. 코드는 작업 브랜치에만 있다. `stage2/c` 병합으로 대응한 것을 받아들인다. 앞으로 main은 설계·규칙 문서만 둔다.
  - repeat 스케치의 전환 시점이 한 step 늦었다. "상태별 출력 공급 헤드"라는 틀에서는 Claude Code의 한 칸 앞 헤드 판이 맞다.

### 6.2 Claude Code 질문에 대한 답
1. **q가 필요한 과제를 pairswap 하나로 볼 것인가:** 아니다(6.1 해석). 판정 묶음은 4과제 그대로다. 보고에는 "학생 출력에 q가 필요한 과제는 pairswap"을 범위로 적는다.
2. **repeat 한 칸 앞 헤드 판을 정본으로:** 예. 다만 손 프로그램은 참조일 뿐이다. 3-1 판정은 자동 합성한 프로그램으로 하고, 손 프로그램을 재현할 필요는 없다.
3. **정의 확정:** 모두 받아들여 앞으로의 정의로 고정한다.
   - A2의 주값은 eos 제외이고, eos 포함은 기록한다.
   - (d) 충돌은 두 셈(구간 안 충돌 + 학습 표와 어긋난 step)의 합이다.
   - κ(r)는 읽은 위치의 종류이고, 답 단계 위치는 answer_phase다.
   - MQAR의 t0는 첫 질의 step이다.
   - q는 원핫 임베딩을 더한다.
4. **동결과 3-1:** 이 절이다.

### 6.5 합성 방법 (사전 고정, 과제 무관)
- **목적 함수 (C3을 L1로 일반화):** 프로그램 (Q, μ, δ)의 헤드 경로가 출력 step마다 덮는 의존도의 합이다. 위치는 한 번만 센다(헤드 3개의 합집합).
  - 의존도는 C3과 같다: 정답 토큰 로짓의 입력 임베딩 기울기 노름을 step마다 정규화한 것이다.
  - C3의 탐욕 덮기와 달리 세 헤드를 **함께** 최적화한다. 공동 최적은 탐욕 이상이다.
- **풀이: 제약 최적화 (OR-Tools CP-SAT), Q = 1, 2, 3, 4 각각.**
  - 변수: μ와 δ의 표 칸(원핫), 예마다 step별 상태 q_t와 헤드 위치(위치 ≤ t).
  - 제약: 이동 후보 위치는 `pf.candidates`로 미리 계산한다. 그래서 경로가 L1 기계 실행과 정확히 같다.
  - 목적: 덮은 의존도(정수로 반올림, ×1000)를 최대화한다.
  - 동점 처리는 사전순이다: 덮임이 먼저다. 다음은 "정지"가 아닌 μ 칸 수, 그다음은 상태를 바꾸는 δ 칸 수이고, 둘 다 적을수록 좋다. 덮임 해상도보다 작은 가중치로 넣는다.
  - 표본: 교사 학습 데이터의 처음 100개다. 합성이 끝난 뒤 처음 2,000개에서 덮임을 다시 재서 기록한다.
  - 상한: (과제, 교사, Q)당 600 CPU초다. 최적 증명 여부와 격차를 기록한다.
  - 합성 계산은 C3 컴파일처럼 CPU초로 따로 보고하고, FLOPs에 합치지 않는다.
- **중복 제거:** Q = k 해의 경로가 2,000개 모두에서 더 작은 Q 해와 같으면 버린다(실제로 쓰는 상태가 적다는 뜻이다).
- **선택 (C4·G-0 오컴 선택, I-0a 결정):** 남은 후보(Q별 최대 4개)마다 C-1 학생(+q)을 재시작 2개로 학습하고, 선택용 검증(`select:<과제>`, 분포 안 1,000개)으로 고른다.
  - 5/1,000 이내는 동점이고, 동점이면 작은 Q, 그다음 작은 재시작 번호를 고른다.
  - **알려진 위험:** 선택용 검증은 분포 안이다. 분포 안을 맞히지만 일반화하지 않는 프로그램이 뽑힐 수 있다. 2단계에서는 틀린 표의 학생이 분포 안에서 낮았다(0.04–0.19). 이번에도 Q별 선택용 값을 모두 기록해 이 위험을 본다.

### 6.6 3-1a: 합성 관문 (교사 학습 전, CPU만, 먼저 한다)
세 검사를 모두 통과해야 본실행으로 간다. 하나라도 아니면 멈추고 보고한다.
1. **오라클 회복 (5과제, MQAR 포함):** 의존도 = 손 프로그램의 출력 공급 위치 원핫(A2와 같다).
   - 가장 작은 Q의 최적 해가 오라클 덮임 1.000이어야 한다.
   - 그 해로 A1 검사 전체를 돌려 (b)·(c′)·정답 읽기 1.000, (d) 충돌 0이 모든 구간에서 나와야 한다.
   - 손 프로그램과 같을 필요는 없다.
2. **L0 회귀 (C-1의 15개 표):** 의존도 = 그 표 경로의 원핫(움직이는 헤드 균등). Q = 1 해의 덮임이 1.000이어야 하고, 출력 step의 읽기 위치가 그 표와 같아야 한다.
3. **실제 교사 의존도 (3-0 B의 rope 시드 0, 판정 4과제):** 이미 추출한 의존도를 쓴다. Q별 최적 해의 덮임 중 최고값이 손 프로그램 덮임 −0.01 이상이어야 한다(탐색이 손 프로그램만큼은 찾는지 본다).
   - 기록만: Q별 덮임, 출력 공급 위치의 일치율(손 프로그램 대비), (d) 충돌.
- 6.6-3은 실패 원인을 가른다. 덮임이 손보다 낮으면 **탐색 실패**다. 덮임은 충분한데 학생이 지면 **목적 함수 실패**다.

### 6.9 3-1 재검토 (2026-11-25, 설계 채팅, 실행 전) — 6.5–6.7절보다 우선
1. **프로그램 선택을 "분포 안 길이 외삽"으로 바꾼다 (가장 중요한 수정).**
   - **문제:**
     - Q가 커질수록 기계의 용량이 커져, 합성 표본의 덮임은 늘 같거나 오른다. 상태가 많은 해는 학습 길이에서만 맞는 경로(잡음 추종)일 수 있다.
     - 6.5의 학생 선택용 검증은 분포 안이라, 이런 해를 거르지 못한다.
   - **1원칙:** 구조가 맞다면, 합성에 쓰지 않은 더 긴 길이에서도 교사의 "어디"를 설명해야 한다. 교사는 학습 범위 안의 모든 길이에서 믿을 만하다. 그래서 정답 없이 분포 안에서 길이 일반화를 시험할 수 있다.
   - **새 규칙:**
     - 합성 표본은 교사 학습 데이터 중 길이 1–7인 처음 100개다(pairswap은 2–6).
     - 선택용 집합은 길이 8–10인 처음 300개다. 선택은 이 집합의 덮임으로 한다.
     - 차이가 0.005 이내면 동점이고, 동점이면 작은 Q를 고른다.
     - 학생은 고른 프로그램 하나에만 재시작 2개(s + 10, s + 110)로 학습하고, 선택용 검증으로 재시작을 고른다(C-1과 같다).
   - I-0a의 "표는 학생 쪽에서 판단" 원칙과 다르다. 이유는 위 문제다. 선택이 맞았는지는 Q별 손 프로그램 일치율(기록)로 사후에 본다.
2. **보지 못한 칸의 기본값을 정한다.**
   - 시간 상한 안에 최적이 증명되지 않으면, 합성 표본에서 한 번도 쓰이지 않은 표 칸이 임의 값으로 남는다. 분포 밖에서는 그런 칸이 쓰일 수 있다.
   - 그래서 합성 뒤에 합성 표본에서 쓰이지 않은 μ 칸은 "정지"로, δ 칸은 "그대로(q 유지)"로 덮어쓴다. 오컴 기본값이며, 결과와 무관하게 미리 정한다.
3. **오라클의 eos step:** 출력 공급 위치는 `<eos>` step에서 정의되지 않는다. 그래서 eos를 정할 정보가 오라클에 없을 수 있다.
   - `<eos>` step의 오라클 의존도는 그 step에서 손 프로그램의 (상태별) 공급 헤드가 읽는 위치로 둔다. 이 위치는 끝 표지를 읽는 자리다.
4. **L0 회귀의 비교:** 헤드 번호는 바뀔 수 있다. 출력 step마다 움직이는 헤드의 읽기 위치를 **집합으로** 비교한다.
5. **6.6-3 문턱의 기준 집합:** 합성 해와 손 프로그램의 덮임을 모두 같은 2,000개(3-0 B와 같은 집합)에서 잰다.

4. **출력 상태 합성 (pairswap 오라클 실패에 대한 원리적 수정).**
   - **1원칙:** 라우팅 목적 함수(어디를 읽는가)는 "읽은 것 중 무엇을 낼지"에 필요한 상태를 보상하지 않는다. 그 상태는 (d) 국소 결정성이 정의한다. 같은 국소 키인데 출력이 다르면, 그 둘을 가르는 상태가 필요하다.

   - **방법:** 라우팅(μ, 경로)은 고정한다. 출력 상태 q′ ∈ {0, …, Q′−1}와 전이 δ′(q′, q, κ(x_t), 읽은 종류들)을 CP-SAT로 합성한다.

5. **정답 읽기 정의:** (ii)로 확정한다. 출력 step(eos 제외)마다 어떤 헤드든 오라클 공급 위치를 읽는 비율이다. 합성 프로그램에는 공급 헤드가 지정되지 않으므로 (i)은 정의가 안 된다. 핵심 기준은 오라클 덮임 1.000과 (d) 충돌 0이다.

1. **L1 필요성은 추정이 아니라 측정이다 (7.4의 [추정]을 고친다).**
   - A2′(경로 무관, Q = 1 최적, eos 제외)에서 L0가 덮은 step 비율(합성 표본 / 길이 8–10):
     - dup: 0.896 / 0.780
     - interleave: 0.671 / 0.490
     - pairswap: 0.938 / 0.824
     - repeat: 1.000 / 1.000
   - 그러니 **세 이긴 과제 모두 라우팅부터 L0 밖이다.** pairswap도 출력 상태만이 아니라 늦게 출발하는 헤드 때문에 라우팅에 L1이 필요하다. 7.4의 "pairswap의 L1 필요성은 출력 상태에 있다"는 틀렸다.
   - repeat는 값 라우팅이 L0로 되고, 끝 판단만 구조가 필요하다.
2. **빠진 기준선 (규칙 4, 발표 전 필수):** 무작위 위치 부호화(Ruoss 외, ACL 2023)는 길이 일반화를 위한 알려진 일반 기법이다. 우리 네 기준선에 없다.
   - 그 논문에서도 Duplicate String(우리 repeat와 같은 형태)은 길이 41–500에서 75.1%다(무작위 relative, 기회 수준 50%) [정확도가 토큰 단위인지 원문 확인 필요].
   - 그래서 판정이 바뀔 가능성은 낮다 [추정]. 하지만 "기준선이 전혀 못 한다"를 외부에 말하기 전에 같은 조건으로 돌려야 한다.
   - `FUTURE.md`의 발표 전 확인 목록에 넣는다. 이미 있는 항목은 Abacus 논문 규모, position coupling, 기준선 다중 시드다.
3. **선택이 필요 이상의 상태를 고른다 (기록).**
   - dup은 손 프로그램이 Q = 2인데, 교사 41·42에서 Q = 3, 교사 43에서 Q = 4가 골라졌다. 설명률이 동점이면 덮임이 상태 수보다 먼저이기 때문이다.
   - 이번에는 이겼지만, 쓰지 않는 상태가 늘면 분포 밖 위험이 커진다. 3-2 설계에서 순서를 다시 본다(덮임 동점 폭 대 상태 수).
4. **3-2의 첫 항목이 왜 "구조 설명률을 합성 목적에 넣기"인가 (1원칙).**
   - 프로그램이 일반화하려면 두 정보원이 필요하다.
     - **(가) 값의 출처:** 교사 의존도.
     - **(나) 무엇을, 언제:** 데이터의 구조적 일관성.
   - 지금은 (가)로 **만들고** (나)로 **고른다.** 그래서 (나)만으로 보이는 구조(끝 표지·경계)는 만들어지지 않는다. repeat와 2단계 뒤집기가 같은 원인이다.
   - L2(출력 없는 내부 step)의 핵심은 "언제 출력하는가"다. 이것은 정의상 (나)의 구조이고, 교사 의존도에는 보이지 않는다.
   - 그러니 (가)와 (나)를 한 목적으로 합성하는 것은 L1을 완성하는 일이면서 **L2의 전제 조건**이다. 순서상 먼저다.
5. **효율 비교의 기준을 적는다.** 7.4의 기준선 시간은 "가장 높은 정확도를 낸 기준선의 학습 시간"이다(6.9-8). 가장 빠른 기준선(rope, 예: dup 944초)과 비교하면 파이프라인 CPU는 수 배다. 합성 비용 절감이 효율 주장의 남은 과제다.

### 8.3 3-B 사전 등록
- **질문:** 알려진 길이 일반화 기법 두 가지를 같은 규약으로 넣어도, 지금까지 "결정적 이김"으로 기록된 과제에서 기준선 최고 2구간이 ≤0.60으로 남는가?
- **새 기준선 둘:** 1단계 규약(1M, N = 100,000, 20,000 step, 판정은 분포 안 최고 체크포인트)에서 위치 부호화만 바꾼다.
  - **`rope_rand`:** 무작위 위치 부호화(Ruoss 외, ACL 2023).
    - 학습과 평가 모두 순서마다 위치 {0, …, L−1}에서 길이만큼을 중복 없이 뽑아 정렬한 뒤 RoPE에 넣는다. L = 512다(가장 긴 평가 순서의 3배 이상).
    - 평가의 위치 추출 시드는 고정한다.
  - **`nope`:** 위치 부호화 없음(인과 마스크만). Kazemnejad 외 2023의 NoPE다.
- **과제와 형식:** 판정에 쓴 형식 그대로 아홉 과제다.
  - 3단계: dup·interleave·repeat·pairswap.
  - 2단계: 덧셈(C4), 복사·N×1·누적합(G-0′), 뒤집기(H-0 BOS 형식).
- **시드:** 0이다(기존 기준선과 같다).
- **판정 (주장 갱신 규칙, 사전 고정):**
  - 과제마다 기준선 최고를 새 기준선까지 포함해 다시 계산한다.
  - 2구간이 0.60을 넘는 과제는 "결정적" 표시를 거둔다.
  - 7.7절 기준 2(기준선 최고 −0.01 이상)를 다시 적용해, 이김이 유지되는지도 기록한다.
  - **질문에 대한 답:** "결정적"이 모든 과제에서 유지되면 예, 하나라도 거둬지면 아니오(과제 목록과 함께)다.
- **학습 전 확인:** 두 기준선의 분포 안 정확도를 rope와 함께 기록한다. 분포 안이 0.95 미만인 과제는 학습률 3개(1단계 규약의 기본값과 그 ×0.5, ×2)로 다시 돌려 최고값을 쓴다. 기준선을 약하게 만들지 않기 위해서다(규칙 4).
- **비용 [추정]:** 18회(+ 재시도)다. rope와 같은 크기이므로 회당 0.3–1시간, 4개 병렬로 3–5시간이다.

### 8.4 (C) L2의 근본 문제 (기록, 다음 설계의 출발점)
- 출력 없는 내부 step은 학습 데이터에 정답이 없다. 그래서 교사 강요 학습으로 그 step의 내용을 가르칠 수 없다.
- 해법 후보는 셋이다. 셋 다 지금의 "단단한 읽기 + 국소 함수" 원리와 충돌하거나 사람 설계를 들여온다. 설계는 3-B와 3-2 뒤에 한다.
  - (i) 사람이 설계한 중간 기록(scratchpad) 형식.
  - (ii) 학생의 잠재 상태(1단계에서 약점이었다).
  - (iii) 내부 step 동안 읽기만 옮기고 값 계산은 하지 않는 형태(표현력이 제한된다).

**수정**
1. **`rope_rand`를 `rel_rand`로 바꾼다.** 논문의 최강 변형인 무작위 relative다.

     - R은 사인·코사인 상대 거리 부호화다. u, v는 학습되는 편향이다.

     - 무작위 추출을 끄고 π = 0, 1, …로 두면 표준 relative 주의와 수치가 같다.
2. **`nope`는 그대로 둔다.** 기제가 다른 일반 기법이라 싸고 정보가 있다.
3. **학습률 조율 (기준선에 유리하게, 사전 고정):**

  - 구현 확인 세 가지는 모두 1.000이다.
- **Claude Code 질문 (π가 전체 길이에서 뽑혀 길이가 새는 문제): 그대로 기록한다.**
  - 이 누출은 기준선에게만 유리하다. 위치 간격이 전체 길이(덧셈·N×1의 마지막 올림 여부 포함)를 알려 주기 때문이다.
  - 그런 유리함이 있는데도 실패했으므로 결론은 더 단단하다. 길이 없는 변형으로 바꿔도 바뀌는 결정이 없다(규칙 2).
- **남는 한계 (발표 전 확인 목록에 둔다):**
  - 기준선 시드는 0 하나다(Ruoss 외는 시드 10개 중 최고).
  - 기준선은 1단계 규약의 조기 종료(분포 안 ≥99% 두 번 연속)로 멈췄다. 오래 학습하면 분포 밖이 늦게 오를 가능성은 rel_rand에서 확인하지 않았다. E-0는 덧셈에서 일반 방법 10배 계산을 확인했다.
- **주장 갱신:** "결정적 이김" 8개(2단계 다섯, 3단계 셋)의 근거가 알려진 기법 여섯(Abacus, RoPE, looped, GRU, 무작위 relative, NoPE)으로 넓어졌다. repeat는 3-1에서 진 그대로다.

### 8.7 방향 재검토 (2026-11-26, 설계 채팅): 가장 큰 신뢰성 공백은 "과제를 우리가 골랐다"는 것이다
**원자 분해: 지금까지 주장의 근거에서 무엇이 가장 약한가**
1. **과제 선택 편향 (가장 크다).**
   - 결정적 이김 8개는 모두 우리가 고른 과제다.
   - 게다가 우리 언어로 표현되는지를 먼저 확인하고 걸렀다(G-0a, H-0a, 3-0 A1). 뺄셈·패리티·MQAR·unzip처럼 표현되지 않는 과제는 판정 묶음에서 빠졌다.
   - 그래서 "8개 이김"은 "이 방법이 얼마나 넓게 통하는가"를 말해 주지 않는다.
   - 북극성의 "이전에는 불가능했던 새로운 문제를 스스로 구조화"에도 같은 공백이 있다. 지금은 문제를 우리가 정했다.
2. **같은 정보를 받은 기준선이 없다.** 학생은 토큰 종류·구획 비트 같은 구조 표지를 받는다. 기준선은 받지 않는다(Abacus의 자릿수 위치는 일부 비슷하다).
   - C-1에서 "읽기를 지우면 0.000–0.006"은 이득이 단단한 읽기에서 온다는 것을 보였다.
   - 그러나 "표준 트랜스포머에 같은 구조 표지만 주면?"이라는 대조는 아직 없다.
3. **기준선 시드 1개, 조기 종료 규약** (8.6 한계).
4. **선행 연구 대조가 체계적이지 않다** (LTP, RASP-L, 오토마톤 추출, Rational Transductors, C-RASP).

**판단**
- 1번이 논문과 북극성 모두에서 가장 큰 공백이다.
- 해법은 이미 있는 **외부 벤치마크**다. Delétang 외(ICLR 2023)의 15과제이고, Ruoss 외(2023)도 쓴 공개 묶음이다(정규 4, 결정적 문맥 자유 4, 문맥 의존 7).
- 우리가 고르지 않은 과제 **전부**에 대해 미리 정한 규칙으로 보고하면 두 가지를 정직하게 보여 줄 수 있다.
  - 몇 개가 표현되는가(범위).
  - 표현되는 것 중 몇 개를 이기는가(효과).
- 결과가 작아도 그 숫자 자체가 주장의 정확한 크기다.

**정리 단계의 순서 제안 (서준 결정 대기, 사전 등록은 결정 뒤에)**
1. **외부 벤치마크 표현력 조사 (학습 없음, 싸다):** 15과제 각각에 대해 L1 손 프로그램이 있는지 확인한다(3-0 A1 방식).
   - 출력이 한 토큰인 분류형 과제와 값 상태가 필요한 과제는 "범위 밖"으로 미리 분류하고 그대로 보고한다.
2. **표현되는 과제에서 3-1 파이프라인 그대로 실행 + 6개 기준선.** 처음 보는 시드를 쓰고, 7.7절 판정이다.
3. **같은 정보 기준선:** 표준 트랜스포머에 토큰 종류·구획 번호 임베딩을 더한 것이다(9과제 + 외부 표현 과제).
4. **기준선 다중 시드와 조기 종료 없는 학습 확인** (8.6 한계).
5. **체계적 선행 연구 대조 → 논문 초안.**
- 1–4는 각각 결과가 주장 범위를 바꾼다(규칙 2 충족).
- 3-2(끝 표지 합성)와 L2는 이 단계 뒤에 한다. 외부 벤치마크의 실패 목록이 그다음 연구 질문을 정해 준다. 이것이 "다음에 무엇을 풀지"를 우리가 고르지 않게 하는 방법이기도 하다.

## 9. 두 갈래로 간다 (2026-11-26, 서준 결정: "정리·우선권과 L2 둘 다")
- **갈래 A (정리·우선권):** 실행은 Claude Code가 한다. 계산이 대부분이다.
- **갈래 B (L2 설계):** 설계 채팅이 한다. 생각과 선행 연구가 대부분이다.
- 서로 막지 않으므로 함께 진행한다. 실험은 한 번에 하나다(규칙 1). 그래서 Claude Code는 갈래 A만 실행하고, 갈래 B의 실험은 설계가 확정된 뒤 순서에 넣는다.

### 9.1 갈래 A 첫 단계: 3-E0 외부 벤치마크 표현력 조사 (사전 등록)
- **질문:** Delétang 외(ICLR 2023) 15과제 중 몇 개가 L1(3절)로 표현되는가? 몇 개가 L0로 되는가? 나머지는 어떤 원인으로 밖인가?
- **이 결과로 바뀌는 것:**
  - 3-E1(파이프라인 + 기준선 6개) 과제 목록이 정해진다.
  - 표현 밖 과제의 원인 분포가 갈래 B의 첫 대상을 정한다(8.7: 다음 문제를 우리가 고르지 않는다).
- **과제 정의:** 공개 코드(`google-deepmind/neural_networks_chomsky_hierarchy`)의 생성 규칙을 그대로 옮긴다(`stage3/e_tasks.py`). 원본 커밋 해시를 기록한다.
- **형식 (모든 과제에 같은 규칙, 과제별 선택 없음):**
  - `<BOS> 입력 <sep> 출력 <eos>` 자기회귀 형식이다. BOS는 H-0 이후 규약대로 모든 과제에 둔다.
  - 분류 과제는 출력 토큰 하나 뒤 `<eos>`다.
  - **종류(κ) 대응 규칙:** 데이터 기호는 `digit`, 연산·명령 기호는 기호마다 `op`, 입력과 출력 사이 구분자는 `=`, 그 밖의 특수 기호는 `other`다. 과제별 대응 표를 보고한다.
- **길이:** 벤치마크가 정의한 입력 길이 n에 우리 규약을 쓴다. 학습 1–10, 분포 밖 11–20 / 21–30 / 31–40이다.
  - 벤치마크 원래 규약(학습 ≤40, 시험 41–500)과 다르다는 점을 보고와 논문에 적는다.
- **방법 (학습 없음):**
  - 과제마다 L1 손 프로그램(Q ≤ 4, 헤드 3)을 쓰고 3-0 A1 검사를 한다.
    - (b)·(c′) 1.000.
    - 복사형이면 정답 읽기 (ii) 1.000.
    - 값 키 (d) 충돌 0, 모든 구간.
  - L0(Q = 1) 손 표도 같은 검사로 시도한다.
  - **표현 밖 판정:** 손 프로그램을 찾지 못한 과제는 원인을 2절 표의 분류 중 하나로 적고 논증을 붙인다. 분류는 다음 중 하나다:
    - 값 상태 필요(누적·패리티·mod 등)
    - 한 step에 한 칸 넘게 이동
    - 출력 하나에 읽기가 길이에 따라 늘어남
    - 값에 따른 제어
    - 그 밖
  - 설계 채팅이 이 논증을 확인한다.
- **설계 채팅의 사전 예상 [추정, 결과로 확인]:**
  - L1 안: Reverse String, Duplicate String(끝 표지 맹점은 3-1과 같음), Even Pairs(첫 토큰 = 마지막 토큰), Binary Addition(자리 순서에 따라 다름).
  - 밖: 값 상태가 필요한 분류 과제 대부분. Odds First(한 step 두 칸), Binary Multiplication·Compute Sqrt(출력당 읽기가 늘어남). Stack Manipulation·Bucket Sort는 판단을 보류한다.
- **비용:** CPU 분–시간 단위다. 보고하고 멈춘다. 3-E1 목록은 설계 채팅이 동결한다.

### 9.2 갈래 B: L2 설계 메모 (초안, 사전 등록 전)
**문제 (8.4):** 출력 없는 내부 step에는 학습 정답이 없다. 1원칙으로 쪼개면, 내부 step이 하는 일은 두 종류다.
1. **라우팅만 하는 내부 step:** 헤드를 더 옮기기만 하고 값은 계산하지 않는다.
   - 학생은 출력 step의 읽기만 보므로, 이 step에는 **감독이 필요 없다.**
   - 이것은 프로그램(제어기)의 일이다. 교사의 "어디" 신호는 출력 step에서 이미 주어진다.
   - 열리는 과제: 한 step 두 칸(Odds First, unzip), 조건을 만날 때까지 건너뛰기(값 종류에 따른 탐색).
2. **값을 나르는 내부 step:** 중간 결과(부분곱·부분합)를 만든다. 이것은 감독이 필요하다. 곱셈이 여기에 속한다.

**후보와 판단**
- **L2a = 라우팅 전용 내부 step:** 언어 변경 한 가지다. 제어기가 "이번 step에 낼지, 한 번 더 움직일지"를 정한다(출력 없는 이동 step 허용).
  - 감독 문제가 없다.
  - 다만 "언제 내는가"는 정의상 교사 의존도에 보이지 않는 구조다. 그래서 3-2의 원리(구조 설명률을 합성 목적에 넣기, 7.7-4)가 여기서 필수가 된다.
  - **결론: 3-2는 L2a 안에 흡수한다.**
- **L2b = 컴파일된 프로그램의 합성(라이브러리):** 값을 나르는 중간 결과를 데이터 대신 **이미 길이 일반화가 확인된 하위 프로그램**이 만든다.
  - 예: N×M = 자리마다 N×1, 자리 이동, 덧셈.
  - 감독은 하위 프로그램이 스스로 공급한다. 사람 scratchpad가 필요 없다.
  - 학습 문제는 "어떤 하위 프로그램을 어떤 경로로 묶는가"를 끝 대 끝 데이터에서 찾는 것이 된다.
  - 북극성의 "새 문제를 스스로 구조화"에 가장 직접 닿는다.
- **기각 후보:**
  - 사람이 설계한 scratchpad: Turing Programs(Hou 외 2024) 등 선행 연구가 있고, "스스로"에 반한다.
  - 학생 잠재 상태: 1단계에서 약점이었고, 단단한 구조를 잃는다.
- **순서 제안:** L2a(3-2 포함) → L2b다.
  - L2a는 3-E0이 "한 칸 넘게 이동" 또는 "조건 탐색" 원인으로 분류할 외부 과제를 직접 대상으로 삼는다. 그래서 과제를 우리가 고르지 않는다.
- **사전 등록 전에 할 선행 연구 대조 (설계 채팅):**
  - Neural Programmer-Interpreters(Reed·de Freitas 2016): 실행 흔적 감독이 필요하다.
  - DreamCoder식 라이브러리 학습.
  - Turing Programs(Hou 외 2024): 곱셈 n×1·n×3, 2배 길이 일반화.
  - 다중 피연산자 덧셈·곱셈 2–3배 길이 일반화(arXiv 2410.15787).
  - 도구 사용 SSM(arXiv 2510.14826).
  - Learning Transformer Programs.
- **L2a의 첫 관문 초안:** 3-0과 같은 형식이다. 손 프로그램 표현력, L1 밖 확인, 오라클 학생, 기준선, 교사 "어디"를 본다. 3-E0 결과를 본 뒤 과제를 정해 사전 등록한다.

### 9.3 L2가 "도약"이려면 (2026-11-26, 설계 채팅) — 사전에 기준을 적는다
서준의 바람은 L2가 양자 도약이 되는 것이다. 무엇을 도약이라 부를지 결과를 보기 전에 적어 둔다. 결과에 맞춰 기준을 옮기지 않기 위해서다.
- **L2a(라우팅 전용 내부 step) 혼자는 도약이 아니다.** 표현 범위를 한 칸 넓히는 일이다(Odds First 같은 과제). 필요한 디딤돌로 본다.
- **도약의 기준 (둘 다 충족, 둘 중 하나면 "부분"):**
  1. **이전에는 불가능:**
     - 두 피연산자가 **모두** 학습보다 길어지는 N×M 곱셈에서 이긴다.
     - 이기는 기준은 7.7절이다. 상대는 기준선 6개와, 선행 연구 형식의 사람 설계 scratchpad 기준선 하나다.
     - 사람이 설계한 중간 형식은 쓰지 않는다.
     - 선행 연구의 최고 수준은 고정 길이 승수(n×1·n×3)에서 2배 일반화다(Turing Programs) [원문 대조 전].
  2. **스스로 구조화 + 더 작은 계산:**
     - 새 과제를 **새 교사 학습 없이**, 이미 검증된 프로그램 라이브러리의 합성만으로 푼다.
     - 새 과제에 드는 계산은 합성 탐색과 합성 결과 검증뿐이다. 학습 FLOPs가 0에 가깝다는 것이 북극성의 "더 작은 계산"을 가장 강하게 보여 준다.
- **정직한 위험 [추정]:**
  - 합성 탐색 공간이 프로그램 수와 깊이에 따라 폭발할 수 있다. 지금도 L1 합성 CPU가 기준선 학습과 같은 자릿수다.
  - 끝 대 끝 데이터만으로 "어떤 하위 프로그램을 어떤 순서로"를 식별할 수 있는지는 아직 근거가 없다.
  - 과제는 여전히 작은 기호 과제다. 실제 데이터로 가는 다리는 이 뒤의 일이다.
- **첫 확인을 싸게 한다:** L2b 설계의 첫 관문은 3-0처럼 학습 없는 표현력 검사로 한다. 손으로 짠 합성(N×1 + 자리 이동 + 덧셈)이 길이와 무관하게 1.000인지 본다. 그다음에 자동 합성으로 간다.

## 10. 3-E0 판정, 빠진 기준선 계열, 3-P 사전 등록 (2026-11-26, 설계 채팅)

### 10.1 3-E0 판정
- **질문에 대한 답:** L1은 15개 중 3개(even_pairs, reverse_string, duplicate_string)이고, L0는 15개 중 2개(even_pairs, reverse_string)다.
  - 원자료는 `stage3/a` `08bbcb4`(코드 `06dcc2f`)다. 원본 코드 재생 15 × 1,000개는 불일치 0이다.
- **표현 밖 12개의 원인:**
  - 값 상태 5: parity, modular_arithmetic, cycle_navigation, modular_arithmetic_brackets, solve_equation.
  - 한 step 두 칸 이상 2: odds_first, stack_manipulation.
  - 출력당 읽기 증가 2: binary_multiplication, compute_sqrt.
  - 값 조건 제어 1: bucket_sort.
  - 그 밖 2:
    - binary_addition: 끝 시점이 남은 윗자리에 달린다. G-0a 뺄셈과 같은 유형이다.
    - missing_duplicate: 상태 6개 프로그램은 A1 1.000이지만 Q ≤ 4를 넘는다.
- **해석: 지금 주장의 정확한 범위는 외부 15과제 중 3개(20%)다.**
  - Q 상한은 탐색 비용 때문에 우리가 정한 값이다. Q ≤ 8이면 missing_duplicate까지 4개다. 둘 다 보고한다.
  - 사전 예상(4–5개)보다 적다. binary_addition의 형식(앞자리 0 없는 합)을 놓쳤다.
- **Claude Code 질문 답:**
  1. **형식 (판정 불변, 고정 L1을 지키는 쪽으로 정한다):**
     - Q1: 연산·명령 기호는 모두 하나의 op 종류(G-0처럼)다. 종류 7개를 넘지 않는다. 9.1의 "기호마다 op"는 고친다.
     - Q2: cycle_navigation의 행동 0/1/2는 데이터(digit)다.
     - Q3: 입력 안의 괄호, x, `=`는 op다. 규칙은 "데이터 기호도 아니고 입력·출력 구분자도 아닌 입력 기호 → op"다.
     - Q4: 끝 토큰을 `<eos>`로 바꾸고 채움은 지운다(자기회귀 형식).
  2. **논증:** 두 빈틈(content 이동이 답을 위치로 담을 가능성, 4상태 이하 불가능성)은 증명이 아니라 논증으로 기록한다. 분류 표에 "[논증]"을 붙인다.
  3. **binary_addition "그 밖: 끝 시점":** 받아들인다.
  4. **3-E1 후보 3개:** 지금 돌리지 않는다. 10.2와 10.4 뒤에 한 번에 돌린다.

### 10.2 빠진 기준선 계열: 구조화된 메모리를 가진 RNN (규칙 4, 가장 중요)
- Delétang 외의 결론: RNN과 트랜스포머는 정규가 아닌 과제에서 일반화하지 못한다. LSTM은 정규·카운터 과제를 푼다. **스택이나 메모리 테이프를 붙인 망만이 문맥 자유·문맥 의존 과제에서 일반화한다.**
- 우리의 결정적 이김 8개는 대부분 이 계열(복사·뒤집기·복제형)이다. 그런데 우리 기준선 6개에는 Stack-RNN·Tape-RNN이 **없다.** 같은 저장소에 공식 구현이 있는 알려진 기법이다.
- 그러니 "이전에는 불가능"은 지금까지 **트랜스포머·RNN·LSTM 계열에 대해서만** 확인된 것이다. 이 검사의 결과에 따라 주장의 틀이 달라진다.
  - **메모리 RNN도 실패하면:** "알려진 모든 계열이 실패하는 과제"다.
  - **메모리 RNN이 이기면:** 주장은 "특수 구조를 과제 계층마다 설계하지 않고, 표준 트랜스포머에서 구조를 찾아 표준 망으로 실행한다"로 좁아진다.
- 정규 과제(값 상태 5개 중 다수)는 LSTM이 풀 수 있는 계열이다. 그러니 우리가 그쪽으로 확장해도 "이전에는 불가능"이 되지 않는다. 북극성 거름망에서 우선순위가 낮다.

### 10.3 3-P 발표 전 확인 (사전 등록, 활성 질문)
**질문:** 남은 알려진 기법과 확인 조건을 넣어도, 결정적 이김 8개(덧셈·복사·N×1·누적합·뒤집기·dup·interleave·pairswap)의 기준선 최고 2구간이 ≤0.60으로 남는가?
- **순서는 정보 가치 순이다.**
- **P0. 메모리 RNN 기준선 (먼저):**
  - Stack-RNN·Tape-RNN이다. 공식 구현(`neural_networks_chomsky_hierarchy` 커밋 `2b8eb4b`)과 그 기본 초매개변수를 그대로 쓴다. JAX 설치가 안 되면 멈추고 보고한다. 우리가 다시 구현하면 기준선이 약해질 위험이 있기 때문이다.
  - **형식:** 그들 본래 형식(비자기회귀, 출력 길이만큼 채움 토큰을 줌)이다. 출력 길이를 알려 주는 쪽이므로 기준선에 유리하다. 정확도는 출력 전체 정확 일치다(우리와 같은 기준).
  - **과제:** 결정적 이김 8개 + 외부 L1 3개(even_pairs, reverse_string, duplicate_string)다. 우리 길이 규약(학습 1–10, 분포 밖 11–40)을 쓴다.
  - **학습:** 최대 100,000 step(우리 기준선의 5배)이다. 분포 안 ≥0.99 두 번 연속이면 멈춘다. 1,000 step마다 기록한다.
  - **학습률 조율:** 분포 안 < 0.95이거나 2구간 ≥ 0.10이면 학습률 ×0.5·×2를 더 돌리고 2구간 최고를 쓴다(3-B 규칙).
- **P1. 기준선 다중 시드:** 과제마다 1구간이 가장 높은 기준선 두 개(P0 포함)를 시드 1·2로 더 돌린다. 시드 중 2구간 최고를 쓴다.
- **P2. 조기 종료 없는 학습:** rel_rand와 P0에서 가장 강한 메모리 RNN을 덧셈·복사·dup에서 조기 종료 없이 끝까지 돌린다(rel_rand 20,000 step, 메모리 RNN 100,000 step). 분포 밖 궤적을 기록한다.
- **P3. 같은 정보 기준선:** rope 트랜스포머에 토큰 종류 κ와 구획 번호 g(i) 임베딩을 더한다. 우리 학생이 받는 구조 표지에서 헤드 읽기만 뺀 것이다. 8과제, 시드 0이다.
- **판정 (주장 갱신 규칙):**
  - 어느 항목에서든 2구간이 0.60을 넘으면 그 과제의 "결정적" 표시를 거두고, 어떤 기법이 넘었는지 적는다.
  - **질문에 대한 답:** 모두 유지되면 예, 아니면 아니오(과제·기법 목록)다.
- **비용 [추정]:**
  - P0: 22회(+조율). 메모리 RNN은 작아서 step당 싸지만 step 수가 많다. 회당 0.5–3시간이다.
  - P1–P3: 약 30회다.
  - 합계 하루–이틀(4개 병렬)이다.
  - **P0만 끝나도 중간 보고한다.** 결과에 따라 갈래 B(L2a)의 대상과 주장 틀이 바뀌기 때문이다.

### 10.4 갈래 B(L2a)에 주는 것
- 외부 표현 밖 목록이 L2a의 후보를 정해 준다.
  - **한 step 두 칸:** odds_first, stack_manipulation.
  - **끝 시점:** binary_addition, 그리고 repeat/duplicate의 끝 표지 맹점.
- 단, P0에서 메모리 RNN이 이 과제들을 푸는지 먼저 본다. 풀면 "이전에는 불가능"이 아니므로 L2a의 판정 과제 선택이 달라진다.
- L2a 사전 등록은 P0 결과 뒤에 한다.

### 10.5 P0 형식 결정 (2026-11-26, 설계 채팅)
원칙은 두 가지다. 하나, 공식 구현에 충실하다. 둘, 애매하면 **기준선에 유리한 쪽**을 택한다(규칙 4, "후보에게 가장 불리한 쪽").
1. **모양:** (a)로 한다.
   - 예마다 실제 답 길이만큼 빈칸을 주고, 같은 모양끼리 묶어 계산한 기울기를 한 step으로 합친다. 배치 128은 유지한다.
   - 덧셈·N×1에만 해당한다. 답 길이를 알려 주므로 기준선에 유리하다.
2. **학습 데이터:** step마다 새 표본을 뽑는다(공식 방식, 기준선에 유리). 우리 N = 100,000 고정 집합과 다르다는 것을 기록한다.
3. **길이 표본:** 공식 커리큘럼이다(배치마다 n 하나, 1–10 균등).
4. **입력:** 8과제는 판정 형식의 프롬프트(BOS·`=` 포함) 뒤에 빈칸을 붙인다. 외부 셋은 공식 맨 입력이다.
5. **출력:** 길이를 주므로 `<eos>`는 출력에서 빼고, 답 토큰 전체의 정확 일치로 채점한다. 우리 모델은 eos까지 맞혀야 하므로 기준선이 유리하다. 이 차이를 기록한다.
6. **메모리 크기: 기본값(스택 30, 테이프 40)을 쓰지 않는다.**
   - 기본값은 분포 밖 순서 길이(최대 163토큰)보다 작다. 그러면 기억 용량 부족으로 실패할 수 있고, 그건 기준선을 일부러 약하게 만드는 것이다(규칙 4).
   - 스택·테이프 크기는 평가에서 가장 긴 전체 순서 길이 이상으로 둔다. 256으로 고정한다.
   - 나머지 초매개변수는 공식 Tape-RNN 예제 값(hidden 256, 칸 8)을 두 모델에 같이 쓴다.
   - 테이프 크기 256과 30·40의 차이를 기록한다.
7. **평가:** 제안대로 한다.
   - 우리 평가 집합(분포 안 1,000, 구간마다 500, 1단계 시드)으로 정확 일치를 잰다.
   - 1,000 step마다 평가하고, 판정은 분포 안 최고 체크포인트다. 프로세스마다 스레드 하나다.
- **stack_manipulation 원인 어긋남:** 두 장애(값 조건 제어, 한 step 두 칸 이상)를 모두 적는다. L1 밖이라는 결론은 같다.

## 11. L2b: 컴파일된 프로그램의 자동 재조합 (2026-11-27, 설계 채팅, 서준 결정: "검증과 별개로 적극 진행")

### 11.1 1원칙: 왜 재조합인가
- 출력 하나에 읽기가 길이에 따라 늘어나는 과제(곱셈, 여러 수 덧셈)는 중간 결과가 필요하다. 중간 결과에는 학습 정답이 없다(8.4).
- **해법:** 중간 결과를 데이터가 아니라 **이미 길이 일반화가 검증된 하위 프로그램**이 만든다. 감독을 하위 프로그램이 스스로 공급하므로 사람 scratchpad가 필요 없다.
- **재조합의 핵심 성질:** 결합자(fold, map 등)는 길이와 무관하게 정의된다. 그래서 하위 프로그램이 정확하면 합성물도 **구조상** 길이 일반화한다. 새 과제에서 학습할 것이 없다. 북극성의 "더 작은 계산"을 가장 강하게 보일 수 있다(9.3 기준 2).
- **원자 단위의 위험 하나 (가장 중요):** 오류가 곱으로 쌓인다.
  - 호출마다 정확도가 p이고 호출이 c번이면, 합성물의 성공은 대략 p^c다 [추정, 독립 가정].
  - 예: N×M(M = 20)은 mul1과 add를 각 20번 호출한다. p = 0.99면 0.99^40 ≈ 0.67이다.
  - 그러니 **모듈 신뢰도가 L2b의 병목**이다. 탐색보다 먼저 이것을 잰다.

### 11.2 재조합 언어 (과제 무관, 사전 고정)
- **값:** 토큰 열과 열의 목록이다.
- **모듈:** 라이브러리의 컴파일된 프로그램이다. 프롬프트 → 답이고, 탐욕 자기회귀로 실행한다.
  - 지금 라이브러리: add(덧셈), mul1(N×1), copy, reverse, prefix_sum(C-1), dup, interleave, pairswap(3-1).
  - 호출 형식은 각 모듈의 판정 형식 그대로다. 예: `add(x, y)` = 프롬프트 `x + y =`.
- **결합자 (목록·열 연산, 사람이 정한 원시 연산이며 과제 무관):**
  - `split(열, 구분자)` → 목록
  - `tokens(열)` → 한 토큰짜리 목록
  - `rev_list(목록)`
  - `fold(f, 초기값, 목록)`, `map(f, 목록)`
  - `concat(열, 열)`, `const(토큰들)`
  - `rstrip(열, 토큰)`: 끝의 같은 토큰을 지우되 하나는 남긴다. 낮은 자리 먼저 쓰는 수의 앞자리 0 정리다.
- **결합자는 열 전체에 작용한다(비자기회귀).** 그래서 끝 시점이 아직 읽지 않은 값에 달린 문제(G-0a 뺄셈, binary_addition)도 결합자 수준에서 다룰 수 있다. L1의 한계 하나를 이 층에서 넘는다.
- **모듈 호출의 다수결:** 같은 기능의 모듈이 여럿이면(C-1은 표 3개 × 선택 학생), 호출마다 출력 열 단위로 다수결한다. 정답 없이 쓸 수 있는 오류 감소 장치다. 단일 모듈 결과도 함께 기록한다.

### 11.3 L2b-0 관문: 손 합성으로 표현력과 오류 누적을 잰다 (학습 없음, 사전 등록)
**질문:** 라이브러리 모듈을 손으로 재조합한 프로그램이, 두 피연산자 축이 모두 학습 범위를 넘는 두 과제에서 분포 밖 ≥0.90을 내는가? 기존 기준선은 같은 과제에서 실패하는가?
- **과제 (둘 다 길이 일반화의 대표적 난제다; 선행 연구 최고는 2–3배):**
  - **multi_add (여러 수 덧셈):** 입력은 `a1 + a2 + … + ak =`(각 수는 낮은 자리 먼저), 출력은 합(낮은 자리 먼저)이다.
    - 분포 안: k 2–5, 자릿수 1–10.
    - 분포 밖 1: k 6–10, 자릿수 11–20.
    - 분포 밖 2: k 11–20, 자릿수 21–30.
  - **mulNM (N×M 곱셈):** 입력은 `A * B =`(둘 다 낮은 자리 먼저), 출력은 곱(낮은 자리 먼저)이다.
    - 분포 안: n, m 1–10.
    - 분포 밖 1: n, m 11–15.
    - 분포 밖 2: n, m 16–20. 곱이 40자리 이하라 add 모듈의 검증 범위(≤40자리) 안이다.
- **손 합성 프로그램:**
  - `multi_add(x) = fold(λacc, a. add(acc, a), const("0"), split(x, "+"))`
  - `mulNM(A, B) = fold(λacc, b. add(rstrip(concat(const("0"), acc), "0"), mul1(A, b)), const("0"), rev_list(tokens(B)))`
    - 높은 자리부터 도는 호너 방식이다. ×10은 낮은 자리 먼저 표기에서 앞에 0을 붙이는 것이다.
    - `rstrip`은 0×10 = "00" 같은 비정규 수를 막는다.
  - **구현 검사 (1.000이 아니면 멈춘다):** 모듈 자리에 정확한 파이썬 의미(정수 덧셈·곱셈)를 넣으면 두 프로그램이 모든 구간에서 1.000이어야 한다. 이것은 합성 논리만 검사하고, 판정에는 쓰지 않는다.
- **측정:**
  - **M. 모듈 신뢰도:** add·mul1 모듈(표마다, 다수결)의 정확 일치를 합성물이 실제로 부르는 입력 분포에서 잰다. 길이별로 무작위 2,000개다.
    - add는 두 피연산자 길이가 다를 수 있다. 큰 쪽 길이 1–42.
    - mul1은 길이 1–20, 승수 0–9.
  - **R. 합성물 정확도:** 다수결과 단일 모듈(표 셋 각각)로 분포 안 1,000개, 분포 밖 구간마다 500개를 잰다.
  - **예측 대비:** 측정 M으로 예측한 p^c와 실제 R을 나란히 기록한다(오류 독립성 확인).
- **기준선 (C):** 표준 기준선 6개(abacus, rope, looped_rr, gru, rel_rand, nope)를 두 과제에 1단계 규약(분포 안 범위로 학습, 시드 0)으로 학습한다. 3-P P0가 끝나면 메모리 RNN 둘도 더한다.
  - **기준선은 R이 통과 기준을 넘은 과제에만 돌린다**(조기 종료, 3-0과 같은 원칙).
- **판정:**
  - 과제가 통과하려면 R(다수결) 분포 밖 1·2구간이 ≥0.90이고, 기준선 최고 2구간이 ≤0.60이어야 한다.
  - **예(두 과제 모두):** 다음은 L2b-1, 즉 **자동 재조합 탐색**이다(11.4).
  - **R이 미달이고 M으로 설명되는 경우** (예측 p^c와 실제 R의 차이 ≤0.05): 병목은 모듈 신뢰도다. 다음은 모듈 단단화다(더 긴 학습, 선택, 다수결 확대). 설계 채팅이 정한다.
  - **R이 미달이고 M으로 설명되지 않는 경우:** 합성 인터페이스 문제(형식·분포 차이)다. 진단한다.
- **모듈 확보:** C-1 학생 체크포인트(로컬)를 쓴다. 없으면 C-1의 설정·시드 그대로 다시 학습하고 기록한다(결정적 재현). 3-1 모듈도 같다.
- **비용 [추정]:**
  - M·R은 추론만이다. mulNM 1회는 모듈 호출 최대 40번이다. CPU 몇 시간이다.
  - 기준선은 2과제 × 6–8회다.
- **결정을 바꾸는가:** 예. 자동 탐색으로 갈지, 모듈 단단화가 먼저인지가 갈린다.

### 11.4 L2b-1 초안: 자동 재조합 탐색 (L2b-0 뒤 사전 등록)
- **탐색:**
  - 11.2 언어의 프로그램을 크기순으로 타입 주도 열거한다.
  - 같은 입력에서 출력이 같은 후보는 하나로 합친다(관측 동치).
  - 모듈 출력은 메모이즈한다.
- **선택 (6.9와 같은 원리):** 길이 1–5 학습 예에서 정확히 맞는 후보 중, 길이 6–10 예에서 정확도가 가장 높은 것을 고른다. 동점이면 작은 프로그램이다.
- **새 과제에 쓰는 계산은 탐색과 검증뿐이다.** 새 교사·학생 학습이 없다. 9.3 도약 기준 2를 직접 잰다.
- **대상:**
  - multi_add·mulNM(손 합성 없이 다시).
  - 외부 binary_multiplication, compute_sqrt(필요한 이진 모듈은 L1 파이프라인으로 라이브러리에 추가).
  - 그리고 결합자 층에서 끝 시점 문제가 풀리는지 볼 binary_addition.
- **선행 연구 대조 (사전 등록 전):**
  - **HOUDINI**(Valkov 외 2018): 신경 함수 라이브러리 + map·fold 타입 함수 언어 + 프로그램 합성. 가장 가까운 연구다.
  - DreamCoder(라이브러리 학습), Neural Module Networks, Neural Programmer-Interpreters, Turing Programs, 여러 수 덧셈·곱셈 2–3배 일반화(arXiv 2410.15787).
  - **차별점 후보 [추정, 확인 전]:** 모듈이 표준 트랜스포머 교사에서 컴파일되어 길이 일반화가 검증된 알고리즘이다. 재조합물이 기존 기법이 모두 실패하는 길이 일반화 과제를 학습 없이 푼다.

### 11.5 L2b 원자 단위 재검토 (2026-11-27, 설계 채팅, 실행 전) — 11.3·11.4절을 고친다
**1. 결과를 미리 알 수 있는 관문은 돌리지 않는다.**
- 11.3의 mulNM(m ≤ 20)은 mul1 20번 + add 20번 호출이다.
- 지금 mul1 모듈의 11–20자리 정확도는 0.948–0.996이다(C-1). 예측 성공률은 0.97^20 × 0.99^20 ≈ 0.45로, 0.90에 못 미칠 것이 거의 확실하다 [추정].
- 이 실패는 정보가 없다. 병목이 모듈 신뢰도라는 것은 지금 이미 안다.
- **그래서 순서를 바꾼다: 라이브러리 입장 기준을 먼저 세우고, 그것을 넘긴 모듈로만 합성물을 잰다.**

**2. 라이브러리 입장 기준 (과제 무관, 사전 고정)**
- 라이브러리는 한 번 만들고 모든 미래 합성에 다시 쓴다. 그래서 모듈 신뢰도에 쓰는 계산은 **상각**된다. 과제마다 드는 비용이 아니다.
- **기준:** 호출 c번짜리 합성물이 ≥0.90이려면 호출당 정확도가 p ≥ 0.9^(1/c)여야 한다.
  - 목표 c_max = 100(아래 3의 50×50 곱셈)이므로 **p ≥ 0.999**다.
  - 측정 범위는 모듈이 합성에서 받는 길이 전체다.
- **측정 M (확장):**
  - add는 큰 쪽 길이 1–100, mul1은 길이 1–50이다. 길이 구간마다 2,000개다.
  - 측정 대상은 표마다의 단일 모듈과 다수결(3개)이다.
  - 모듈 사이 오류 상관(같은 입력에서 함께 틀리는 비율)도 기록한다. 다수결이 효과가 있는지가 여기에 달렸다.
- **미달이면 H (모듈 단단화, 사전 등록):**
  - C-1과 같은 표와 같은 학습 길이(1–10)로 학생을 다시 학습한다. 조기 종료 없이 20,000 step이고, 표마다 재시작 3개다.
  - 그다음 M을 다시 잰다. 가장 좋은 조합(단일 또는 다수결 3·5·9)을 고른다. **고르는 기준은 분포 안 자기 일관성**(다수결 합의율)이다. 정답이 있는 분포 밖 값으로 고르지 않는다.
  - 그래도 미달이면 멈추고 보고한다.

**3. "도약"이 되려면 길이 배율이 선행 연구를 크게 넘어야 한다.**
- 선행 연구의 여러 수 덧셈·곱셈은 2–3배 길이 일반화다. 우리 11.3의 mulNM(10 → 20)은 2배라서 같은 수준이다. 도약이 아니다.
- **구간을 바꾼다 (학습·선택 범위는 그대로 1–10):**
  - **mulNM:** n, m은 분포 안 1–10, 분포 밖 11–20 / 21–30 / 31–50이다(최대 5배, 곱은 ≤100자리).
  - **multi_add:** 분포 안은 k 2–5·자릿수 1–10, 분포 밖은 (k 6–10, 11–20) / (k 11–20, 21–30) / (k 21–40, 31–50)이다.
- **계산 [추정]:**
  - mulNM 50×50 한 예는 모듈 호출 약 100번이고, 호출마다 최대 100토큰을 생성한다.
  - 그래서 R 측정은 긴 구간을 200개로 줄인다.
  - Claude Code가 M을 끝낸 뒤 R 비용을 추정해 보고한다. 4개 작업자로 하루를 넘으면 표본을 줄이는 대신 먼저 보고한다.

**4. 자동 탐색(L2b-1)의 비용 문제와 원리적 해법: 모듈 계약**
- 열거 탐색은 후보 수십만–수백만 개다. 후보마다 신경 모듈을 부르면 계산이 터진다.
- **해법:** 라이브러리 항목은 (컴파일된 프로그램, **계약**)의 쌍이다.
  - 계약은 그 모듈이 학습한 과제의 생성 규칙이다. 즉 "이 모듈이 무엇을 계산하도록 만들어졌는가"이고, 라이브러리가 원래 아는 정보다.
  - 탐색은 계약으로 빠르게 평가한다. 고른 프로그램은 **신경 모듈로 실행해서** 검증·판정한다.
  - 사람이 문서를 보고 함수를 조합하는 것과 같다. 새 과제의 답이나 구조는 주지 않는다.
- **정직하게 적을 것:** 계약은 각 모듈이 어떤 과제에서 왔는지를 아는 것이다. 이것은 라이브러리가 스스로 만든 기록이다(우리가 그 과제를 학습시켰다).

**5. 라이브러리 성장 (L2b-2, 도약의 두 번째 축)**
- 판정을 통과한 합성물(예: mulNM)은 입장 기준을 넘으면 **새 모듈로 라이브러리에 들어간다.**
- 그러면 다음 과제(거듭제곱 = mulNM의 fold 등)는 더 큰 부품으로 짧게 표현된다.
- "새 문제를 스스로 구조화하고, 그 구조를 더 작은 계산으로 실행"이 한 번이 아니라 **누적**된다. 북극성의 가장 강한 형태다. L2b-1 뒤에 사전 등록한다.

**6. 수정된 L2b-0 순서**
1. 구현 검사(정확한 정수 연산으로 1.000).
2. M(add 1–100, mul1 1–50, 단일·다수결·상관).
3. 입장 기준 판정. 미달이면 H 다음 M 재측정.
4. 입장한 모듈로 R(3의 구간).
5. R이 통과 기준을 넘은 과제에만 기준선(P0 뒤).

### 11.6 L2b-0 M 판정과 H 재정의 (2026-11-27, 설계 채팅) — 11.5-2의 H를 대체한다
**M 판정:** 입장하지 못했다(`stage3/a` `b56e433`, 정정 `595c2ed`).
- add: 단일 최고 0.910, 다수결 0.8645(91–100).
- mul1: 단일 최고 0.964, 다수결 0.9425(41–50).
- 오류는 대부분 길이가 맞고 한 자리만 틀린다. add는 높은 자리에 몰린다. 모듈끼리 독립보다 1–10배 함께 틀린다.

**원자 분해: 오류가 길이에 따라 늘어나는 이유**
- add 단일 최고의 정확도는 구간별로 0.9985(11–20), 0.977(51–60), 0.910(91–100)이다. 자리당 오류로 바꾸면 약 1e-4에서 1e-3으로 **길이와 함께 커진다** [추정].
- 학생이 정말 국소 함수라면 100번째 자리와 5번째 자리의 계산은 같아야 하고, 오류가 길이에 따라 늘 이유가 없다.
- **늘어난다는 것은 어텐션 학생이 국소 입력 밖(긴 문맥)을 보고 있고, 길이가 길어질수록 어텐션이 묽어져 흔들린다는 뜻이다** [추정].
- **C-1의 진단 팔 M(어텐션 없는 MLP)은 구조상 국소적이다.** 그래서 같은 국소 키면 위치와 무관하게 같은 출력을 낸다.
  - C-1 원자료에서 MLP 학생 31–40 구간 값은 다음과 같다.
    - add: 1.000 · 1.000 · 0.998.
    - mul1: 0.964 · 1.000 · 0.994. 표 1은 11–20에서 0.976으로 떨어진 뒤 0.956–0.964로 평평하다. 길이를 따라 늘지 않고, 특정 키를 틀리는 모양이다.
  - 같은 표의 어텐션 학생은 다음과 같다.
    - add: 0.980 · 1.000 · 0.978.
    - mul1: 0.898 · 0.938 · 0.956.
- **결론: 라이브러리 모듈의 실행기는 MLP 학생이어야 한다.** 국소성은 길이 불변성을 구조로 보장한다. 남는 오류는 특정 국소 키를 틀린 것이고, 이것은 학습으로 줄일 수 있다. 어텐션 학생의 표류는 학습을 늘려도 남을 수 있다.
- **정직한 기록:** MLP 팔의 40자리까지 값은 C-1에서 이미 본 것이다. 그래서 입장 판정은 **아무도 잰 적 없는 41–100자리와 새 시드**로 한다.

**H (재정의, 사전 고정)**
1. **학생:**
   - C-1 MLP 학생(진단 팔 M 구성, MLP 블록 4개)을 쓴다. 입력은 C-1과 같다(읽기 + 구획 비트 + 한 칸 이동).
   - 표는 C-1의 add·mul1 표 1–3이다.
2. **학습:**
   - 1단계 규약에 학습 길이 1–10, N = 100,000이다.
   - **조기 종료 없이 20,000 step**이고, 마지막 체크포인트를 쓴다(분포 안이 포화돼 고를 근거가 없다).
   - 표 i마다 시드 230 + i, 330 + i, 430 + i(재시작 3)이다. 기능마다 모듈 9개다.
3. **조합 선택 — 모듈 계약으로 검증한다 (11.5-4):**
   - 모듈 계약(add = 정수 덧셈, mul1 = 정수 × 한 자리)으로 **선택 집합**을 만든다. add는 길이 1–100, mul1은 1–50이고, 구간마다 500개, 생성 시드는 "L2b-0:Hsel:<모듈>:<구간>"이다.
   - 후보는 단일 9개 각각, 그리고 선택 집합 정확도 상위 3·5·9개의 다수결이다.
   - 다수결은 출력 열 단위 최다 득표이고, 동점이면 선택 집합 정확도가 가장 높은 모듈의 출력을 쓴다.
   - 후보 중 **선택 집합의 구간별 최저값**이 가장 높은 것을 고른다. 0.0005 이내는 동점이고, 동점이면 모듈 수가 적은 쪽이다.
   - 11.5-2의 "분포 안 합의율로 선택"은 버린다. 분포 안은 모두 포화돼 정보가 없다.
   - **정당성:** 계약 검증은 라이브러리가 자기 부품을 시험하는 일이다. 합성 과제(multi_add·mulNM)의 데이터는 쓰지 않는다.
4. **입장 판정:**
   - 고른 조합을 M 집합(11.5와 같은 생성 시드, 선택 집합과 겹치지 않음)에서 잰다.

5. **기록만:** 오류가 난 예의 국소 키(읽은 토큰·비트·한 칸 이동)를 모은다. 같은 키가 반복되는지(특정 키 오류) 흩어지는지(표류) 기록한다.
6. **계산 [추정]:** 학생 18개(add 9, mul1 9) × 20,000 step이다. MLP는 작아서 회당 수십 분이다. 3-P P0와 작업자를 나눠 쓴다(P0 우선).
- 입장하면 R(11.5-3)로 간다. R 비용을 먼저 추정해 보고한다.

### 11.7 입장을 "측정"에서 "증명"으로 (2026-11-27, 설계 채팅, H 실행 전) — 11.6-3·4를 대체한다
**원자 분해: MLP 학생은 무엇의 함수인가**
- 코드(`stage2/c1a.py` `HardReadLM`)를 확인했다.
  - 입력은 in_t = u_t + S(u_{t−1})이고, u_t = E(x_t) + Σ_h R_h(E(x[p_h(t)]) + F_h b_h(t))다.
  - **위치 부호화가 없다.** MLP 블록은 위치마다 따로 작용한다.
- 그러므로 MLP 학생의 step t 출력은 **국소 키**의 결정적 함수다.
  - 국소 키 κ_t = (x_t, 읽은 토큰들_t, 구획 비트들_t, x_{t−1}, 읽은 토큰들_{t−1}, 구획 비트들_{t−1})다.
  - 위치 t도, 순서 길이도 들어가지 않는다.
- **따름정리 (귀납):** 다음 세 가지가 성립하면, 모듈은 **모든 길이에서 정확**하다. 측정이 아니라 논리로 나온다.
  1. 라우팅이 모든 길이에서 맞는 위치를 읽는다.
  2. 긴 순서에 나오는 국소 키가 모두 짧은 순서에서도 나온다(키 닫힘).
  3. 짧은 순서의 모든 키에서 출력이 맞다.
  - 오류가 생기는 유일한 길은 "처음 보는 키" 또는 "틀린 키"다. 둘 다 짧은 길이에서 **전수로** 확인할 수 있다.
- **어텐션 학생에는 이 논리가 성립하지 않는다.** 어텐션은 키 밖의 문맥을 본다. 11.6의 표류 관측과 맞는다.

**입장 판정 (11.6-3·4를 대체, 사전 고정)**
1. **라우팅 (모든 길이):**
   - 컴파일 표와 C-1a 손 표가 도달하는 칸에서 같은지 비교한다(같으면 경로가 모든 길이에서 같다).
   - 길이 1–100 무작위 2,000개에서 읽기 위치가 손 표 경로와 같은 비율이 1.000이어야 한다.
2. **키 닫힘 [논증, 경험적]:**
   - 전수 집합 K(L)을 만든다.
     - add: 두 피연산자 길이가 각각 1–3인 모든 순서(약 1.2e6개).
     - mul1: 길이 1–4 × 승수 0–9인 모든 순서(약 1.1e5개).
     - 키는 채점 step의 국소 키만 모은다.
   - add 길이 4–100, mul1 길이 5–50에서 무작위 100,000개를 뽑아, K(L)에 없는 키 수를 센다. **0이어야 한다.**
   - 0이 아니면 그 키들을 보고하고 멈춘다. L을 키우는 것은 계산이 크므로 설계 채팅이 정한다.
3. **키 정확성 (전수, 정답은 짧은 길이의 계약에서만 온다):**
   - K(L)을 만든 모든 순서의 모든 채점 step에서, 모듈 출력(teacher-forced)이 계약의 정답과 같아야 한다. 1.000이다.
   - **이 검증에 쓰는 정답은 길이 ≤ 4(학습 범위 안)뿐이다.** 분포 밖 정답은 모듈 선택에 전혀 쓰지 않는다. 11.6의 긴 길이 계약 선택 집합은 버린다.
4. **입장:** H로 학습한 MLP 모듈 9개 중 1–3을 통과하는 모듈이 하나라도 있으면 입장한다. 여럿이면 시드가 작은 것이다.
   - 다수결은 필요 없다.
   - **기록:** 각 모듈의 "틀린 키" 수와 그 키들.
5. **표적 보수 (한 번만, 사전 고정):**
   - 통과하는 모듈이 없으면, 틀린 키가 가장 적은 모듈을 이어서 학습한다. 5,000 step이다.
   - 학습 데이터 = 원래 학습 데이터 + **K(L) 순서 중 틀린 키를 포함한 것**(길이 ≤ 4, 학습 범위 안)이다.
   - 다시 1–3으로 검증한다. 그래도 실패하면 멈추고 보고한다.
6. **확인용 표본 측정:** 입장한 모듈로 11.5의 M 집합(add 1–100, mul1 1–50)을 잰다. 1–3이 맞다면 모든 구간 1.000이어야 한다. 아니면 논리의 빈틈이므로 멈추고 보고한다.

**이것이 바꾸는 것 (도약의 핵심)**
- 모듈이 입장하면, 합성물(multi_add·mulNM)은 결합자가 정확한 코드이므로(구현 검사 1.000) **어떤 길이에서도 정확**하다. 길이 일반화를 재는 것이 아니라 **보장**한다.
  - 단, 키 닫힘이 경험적 논증이므로 "[논증]"으로 적는다.
- 선행 연구의 "2–3배 일반화"는 측정된 배율이다. 우리는 **배율 상한이 없다**는 주장을 할 수 있다.
  - 이를 보이기 위해 R에 확인 구간 하나를 더한다: mulNM n, m 51–100(곱 ≤200자리, 100개).
  - add 모듈 검증 범위를 넘으므로, 그 구간은 1–3의 논리에만 기댄다. 그 사실을 보고에 적는다.
- **학습 비용:** MLP 학생 18개 × 20,000 step이 라이브러리 전체 비용이다. 새 과제(합성물)의 학습 비용은 0이다.

### 11.8 키 닫힘 실패의 원인과 H′: 최소 충분 국소 키 (2026-11-27, 설계 채팅) — 11.7에 더한다
**결과:** 키 닫힘이 모든 표(손 표 포함)에서 실패했다(`stage3/a` `f55408d`).
- add(표 2): K(L)의 서로 다른 키는 219,021개다. 긴 순서 채점 step의 56%(2,972,605 / 5,302,111)가 새 키이고, 서로 다른 새 키는 286,646개다.
- mul1: 새 키 step이 144,227개다.
- 짧은 집합 안에서 키 → 정답 충돌은 0이다. 국소 키는 출력을 정한다.

**원자 분해: 왜 닫히지 않는가**
- 11.7의 키는 MLP 입력 **전체**다. 그런데 출력은 그 일부에만 달려 있다. 출력과 무관한 성분이 길이에 따라 새 조합을 계속 만든다.
  - **여분 헤드:** add 컴파일 표에는 손 표에 없는 움직이는 헤드(헤드 2)가 있다. 그 읽기는 출력과 무관한 숫자다.
  - **끝난 피연산자를 읽는 헤드(비트 0):** 길이가 다른 두 수에서, 짧은 쪽 헤드는 답 구간을 읽으며 지나간다. 긴 순서에서만 생기는 조합이다. 이것을 가려도 새 키 step이 714,372개 남는다(`closure_diag_hand.json`).
  - **x_{t−1} 같은 직전 칸 성분:** 덧셈의 올림에는 x_t(직전 출력)와 직전 칸의 두 읽기만 있으면 된다. x_{t−1}은 무관하다.
- **결론:** 전체 키로는 닫힘이 원리적으로 성립하지 않는다. 11.7의 "증명" 경로는 **이 키 정의로는** 막혔다. 11.7의 보장 주장은 거둔다.
- **다만 원리는 살아 있다.** 출력이 의존하는 **최소 충분 키**로 바꾸면 키 공간이 작아져 닫힘이 성립할 수 있다 [추정].
  - 예: add의 올림 규칙은 (x_t, a_k, b_k, a_{k−1}, b_{k−1}, 비트)면 충분하다.

**H′ (최소 충분 국소 키 표, 사전 고정, H와 나란히)**
1. **성분 집합 C:**
   - x_t와 x_{t−1}.
   - 움직이는 헤드 h마다 (읽기_{h,t}, 비트_{h,t}, 읽기_{h,t−1}, 비트_{h,t−1}).
   - 헤드 3개면 14성분이다.
2. **최소 충분 키 S:**
   - 학습 데이터(N = 100,000, 길이 1–10)의 채점 step에서 key_S → 출력이 **결정적**(충돌 0)인 부분집합 S를 찾는다.
   - 크기가 작은 순서로 전수 탐색한다(2^14 = 16,384개).
   - 같은 크기면 서로 다른 키 수가 적은 것이 앞이고, 그다음 성분 번호 사전순이다.
3. **모듈 = (컴파일 라우팅, 표 T_S):**
   - T_S는 학습 데이터에서 만든 key_S → 출력 표다. **경사 학습이 없다.**
   - T_S에 없는 키가 나오면 표는 답하지 못한다. 그 경우는 "닫힘 실패"로 센다.
4. **검증 (11.7-1·2·3을 S로 바꿔 그대로):**
   1. 라우팅: 손 표 경로와 1.000. 여분 헤드는 S에 없으면 무관하다.
   2. 닫힘: 긴 무작위 100,000개(add 4–100, mul1 5–50)에서 key_S가 T_S에 없는 step이 0이어야 한다.
   3. 짧은 전수 집합 K(L)의 모든 채점 step에서 T_S 출력 = 계약 정답, 1.000이어야 한다.
   4. 확인: M 집합(add 1–100, mul1 1–50) 1.000.
   - 1–3이 성립하면, 모듈은 **긴 순서에 나타나는 모든 키에서 정확**하다. 닫힘은 무작위 표본에 기댄 경험적 논증이므로 "[논증]"으로 적는다.
   - 키 공간이 작으므로, S 성분들의 곱공간 크기 대비 T_S 크기도 기록한다.
5. **기록:**
   - 고른 S(어느 성분인지), |T_S|, 표본별 닫힘 비율.
   - 손 프로그램이 알려 주는 "필요한 성분"과 S가 일치하는지(사후 해석).
- **H(MLP 학습)는 계속 돌린다.** H′가 입장하면 라이브러리 모듈은 H′(표)다. H′가 실패하면 아래 대비책으로 간다.

**대비책: 측정 기반 입장 (H′가 실패할 때만)**
- H의 MLP 모듈 9개 중 하나를 고른다. 고르는 기준은 K(L) 전수 집합의 정확도(분포 안 정답만)이고, 동점이면 시드가 작은 것이다.
- M 집합에서 모든 구간 ≥0.999면 입장한다. 계약으로 만든 긴 길이 정답을 **입장 시험**에만 쓴다(선택에는 쓰지 않는다).
- 이 경우 합성물 주장은 "측정된 길이까지"이고, 보장은 하지 않는다.

**도약 관점에서 이것이 바꾸는 것**
- H′가 입장하면 학생 학습 자체가 사라진다. 라이브러리 모듈은 "교사에서 컴파일한 라우팅 + 데이터에서 찾은 최소 국소 규칙표"다.
- 실행은 표 조회이므로 신경 오류가 없고 계산이 아주 작다.
- 이것이 C 단계 해석("학습기는 유한한 국소 함수만 배운다")을 끝까지 밀고 간 형태다.
