# 3단계 판정 (설계 채팅 판정을 그대로 옮긴다, 날짜순 추가)

## 2026-11-25 · 3-0 판정 (설계 채팅, CLAUDE.md "3-0 판정" 블록)
- 질문에 대한 답: 예(4개 중 4개). A0 1.000이다. 네 과제 모두 A1 1.000·(d) 0, A2 L0 덮임 0.32–0.80, D 전 구간 1.000, 기준선 최고 2구간 0.000, B 비 2.22–3.99다.
- 네 과제를 3단계 판정 묶음으로 동결한다. 허용 예산과 기준선 최고는 3-0 C 값이다.
- 해석: 상태는 라우팅에 필요하다. 학생 출력에 q가 필요한 과제는 pairswap 하나다(q = 0 대조). 주장은 라우팅의 자동 구조화에 둔다.
- Claude Code 질문 답:
  1. 판정 묶음은 4과제 그대로다.
  2. repeat는 한 칸 앞 헤드 판을 정본으로 하되, 손 프로그램은 참조일 뿐이다.
  3. 정의를 확정한다: A2 주값은 eos 제외, (d)는 두 셈의 합, κ(r)는 읽은 위치의 종류, MQAR t0는 첫 질의, q는 원핫이다.
- 자세한 내용은 설계서 6.1–6.2절.

## 2026-11-26 · 3-1 판정 (설계 채팅, CLAUDE.md "3-1 판정" 블록)
- 질문에 대한 답: 예(4개 중 3개).
  - dup·interleave·pairswap은 처음 보는 교사 41·42·43 모두에서 결정적 이김이다(분포 밖 0.984–1.000, 기준선 최고 2구간 0.000, FLOPs 예산의 0.13–0.29).
  - repeat는 교사 43에서 졌다(0.888 · 0.648 · 0.396).
- pairswap의 출력 선택 상태(짝·홀)를 세 교사 모두에서 자동으로 구성했다(Q, Q′ = 2, 2). 공급 위치 일치율은 0.991–1.000이다.
- repeat 패배는 끝 표지 맹점이다(고른 프로그램의 eos 설명률 0). 다음 설계 원리는 구조 설명률을 합성 목적에 넣는 것이다.
- 효율: FLOPs로는 싸지만, CPU 시간으로는 합성 때문에 기준선과 같은 자릿수다(2,837–7,506초 대 2,233–5,353초).
- "L1 라우팅의 자동 구조화"를 세 과제 범위에서 확립으로 기록한다. 자세한 내용은 설계서 7절.
