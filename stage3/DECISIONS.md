# 3단계 판정 (설계 채팅 판정을 그대로 옮긴다, 날짜순 추가)

## 2026-11-25 · 3-0 판정 (설계 채팅, CLAUDE.md "3-0 판정" 블록)
- 질문에 대한 답: 예(4개 중 4개). A0 1.000이다. 네 과제 모두 A1 1.000·(d) 0, A2 L0 덮임 0.32–0.80, D 전 구간 1.000, 기준선 최고 2구간 0.000, B 비 2.22–3.99다.
- 네 과제를 3단계 판정 묶음으로 동결한다. 허용 예산과 기준선 최고는 3-0 C 값이다.
- 해석: 상태는 라우팅에 필요하다. 학생 출력에 q가 필요한 과제는 pairswap 하나다(q = 0 대조). 주장은 라우팅의 자동 구조화에 둔다.
- Claude Code 질문 답:
  1. 판정 묶음은 4과제 그대로다.
  2. repeat는 한 칸 앞 헤드 판을 정본으로 하되, 손 프로그램은 참조일 뿐이다.
  3. 정의를 확정한다: A2 주값은 eos 제외, (d)는 두 셈의 합, κ(r)는 읽은 위치의 종류, MQAR t0는 첫 질의, q는 원핫이다.
- 자세한 내용은 설계서 6.1–6.2절.

## 2026-11-26 · 3-1 판정 (설계 채팅, CLAUDE.md "3-1 판정" 블록)
- 질문에 대한 답: 예(4개 중 3개).
  - dup·interleave·pairswap은 처음 보는 교사 41·42·43 모두에서 결정적 이김이다(분포 밖 0.984–1.000, 기준선 최고 2구간 0.000, FLOPs 예산의 0.13–0.29).
  - repeat는 교사 43에서 졌다(0.888 · 0.648 · 0.396).
- pairswap의 출력 선택 상태(짝·홀)를 세 교사 모두에서 자동으로 구성했다(Q, Q′ = 2, 2). 공급 위치 일치율은 0.991–1.000이다.
- repeat 패배는 끝 표지 맹점이다(고른 프로그램의 eos 설명률 0). 다음 설계 원리는 구조 설명률을 합성 목적에 넣는 것이다.
- 효율: FLOPs로는 싸지만, CPU 시간으로는 합성 때문에 기준선과 같은 자릿수다(2,837–7,506초 대 2,233–5,353초).
- "L1 라우팅의 자동 구조화"를 세 과제 범위에서 확립으로 기록한다. 자세한 내용은 설계서 7절.

## 2026-11-26 · repeat 진단 판정 (설계 채팅, 설계서 8.1절)
- 분포 밖 실패는 대부분 eos 시점 오류다. 학생 넷 × 세 구간 = 12칸 중 11칸에서 0.78–0.99다.
- 거의 모두 **일찍 끝내는** 쪽이다. 정답 길이보다 평균 1.9–6.0 step 앞이고, 첫 오류는 답의 뒤쪽 절반에 있다.
- 숫자 값 오류는 주로 첫 사본에 있다. 교사 42 학생에서만 비율이 높다(1구간 0.50).
- **해석:** 7.3의 끝 표지 맹점이 확인됐다. 학생은 끝을 구조로 받지 못해, 학습 길이에 묶인 셈으로 추정한다.
- **Claude Code 질문 (학생 수 7):** 설계 채팅의 오기다. 정의대로 넷이 맞다. 선택되지 않은 두 학생은 평가하지 않는다. 결과가 어느 쪽이어도 바뀌는 결정이 없기 때문이다(규칙 2).

## 2026-11-26 · 3-B 판정 (설계 채팅, CLAUDE.md "3-B 판정" 블록)
- 질문에 대한 답: 예(9개 중 9개). "결정적" 표시를 거둔 과제는 없다.
  - rel_rand(무작위 relative)·nope의 2구간 최고는 0.050(N×1)이다. 1구간은 0.008–0.520이다. 학습률 조율 조건에 걸린 경우는 없다.
- π 길이 누출은 그대로 기록한다. 기준선에게만 유리한 누출이므로 결론이 더 단단하다.
- 한계: 기준선은 시드 0이고, 조기 종료 규약으로 멈췄다. 이 둘은 발표 전 확인 목록에 둔다.
- 자세한 내용은 설계서 8.6절.

## 2026-11-26 · 3-E0 판정 (설계 채팅, CLAUDE.md "3-E0 판정" 블록)
- 질문에 대한 답: L1은 외부 15과제 중 3개(even_pairs, reverse_string, duplicate_string), L0는 2개다. Q ≤ 8이면 missing_duplicate까지 4개다.
- 원인: 값 상태 5, 한 step 두 칸 이상 2, 출력당 읽기 증가 2, 값 조건 제어 1, 그 밖 2(binary_addition 끝 시점, missing_duplicate 상태 수). 논증은 "[논증]"으로 표시한다.
- 형식은 10.1-1대로 정한다: op 종류 하나, cycle 행동은 digit, 입력 안 괄호·x·=는 op, 끝 토큰은 `<eos>`, 채움은 지운다.
- 3-E1은 3-P와 L2a 뒤에 한 번에 돌린다. 자세한 내용은 설계서 10절.

## 2026-11-28 · TF-0 판정 (설계 채팅, 설계서 13.1절)
- **질문에 대한 답: 예(5개 중 5개).**
  - 교사, 의존도, 손 표 없이, 길이 외삽 점수만으로 고른 라우팅의 움직이는 헤드가 다섯 과제 모두 손 표와 글자 그대로 같다.
  - H′ 검증은 다섯 과제 모두 닫힘 0, K(L) 1.000, 확인 1.000이다.
  - 학습 FLOPs는 0이다. TF-0 전체 벽시계는 교사 파이프라인의 0.29–1.29배다. 교사 쪽은 판정 시점까지만 센 과소 추정이고, 뒤집기만 1을 넘을 수 있다.
- **"교사 없는 구조 발견(L0 범위)"을 확립으로 기록한다.** 교사 학습과 의존도 추출은 이 범위에서 필요 없는 부품이다.
- **Claude Code가 정한 것은 모두 받아들인다.** 시드 0 데이터, 생성 좌표 길이, 경로 정의와 대표 규칙, 최다 출력 동점 규칙, K(L) 범위, 확인 표본이 해당한다.
- **위치 매김은 12.5-3 그대로다.** 이 결과만으로는 고전 프로그램 유도의 영역이다. 독창성은 발견·전이·성장(13.3)에서 입증해야 한다.

## 2026-11-28 · L2b-0 판정과 종료 (설계 채팅, 설계서 13.2절)
- **질문에 대한 답: 예.**
  - H′로 입장한 add·mul1 모듈의 손 재조합은 multi_add(k ≤ 40, 31–50자리)와 mulNM(51–100자리 포함)의 모든 구간에서 1.000이다.
  - 지금까지 돈 기준선(rope, abacus)은 분포 밖 0.000이다.
- **발견: H′ 입장은 학습 데이터 덮임에 달려 있다.** 같은 S에서 add 표 2·3은 드문 올림 사슬 키 3개가 없어 닫힘에 실패했다. 판정은 바꾸지 않는다. EXT-0은 이 문제를 "없는 키 = 오답"으로 엄격하게 다루고, 없는 키 비율을 기록한다.
- **L2b-0은 여기서 닫는다.** 남은 R 기준선은 발표 전 묶음(13.4-3)으로 옮긴다. 이미 돌고 있는 실행은 끝까지 두고, 새 실행은 시작하지 않는다.
