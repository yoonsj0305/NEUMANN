### 손 프로그램 (3절 정의 안, Claude Code 작성)
- 헤드는 3개다. μ의 기본값은 stay이고, δ는 첫 일치 규칙이다. κ는 1단계 토큰 종류 7개다.
- 모든 과제에서 BOS를 쓰지 않는다. 이유: 모든 헤드가 위치 0에서 시작해 그 칸을 직접 읽는다. 왼쪽으로 가는 헤드도, 왼쪽 끝을 알아야 하는 헤드도 없다.

| 과제 | Q | μ (적힌 것 외에는 stay) | δ | 출력 공급 헤드 |
|---|---|---|---|---|
| dup | 2 | 헤드 0: (q1, 답) → right | (*, =) → 0; (0, 답) → 1; (1, 답) → 0 | q0 → 0, q1 → 0 |
| interleave | 2 | 헤드 0: (q0, 답) → right<br>헤드 1: (q0, +)·(q1, +) → next_sep, (q1, 답) → right | (*, =) → 1; (0, 답) → 1; (1, 답) → 0 | q0 → 0, q1 → 1 |
| repeat | 3 | 헤드 0: (q0, 답) → right<br>헤드 1: (q0, =)·(q0, 답) → right (한 칸 앞 보기)<br>헤드 2: (q2, 답) → right | (q0, 헤드 1이 '=' 읽음) → 1; (1, *) → 2; (2, *) → 2 | q0 → 0, q1 → 2, q2 → 2 |
| pairswap | 3 | 헤드 0: (q0, =)·(q0, 답)·(q1, 답)·(q2, 답) → right<br>헤드 1: (q0, 답)·(q2, 답) → right | (0, =) → 1; (1, 답) → 0; (0, 답) → 2; (2, 답) → 0 | q0 → 0, q1 → 1, q2 → 1 |
| MQAR (기록) | 2 | 헤드 0: (q0, \|) → start, (q0, 답) → content, (q1, 답) → start | (*, \|) → 0; (0, 답) → 1; (1, 답) → 0 | q0 → 0 |

("답" = answer_phase 종류. 나머지 규칙은 q를 그대로 둔다.)

  1. κ(r)은 읽은 위치의 종류로 했다(위치 기준). 이 프로그램들에서는 차이가 없다.
  2. MQAR의 t0는 첫 '|' 다음, 즉 첫 질의 step으로 했다.
  3. A2의 eos step 포함 여부: 두 변형을 모두 계산했고, 판정이 같다.
  4. q는 u_t에 원핫 임베딩으로 더했다.
  5. (d) "충돌"은 구간 안 충돌과, 학습 표와 어긋난 덮인 step을 둘 다 셌다.
- repeat 손 프로그램은 설계서 스케치와 다르다.
  - 한 칸 앞을 보는 헤드 1을 더했다.
  - 이유: 스케치("A가 '='를 읽으면 q 0 → 1")대로 하면 전환이 한 step 늦다. 헤드 1이 답 step n−1에 '='를 읽어, 전환이 step n에서 일어나게 했다. 스케치판 자체는 돌려 보지 않았다.

  - 이 과제들에서는 q 정보가 학생 입력(읽기·구획 비트·한 칸 이동)에 이미 들어 있다 [추정].
